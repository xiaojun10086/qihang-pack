## 二、评审四维度自评

### 2.1 创新性

| 创新点 | 说明 |
|---|---|
| **澄清门量化** | 用 `U = 1 − Σ(wᵢcᵢ)/Σwᵢ` 把「该不该追问」变成可计算判定，> 0.30 才追问，避免打扰 |
| **三级可插拔结构** | skill 库 → 域 → skill；1 级只管四件事（需求明确/域审查/输出规范/记忆），不承载业务 |
| **库内优先** | 库内有就不装库外，从机制上规避低星/无证/需 Key 的第三方风险 |
| **横切信息库** | DUT 公开站 160 条 + 私密站 19 站，**强制查表、禁止编造 URL** |
| **越界用例含反例** | 22 条用例中 **3 条是"不该拦截"的反例**，防过度拦截 |

### 2.2 需求度

四大痛点全覆盖：需求说不清 → 澄清门；工具散 → 三级包；学习生活割裂 → 19 域打通；校情碎片化 → 信息库。
**演示 3 条**分别命中：备考（最高频）、校园事务（最高频）、论文（最高价值）。

### 2.3 可行性
