## 二、P0 缺陷（会导致行为错误或安全事故）

### P0-1 · L3 禁读门禁可被「变体写法」绕过 🔴

**现象（实测，修复前）**

| 命令 | 文档定义 | 实际退出码 | 结果 |
|---|---|---|---|
| `dlut-read.sh 缴费` | L3 禁读 | **3** | ✅ 拦住 |
| `dlut-read.sh 缴费金额` | L3 禁读 | **1** | ❌ **未走拒绝分支** |
| `dlut-read.sh 银行卡号` | L3 禁读 | **1** | ❌ 绕过 |
| `dlut-read.sh 身份证号` | L3 禁读 | **1** | ❌ 绕过 |
| `dlut-read.sh 邮件内容` | L3 禁读 | **1** | ❌ 绕过 |

**根因**：`scripts/dlut-read.sh` 用 `case "$TARGET" in 缴费|银行卡|…)` **精确等值**匹配，而文档里 L3 的**第一条**就是「缴费金额」。等于清单名字与实际拦截名不是一个东西。

**为什么自检抓不到**：`audit.sh` 只测了 `缴费 / 银行卡 / 身份证 / 邮件正文 / 心理记录 / 成绩明细` —— 恰好全是「不带后缀」的原词。**自检样本与缺陷样本不重叠**，形成盲区。

**修复**：改为**关键词包含**匹配（`case "$TARGET" in *"$_k"*`），关键词表 `缴费 金额 银行卡 身份证 家庭 邮件 心理 成绩明细 成绩单 简历`。

**复测（v2.7）**：13 个 L3 变体 **13/13 全部 rc=3**；合法目标 `课表/网费/借阅/门户/日程` 仍 rc=0 且 dry-run 不启动浏览器；`邮箱提示` 仍 rc=2；裸 `成绩` 仍 rc=1（要求区分等级/明细）。

> **教训**：**门禁类逻辑不能用「等值匹配」实现语义清单。** 拦截清单越重要，越要用最宽的匹配口径。

### P0-2 · 自检脚本静默失败：零输出、退出码 1 🔴

**现象（实测）**：某次修复后 `bash scripts/selfcheck.sh` **完全无输出**、退出码 1。加 `bash -x` 也拿不到输出。

**根因（两层）**

1. 旧版在 `EXIT` trap 里 `rm -f` 临时文件；而本机沙箱把 `rm` 做成**「失败即封」**的拦截器 —— trap 一旦触发，**整个脚本被静默终止**，连已缓冲的 stdout 一起丢失。
2. 更底层：脚本里存在**大量逐文件循环**（[3] frontmatter 逐文件 3 次 grep ≈120 子进程；[4] 交叉引用逐文件 grep ≈280 子进程）。在受限环境中**子进程数超限会被中断**，表现为「跑到某一行就没有下文」。

**修复**

- **彻底零临时文件**：`[4]` 改为单遍 `grep -rhoE` + shell 内建 `test` 判定；删掉 `TMP` 与 trap。
- **单遍化**：`[2]/[3]/[4]/[7]` 的逐文件循环改为**单次 awk / 单次 grep -r**，子进程从 **~500 降到 ~20**。

**复测**：`selfcheck.sh` 完整跑通 → **OK 31 / WARN 0 / FAIL 0，结论：可交付**。

> **教训**：**验证脚本本身必须能在最恶劣的环境里跑完。** 一个会静默失败的检查脚本，比没有检查脚本更危险（它给人「已检查」的错觉）。

### P0-3 · 澄清门「关键槽齐全 = 放行」存在逻辑洞 🔴

**现象**：`library/clarity.md` v2.6 规定「`O`/`T`/`D` 三关键槽齐全即放行，`U` 只作补充」。但**「齐全」只判有没有填，不判填得清不清楚**。

**反例（构造并实测）**：输入「帮我写点东西」→ `O`=0.5（对象歧义）、`T`=0.5（可导向 S3/S5 两域）、`D`=0（缺）。旧规则下三槽「都非空」→ **放行**；而此时 `U = 0.754`，远超 0.30 阈值。**规则自相矛盾，且方向是「越模糊越放行」。**

**修复**：补硬条件 —— **关键槽判「已填」须 `cᵢ ≥ 0.8`；出现 `0.5`（歧义）视同「缺」，必须追问。** 并在 `clarity.md` 增「例 C · 漏洞反例」章节，把上面的反例写进去当回归用例。

**复测**：回归脚本 7 个算例全部符合新判定（含「例丁-全歧义」由「放行」纠正为「追问」）。

## 八、方法论沉淀（下一轮沿用）

1. **门禁逻辑禁用等值匹配。** 清单一改名字，等值匹配就漏。
2. **自检样本必须包含「变体」。** 只测原词的自检 = 假自检。修复后已把 13 个变体写进 `regress.sh`。
3. **验证脚本要能在最恶劣环境跑完。** 零临时文件、单遍扫描，别在 trap 里 `rm`。
4. **一个常量散落 N 个文件时，改一处等于没改**（v2.5.0 的教训），本轮升级为：**凡跨文件常量，由生成器回写 + 自检断言**（如 registry 候选数）。
5. **记录 ≠ 修复。** 前次会话记录了 9 项，一项都没修。跨会话待办必须落到可执行脚本里，否则就是笔记。
