## 一、我理解的需求（复述）

### 1. 结构改造：把现在的「平铺 7 域」改成 **三级结构**

```
【1 级】skill 库  ←→  【2 级】域  ←→  【3 级】skill
```

- **第 1 级 skill 库**：**既是 skill（可被安装调用），也是库（承载索引与规则）**。
  它的 skill 本体**只做四件事**，不承载任何具体业务：
  1. **需求明确**（6 槽位拆解 + 澄清门，U > 5% 追问）
  2. **域的审查**（判断需求落在哪个域、域是否覆盖、是否越界）
  3. **输出规范**（统一要点模板，≤6 条）
- **第 2 级 域**：能力方向。**要覆盖学习 / 生活 / 科研的全部方向**（本文件 §四做方向自查）。
- **第 3 级 skill**：落在具体域里的可执行能力。

### 2. 工作流（这是本次改造的核心）

```
用户需求
  ↓
① 需求明确（1 级库）      → 6 槽位 + 澄清门，U ≤ 5% 才继续
  ↓
② 锁定域（1 级库 → 2 级）  → 域审查：命中哪个域 / 跨域 / 无域可命中
  ↓
③ 锁定 skill（2 级 → 3 级）→ 在该域内检索
  ↓
④ 优先用【库内 skill】     → 命中即直接调用，无需安装
  ↓
⑤ 库内没有该场景 skill     → 才走【库外安装】（读 external 表 → 探测 → 安装 → 调用）
```

**关键判据**：`库内优先` 是硬规则 —— 库内有就不装库外，避免引入低星、无许可证、需 API Key 的第三方风险。

### 3. DUT 融入

域要**有机融入**大连理工的公开站与**私密站（需登录）**，不是单独挂一个「G 域」了事。

## 二、三级结构落地形态（草案）

```
qihang-pack/
├── SKILL.md                      入口薄壳（安装后 Agent 看到的就是它）
├── config.yaml
├── library/                      ★【1 级】skill 库（既是 skill 也是库）
│   ├── SKILL.md                  库本体 = 安装单元
│   ├── clarity.md                规则：需求明确（6 槽位 + 澄清门公式）
│   ├── domain-review.md          规则：域审查（锁定 / 越界 / 无域兜底）
│   └── output-spec.md            规则：输出规范（模板 + 简略原则）
├── domains/                      ★【2 级】域
│   ├── _registry.md              域总表 + 方向自查矩阵
│   └── <域ID>/
│       ├── _domain.md            域定义：触发词 / 边界 / 输入输出 / DUT 绑定点
│       └── skills/               ★【3 级】skill
│           ├── local/            库内 skill（自带，无需安装）
│           │   └── <name>/SKILL.md
│           └── external.md       库外候选（要装时读这张表）
├── references/
│   ├── dlut-official-sites.md    DUT 官网信息库
│   ├── dlut-login-sites.md       DUT 私密站（需登录）清单 ★新增
│   └── validation-report.md
├── commands/
└── scripts/
```

**三级职责边界（消歧义）**

| 级别 | 允许做 | 禁止做 |
|---|---|---|
| 1 级 skill 库 | 澄清需求、锁定域、审查域、规范输出、路由 | 承载具体学科知识、写死业务逻辑 |
| 2 级 域 | 定义边界与触发词、列出域内 skill、声明 DUT 绑定点 | 直接回答问题 |
| 3 级 skill | 执行具体任务 | 自行决定跳过澄清门 |

### 5.3 ⚠️ 技术限制（必须澄清，不能想当然）

**「你已在 Edge 登录」≠「我能直接复用」**。我的浏览器自动化工具运行在**独立浏览器实例**里，**读不到你 Edge 的 Cookie / 登录态**。所以私密站实际可行的方案只有三种：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A 受控浏览器登录** | 我用自动化浏览器打开站点 → **你在我的窗口里登录一次** → 我读取页面 | 我能直接读到结构化数据（成绩、课表） | 你的账号会在我的浏览器会话里；需你当场配合 |
| **B 手动投喂** | 你自己复制/截图/导出（如成绩单 CSV）→ 贴给我 | 零风险，登录态不外流 | 每次要手动，不能自动化 |
| **C 仅登记不抓取** | 只登记 URL + 操作路径 + 校验话术，数据一律你自己看 | 最安全 | 拿不到实时数据 |

**我的建议**：**A（高频只读项：课表/成绩/借阅/一卡通余额）+ C（低频项）**，且**只读、不外传、不写入任何文件**。涉身份证/银行卡类一律走 C。

## 七、一句话总结你的需求

> 把「启航」从**平铺 7 域**改成 **skill 库 → 域 → skill 的三级结构**：
> **1 级库只负责「把需求问清楚、判断属于哪个域、按规范输出」**；
> **2 级域要全覆盖学习 / 生活 / 科研三大方向**；
> **3 级 skill 执行具体任务**；
> 选型时**库内 skill 优先，库内没有才去安装库外 skill**；
> 并把大连理工的**公开站与需登录的私密站**都**有机嵌入对应域**，而不是当成一个孤立的信息域。
