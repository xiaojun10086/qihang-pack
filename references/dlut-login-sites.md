# 大连理工大学 私密站清单（需登录）

> **配套 `dlut-official-sites.md`（公开站）使用。**
> **接入方式：方案 A —— 受控浏览器登录**（每次打开前须获用户同意）
> **访问边界：① 只读 ② 工具不采集或输出页面内容 ③ 使用一次性 Profile 并在退出时清理**
> 登录动作由**用户本人**在受控浏览器窗口内完成，编排器不接触、不存储凭证。

## 0. 接入流程（方案 A）

```
1) 编排器用受控浏览器打开目标站点登录页
2) 提示用户在该窗口内自行登录
3) 用户自行查看当前页面；编排器不读取、复制或输出网页内容
4) 用户可选择只在聊天中提供回答必需的最少信息
5) 只关闭本次随机会话，并删除一次性 Profile；失败须明确报错
```

**禁止事项**
- ❌ 不代填账号密码，不代点「记住我」
- ❌ 不导出 Cookie / Session / Token
- ❌ 不把页面内容写入任何文件
- ❌ 不访问与本域无关的页面
- ❌ 涉身份证 / 银行卡 / 家庭信息类页面**一律不打开**（走方案 C）

## 0.1 ★ 会话与 Profile 隔离（强制项）

**实测发现（2026-10-01）**：`agent-browser` 默认复用用户**真实 Chrome 的 profile**
（实测命中 `%LOCALAPPDATA%\Google\Chrome\User Data` → Profile 2）。

**后果**：自动化浏览器不只是拿到 DUT 登录态，而是**继承了该 profile 下所有站点的 Cookie**（邮箱、社交、支付…），远超本包所需的最小权限。

**强制做法**：为每次访问分配随机会话和一次性 Profile；不关闭其他 agent-browser 会话。

```bash
agent-browser --session "$SESSION_ID" open <url> --headed --profile "$HOME/.qihang/browser-profile.XXXXXX"
```

**每次会话结束必须**：只关闭 `"$SESSION_ID"` 会话，并清理本次 Profile。不得使用 `close --all`。

且「智慧学工」与「学工系统」是两个**不同**系统而此前只登记了一个。本轮共补 **26 条** → 见 §1.1。

**口径说明（四条，避免后续误登记）**：

1. **不登记内网直连地址**：WebVPN 资源清单给出的是真实内网地址（`10.8.x.x`、`202.118.x.x`
   及校内端口）。它们**只在 WebVPN 会话内可达**，登记直连 URL 会误导用户 → 一律只登记 WebVPN 入口。
2. **门户「全部服务」的 177 个格子里，33 个是 `empt-box` 空占位格，不是服务**：
   `class="service-type-list-item empt-box"`，`textContent` 为空，且**没有** `url` / `data-type` /
   `appid` 属性（`innerHTML` 里只有空 `span`）→ 是**布局占位格**。
   ⇒ **真实服务 144 项，全部带落地 URL；「无独立 URL 的服务」为 0 条。**
   此前「33 项无独立 URL」的写法是把占位格当成了服务，**已更正**。
   另：门户「事务」列表视图（`#menu=service`）有 9 项 `data-url` 为空（迎新系统 / 网络自助 /
   组织工作一体化平台 / 智慧学工 / 正版软件 / 站群系统 / 就业系统，去重 7 个）—— 那是
   **app 类条目靠 `appid` 启动**，这 7 个在「全部服务」视图里都有 URL，**同样不属于缺 URL**。
3. **`aigw.dlut.edu.cn` 仅 HTTP**：HTTPS **校内视角亦不可达**（超时）；门户「模型广场」指向的正是它。
   `webvpn.dlut.edu.cn/log` 是**大模型网关的 WebVPN 代理路径**，在 WebVPN 会话内直开会无限重定向
   （`ERR_TOO_MANY_REDIRECTS`）—— 必须从 WebVPN 门户点资源卡进入，不能手拼 URL。
4. **探测视点必须声明**：本轮所有直连探测的**本机在 DUT 校园网内**（见 §0.4），
   故「不可达」= **校内视角亦不可达**（结论更硬），而「可达」**不等于公网可达**。
   此前文档里「从公网连不上」的措辞**不成立**，已改为「校内亦不可达 / 校内视角不可达」。

> 除上述四条登记口径外，还有**协议与路径类的坑**（仅 HTTP 主机、必须带尾斜杠的路径、裸根 404），
> 已在 **§0.4** 与 `dlut-url-verification.md` §11.3 / §11.4 集中说明 —— 改链接前先看那两处。

## 0.4 全量复核记录（2026-10-04 · 本机多通道重跑）

**范围**：包内 **174 条唯一外链**（§11.2 口径；本机审计脚本未做 http→https 归一，
故实际逐条探测的是 **176 个字符串**）。口径与复现命令见 `dlut-url-verification.md` §11.7 ①。
每条重跑「系统解析 → AliDNS → DNSPub → 权威 NS → 80/443 端口 → 双协议实抓」。

**结果**：**173 个字符串可达**；其余 3 条**逐条定位后均为「非站点问题」**：

| 条目 | 现象 | 根因 | 处置 |
|---|---|---|---|
| `smart.lib.dlut.edu.cn/caslogin`（**无尾斜杠**） | 超时 | 无斜杠时服务端 **301 到 `/caslogin/`**（并降级为 http），客户端跟随该降级重定向时超时 | **必须带尾斜杠**：`/caslogin/` → 302 → 统一身份认证（0.0 s）。§1 第 33 行已用带斜杠写法 |
| `www.dlut.edu.cn/（URL` | 探测报错 | **审计脚本自身缺陷**：URL 正则字符类含全角右括号 `）` 但**未含全角左括号 `（`**，于是「URL 紧贴中文」的负向注入用例被整段当成 URL 去抓，请求行含非 ASCII 字符而报错 | 非站点问题；该字面量是 `negative_test.py` 的**负向用例**，不是真实链接。审计脚本已加 `PROSE` 判定：路径/查询含中日韩或全角字符的字面量直接跳过、不探测 |
| `xyz.dlut.edu.cn` | 无解析记录 | 它是负向示例里的**假 URL** | 符合预期，见 `dlut-url-verification.md` §11.5 |

**两处口径问题已在 `dlut-url-verification.md` 更正**：
1. §11.4「仅 HTTP」清单原写「8 条」却只列 6 个主机 → 实测为 **15 个主机**（本轮新增的
   `aigw` / `dutsa` / `dutxg` / `ecardpayment` / `is` / `speedtest` / `szdx` 也是仅 HTTP）。
   **改成 https 会打不开。**
2. §11.5 的八条老域名已用**权威 NS 直查**复核（8/8 无解析记录 + 正/负对照）→ 结论改述为
   「**解析层无记录**」，**不再表述为「站点不存在」**。

**⚠️ 交用户人工复查的清单**：本机多通道**均未验证到可用站点**的条目已集中列在
`dlut-url-verification.md` **§11.5（8 条老域名）**与 **§11.4（15 个仅 HTTP 主机）**，
另加 `smart.lib…/caslogin`（须带尾斜杠）与 `jxgl` 裸根（须走 `/student/home`）。

## 2.1 WebVPN 会话纪律（2026-10-04 新增）

WebVPN 登录态 ≈「校外可达全校内网」，权限面**远大于**任何单个业务系统，故单列三条：

- 只在用户明确要求「校外访问某系统」时打开，**不与其他站点共用**同一次会话与 Profile。
- 用毕立即关闭该会话；不登记内网直连地址（见 §0.3 口径 ①）。
- WebVPN 有 **Referer 校验**：手拼 URL 或改 `location.href` 会报「不正确的 HTTP Referer」
  → 只能从 WebVPN 门户点资源卡进入。

## 3. 会话与隐私

- 会话结束只关闭本次浏览器会话；一次性 Profile 正常退出后删除。
- 工具不读取、不保存或输出页面内容；用户自行查看并决定是否分享最少必要字段。
- 用户可随时中止：说「停止」即立即关闭会话。
