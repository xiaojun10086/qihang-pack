## 五、附带修掉的一个工具死结（`sync_release.py` 的 `EXF`）

- **现象**：为防「fresh clone 后脚本变 CRLF」，给源仓库 `.gitattributes` 加了 `eol=lf` 锁定；
  随手一跑终检 → `verify.py` 报 **`内容不一致：1 ['.gitattributes']`**。
- **根因（两脚本口径不一致）**：
  - `verify.py` 的排除集**只有** 8 份过程文档 + 噪声目录 → `.gitattributes` / `.gitignore` **在终检口径内**；
  - `sync_release.py` 却写了 `EXF = {'.gitattributes', '.gitignore'}`，把这两个文件**排除在同步之外**。
  - 结果：文件被终检纳入、却不由同步管理 → **永久假漂移**（`--apply` 只复核、不修复该项）。
- **修法**：`sync_release.py` 改为 `EXF = set()`（过程文档仍由 `.gitignore` 派生排除），
  再 `--apply` → 同步 1 个文件、复核「内容不一致 0」。
- **结果**：`verify.py` = 源仓库 169 文件 ↔ 副本 169 文件，仅源有 0 / 仅副本有 0 / 内容不一致 0
  → **「✅ 两树完全一致（交付树 = 源仓库 − 过程文档）」**；记忆三文件两处逐字节一致。
- **顺带核实**：两处 `.gitignore` 本就相同（701 B，sha `cff657fa…`）；
  工作区 218 个已跟踪文件里 217 个本就是 LF（唯一 CRLF 是 `scripts/_build/build_phase15.py`，不交付的生成器）。
