# 实验设计

- **归属域**：`R2` 实验与数据（科研类）
- **来源**：自建
- **覆盖主体**：U 在读本科 · M 硕士
- **定位**：给实验设计的要素检查：研究问题、变量与操作化、对照与随机化、样本量与重复，强调先设计再收数据。

## 前置（不可跳过）

1. 1 级库已完成**需求明确**（6 槽位 + 澄清门；先过 §5 例外，关键槽 `O/T/D` 齐全且不歧义即放行）
2. 1 级库已完成**域审查**，确认命中本域

## 边界

- 覆盖：实验设计要素检查、变量操作化、对照 / 随机 / 盲法、样本量估算思路
- 不覆盖：数据分析与统计（→`stats-workflow`）；统计前提与造假核查（→`stats-guard`）；报告结构（→`S3`）

## 执行步骤

1. 把假设转成可检验的研究问题（自变量 / 因变量）
2. 操作化变量并定测量方式
3. 设计对照与随机化，必要时加盲法
4. 用功效分析思路估样本量（给口径不给数字承诺）
5. 列可能的混淆变量与控制方案

## 方法库 · 判定细则

**变量操作化检查**：每个变量都要有「操作性定义 + 测量工具 + 单位」。

| 设计要素 | 检查点 |
|---|---|
| 对照 | 有无空白 / 安慰剂对照 |
| 随机 | 分组是否随机 |
| 盲法 | 单盲 / 双盲是否可行 |
| 样本量 | 依据效应量 + 功效估算思路 |

**判定顺序**：先判是不是「为凑显著调整数据」请求，是则改走统计自查 → 再判设计要素（对照、随机、盲法、样本量）是否齐 → 最后才做变量操作化检查。

**高频误判**

- ❌ 把「算出显著结果」当设计需求 → ✅ 为凑显著性调数据改走统计自查路径
- ❌ 变量只写名称 → ✅ 每个变量要有操作性定义、测量工具与单位
- ❌ 无对照也算实验 → ✅ 对照是设计要素，缺对照只能做描述
- ❌ 混淆变量不控制就下因果结论 → ✅ 混淆未控制时结论只能相关不能因果
- ❌ 样本量凭感觉 → ✅ 样本量要有效应量与功效的估算思路

**判据**：混淆变量未控制 → 结论只能相关不能因果；须与 `stats-guard` 联用。

## 可执行示例

**示例 1（正常命中）**

**输入**

> 我想做个影响学习效率的实验，该怎么设计

**澄清判定**：关键槽 `O/T/D` 齐全且不歧义 → 依 `clarity.md` §5 例外 2 放行

**输出**

```
【结论】先定自变量 / 因变量与操作化，再补对照与随机。
【依据】实验设计：变量操作化 + 对照随机
【结果】① 假设转研究问题 ② 操作化变量 ③ 设对照随机 ④ 估样本量
       → 产出：实验设计要素检查表
【下一步】把你的自变量 / 因变量写出来发我，先过操作化
```

**示例 2（边界 / 失败例 —— 不该命中的情形）**

**输入**

> 帮我把这批数据算出显著结果

**澄清判定**：命中红线（为凑显著性调整数据）→ 依 `clarity.md` §5 例外 2 放行域锁定后改锁 `stats-guard`

**为什么这样判**：为凑显著性调整数据属禁答范围，改由统计自查做前提与规范核查（是换路径，不是拒答）。

**输出**

```
[已降级] 由「实验设计」改为「统计自查」
【结论】不补造 / 不篡改数据；改由 统计自查 做前提与规范核查。
【依据】合规边界：不得为达成 p<0.05 而调整样本
【结果】只交付前提与规范核查结论，数据本身保持原样 —— 凑显著类请求一律只降级不代劳。
【下一步】把原始数据与处理流程发我，做规范核查
```

## ⚠️ 红线（不得绕过）

- **不补造、不篡改、不选择性报告数据**；不得为达成 p<0.05 而调整样本
- 结论后**必须列出「不能下的结论」**（不推因果 / 不外推总体 / 不称「证明」）
