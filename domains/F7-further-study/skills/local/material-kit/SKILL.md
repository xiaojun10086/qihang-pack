# 升学材料结构

- **归属域**：`F7` 升学深造（生活类）
- **来源**：自建
- **覆盖主体**：G 毕业年级本科生
- **定位**：给个人陈述 / 研究计划 / 推荐信材料的「结构骨架与自查清单」，只搭框架与检查真实完整性，不代写正文。

## 前置（不可跳过）

1. 1 级库已完成**需求明确**（6 槽位 + 澄清门；先过 §5 例外，关键槽 `O/T/D` 齐全且不歧义即放行）
2. 1 级库已完成**域审查**，确认命中本域

## 边界

- 覆盖：升学文书结构骨架、材料齐备自查、真实性与一致性检查
- 不覆盖：代写正文 / 虚构经历（见红线）；选校策略（→`school-pick`）；时间线（→`grad-calendar`）

## 执行步骤

1. 明确材料类型与目标院校要求
2. 给该类材料的结构骨架（段落功能清单）
3. 检查经历 / 奖项与成绩单的一致性
4. 标出「需本人补真实内容」的空位
5. 给一次通读自查清单（无虚构、可被追问到底）

## 方法库 · 判定细则

**三类文书段落功能**：

| 类型 | 段落功能 |
|---|---|
| 个人陈述 | 动机 → 相关经历 → 匹配点 → 规划 |
| 研究计划 | 问题 → 现状 → 方法 → 预期贡献 |
| 推荐信 | 关系 → 具体事例 → 能力评价 → 结论 |

**判据**：任何一段若删掉后不影响理解 → 该段是凑字数，删。

**判定顺序**：先判是不是「代编内容 / 虚构经历」请求，是则只给结构与自查 → 再判文书类型（个人陈述 / 研究计划 / 推荐信）→ 最后才按段落功能搭骨架。

**高频误判**

- ❌ 把「你也帮我编一下」当润色 → ✅ 编内容一律拒绝，只做真实材料的措辞与结构优化
- ❌ 三类文书用同一套段落 → ✅ 个人陈述、研究计划、推荐信段落功能各不相同
- ❌ 只给骨架不查真实性 → ✅ 结构骨架要配真实性自查，否则搭完还是编
- ❌ 段落写得越长越好 → ✅ 删掉不影响理解的段落就是凑字数，直接删
- ❌ 推荐信替老师定评价 → ✅ 推荐信只给段落功能，评价内容由推荐人写

## 可执行示例

**示例 1（正常命中）**

**输入**

> 保研要写个人陈述，我不知道怎么组织

**澄清判定**：关键槽 `O/T/D` 齐全且不歧义 → 依 `clarity.md` §5 例外 2 放行

**输出**

```
【结论】按「动机—经历—匹配—规划」四段功能搭骨架。
【依据】升学材料结构：个人陈述段落功能
【结果】① 列真实经历 ② 按四段归类 ③ 标需补的真实内容 ④ 通读自查
       → 产出：个人陈述结构骨架
【下一步】把你的经历清单发我，我帮你归到四段里
```

**示例 2（边界 / 失败例 —— 不该命中的情形）**

**输入**

> 内容你也帮我编一下吧

**澄清判定**：命中红线（虚构经历）→ 依 `clarity.md` §5 例外 2 放行域锁定后按红线拒绝并给替代

**为什么这样判**：虚构经历属禁答范围，本 skill 一律只降级不代劳，只做真实材料的措辞与结构优化。

**输出**

```
【结论】不代编经历；只作真实材料的措辞与结构优化。
【依据】合规边界：不虚构经历、奖项、录取动机
【结果】只交付结构骨架与真实性自查，经历内容由你按真实情况填写 —— 代编类请求一律只降级不代劳。
【替代方案】结构骨架 + 真实性自查
【下一步】把你真实的经历写出来，我帮你组织语言
```

## ⚠️ 红线（不得绕过）

- **不代写文书**（个人陈述 / 推荐信 / 研究计划）—— 只给结构与自查；**真实材料的措辞优化属合规**（不得虚构内容）
- 不虚构经历、奖项、录取动机
