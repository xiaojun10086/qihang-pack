# 公寓与离校

- **归属域**：`F1` 校园事务（生活类）
- **来源**：自建
- **覆盖主体**：N 新生 · U 在读本科
- **定位**：覆盖宿舍入住、报修、调宿、毕业退宿与离校手续的流程梳理，只给入口与材料清单，不代提交申请。

## 前置（不可跳过）

1. 1 级库已完成**需求明确**（6 槽位 + 澄清门；先过 §5 例外，关键槽 `O/T/D` 齐全且不歧义即放行）
2. 1 级库已完成**域审查**，确认命中本域

## 边界

- 覆盖：宿舍入住 / 报修 / 调宿、毕业退宿与离校手续、公寓管理规定梳理
- 不覆盖：代提交申请（见红线）；水电网费金额（→`F4`，L3 禁读）；室友矛盾（→`F3` `peer-talk-script`）

## 执行步骤

1. 判定场景：入住 / 报修 / 调宿 / 退宿 / 离校
2. 列出该场景所需材料与办理地点
3. 给对应系统或窗口入口
4. 提示关键时间节点（退宿截止、离校清单）
5. 输出材料清单与办理顺序

## 方法库 · 判定细则

| 场景 | 典型材料 | 入口 |
|---|---|---|
| 入住 | 录取 / 住宿凭证 | 公寓服务中心 |
| 报修 | 房号 + 设施描述 | 后勤报修入口 |
| 调宿 | 申请表 + 理由 | 学生工作处 |
| 退宿 / 离校 | 离校清单 + 钥匙 | 离校系统 |

**判据**：只要出现「帮我提交 / 帮我退」，一律按红线引导本人操作。

**判定顺序**：先判是不是「代提交 / 代退办」请求，是则一律只给清单与顺序 → 再判场景（入住 / 报修 / 调宿 / 退宿离校）→ 最后才给材料与入口。

**高频误判**

- ❌ 把「帮我提交退宿」当咨询 → ✅ 代提交不代劳，只给材料清单与办理顺序
- ❌ 四类场景用同一套材料 → ✅ 入住、报修、调宿、退宿各自材料不同，先定场景
- ❌ 报修只报房号 → ✅ 房号之外要给设施描述，否则维修上门还得再跑一趟
- ❌ 调宿只交申请不写理由 → ✅ 调宿需申请表与理由，理由不写会被退回补
- ❌ 退宿忘带钥匙与离校清单 → ✅ 退宿按离校清单逐项核，钥匙要在最后一步交

## 可执行示例

**示例 1（正常命中）**

**输入**

> 宿舍空调坏了怎么报修

**澄清判定**：关键槽 `O/T/D` 齐全且不歧义 → 依 `clarity.md` §5 例外 2 放行

**输出**

```
【结论】走后勤报修入口，报房号 + 设施 + 拍图更快。
【依据】公寓与离校：报修场景材料表
【结果】① 拍故障图 ② 填房号与设施 ③ 提交报修单
       → 产出：报修单要点清单
【下一步】提交后把报修单号记下，超 48h 未响应再联系楼层管理员
```

**示例 2（边界 / 失败例 —— 不该命中的情形）**

**输入**

> 帮我把毕业退宿申请提交了

**澄清判定**：命中红线（代提交申请）→ 依 `clarity.md` §5 例外 2 放行域锁定后按红线拒绝并给替代

**为什么这样判**：退宿涉及钥匙与离校清单的实物交接，必须本人办理，本 skill 只给清单与顺序（只降级不代劳，不是空手退回）。

**输出**

```
【结论】不代提交退宿申请；可给材料清单与办理顺序。
【依据】合规边界：不代操作系统（提交）
【结果】只交付离校清单与办理顺序，退宿申请由你本人提交 —— 代操作系统一律只降级不代劳。
【替代方案】提供离校清单与办理顺序
【下一步】按清单逐项自行办理
```

## ⚠️ 红线（不得绕过）

- **不代操作系统**（选课 / 提交 / 报名）—— 只给入口与路径；**缴费 / 代缴属 `F4`**
- L3 禁读：缴费金额 / 银行卡 / 身份证 / 家庭信息
