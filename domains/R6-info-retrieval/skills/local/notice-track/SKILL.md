# 通知公告追踪

- **归属域**：`R6` 信息搜集与输出（科研类）
- **来源**：自建
- **覆盖主体**：全体学生
- **定位**：帮用户把需要持续跟进的报名 / 考试 / 评奖节点整理成带来源与截止时间的追踪清单，只查公开通知不臆造。

## 前置（不可跳过）

1. 1 级库已完成**需求明确**（6 槽位 + 澄清门；先过 §5 例外，关键槽 `O/T/D` 齐全且不歧义即放行）
2. 1 级库已完成**域审查**，确认命中本域

## 边界

- 覆盖：通知 / 公告追踪清单、关键节点与截止时间、来源核验与提醒设置
- 不覆盖：获取非公开信息（见红线）；教师个人信息（→`advisor-finder`）；办事流程（→`F1`）

## 执行步骤

1. 明确要追踪的事项（考试报名 / 评奖 / 夏令营 / 缴费）
2. 定位权威来源（教务处 / 研究生院 / 学院 / 新闻网等公开站）
3. 摘录关键节点与截止时间，标注来源与核验状态
4. 生成追踪清单与提醒建议
5. 未收录的固定回复「信息库未收录」，给核实入口

## 方法库 · 判定细则

**来源分级**：

| 级别 | 来源 | 可信度 |
|---|---|---|
| A | 职能部门官网通知 | 高 |
| B | 学院 / 辅导员通知 | 高 |
| C | 二手转述 / 群消息 | 需回源核实 |

**判据**：只有 C 级来源的节点 → 标 ⚠️ 待核实，并给 A 级核实入口。

## 可执行示例

**示例 1（正常命中）**

**输入**

> 我想跟进这学期的评奖和考试报名，怕错过时间

**澄清判定**：关键槽 `O/T/D` 齐全且不歧义 → 依 `clarity.md` §5 例外 2 放行

**输出**

```
【结论】建一张「事项—截止时间—来源」追踪清单，只用 A / B 级来源。
【依据】通知公告追踪：来源分级
【结果】① 列要跟的事项 ② 定位权威来源 ③ 摘节点与截止 ④ 设提醒
       → 产出：通知追踪清单
【下一步】把你要跟的事项发我，我帮你找权威来源入口
```

**示例 2（边界 / 失败例 —— 不该命中的情形）**

**输入**

> 帮我查一下某老师的私人电话

**澄清判定**：命中红线（获取非公开个人信息）→ 依 `clarity.md` §5 例外 2 放行域锁定后按红线拒绝并给替代

**输出**

```
【结论】不获取非公开个人信息；只查公开联系方式。
【依据】合规边界：只查公开信息；禁编造 URL / 电话
【替代方案】查公开的部门电话与教师主页
【下一步】需要找老师可查公开资料
```

## ⚠️ 红线（不得绕过）

- **只查公开信息**——任何尝试获取非公开个人信息（私人联系方式、家庭、行程）一律拒绝；个人隐私受法律保护
- **禁止编造 URL / 电话 / 姓名 / 职称**——`references/dlut-official-sites.md` 未收录的固定回复「信息库未收录，建议访问 https://www.dlut.edu.cn/ 核实」（硬规则 2）
- 涉及师生的负面舆情 / 争议信息不做「情报搜集」式的聚合输出——只提供官方来源原文入口
- 信息输出必须标注来源与核验状态；未经核验（⚠️）的信息不得当作事实输出
