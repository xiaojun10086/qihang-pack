# 面试演练

- **归属域**：`F8` 求职与竞赛（生活类）
- **来源**：自建
- **覆盖主体**：G 毕业年级本科生
- **定位**：用 STAR 结构把经历拆成可追问的故事，做模拟问答与追问压力测试，不教圆谎、不编造经历。

## 前置（不可跳过）

1. 1 级库已完成**需求明确**（6 槽位 + 澄清门；先过 §5 例外，关键槽 `O/T/D` 齐全且不歧义即放行）
2. 1 级库已完成**域审查**，确认命中本域

## 边界

- 覆盖：面试问答演练、STAR 故事拆解、追问压力测试、自我介绍结构
- 不覆盖：简历措辞（→`resume-tailor`）；编造经历（见红线）；升学面试（→`F7`）
- **裸「面试」= 歧义**：须先 1 问区分升学 / 求职（消歧表见 `domains/_registry.md`），不得默认按求职直接演练

## 执行步骤

1. 明确岗位与面试类型（行为 / 技术 / 群面）
2. 用 STAR 把 3–4 段经历拆成故事卡
3. 做自我介绍结构（30s / 1min 两版）
4. 模拟追问 2–3 轮，标出答不上来的点
5. 给改进方向，坚持只保留可被追问到底的内容

## 方法库 · 判定细则

**STAR 拆解**：Situation → Task → Action → Result，Result 必须有可量化结果。

| 追问压力测试 | 追问示例 |
|---|---|
| 细节 | 「具体数据是多少？」 |
| 反事实 | 「如果重来你会改什么？」 |
| 归因 | 「这个结果多大程度靠你？」 |

**判据**：答不上来的追问点 → 说明该经历「不熟」，要么补事实，要么从简历删掉。

## ⚠️ 红线（不得绕过）

- **不编造经历、学历、获奖、实习、时间线** —— 只做「相关性重构」
- 面试不教「圆谎」；简历只保留可被追问到底的内容
- 商业计划书与作品集同样**只给结构，不代写**
