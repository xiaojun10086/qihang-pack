# 简历岗位定制

- **归属域**：`F8` 求职与竞赛（生活类）
- **来源**：改造自 `Paramchoudhary/ResumeSkills`（MIT，resume-tailor）· 骨架提取重写 + DUT 特化
- **定位**：同一份真实经历，针对不同岗位生成不同的「侧重点版本」——选择与重排，不是创造。

## 前置（不可跳过）

1. 1 级库已完成**需求明确**（6 槽位 + 澄清门；先过 §5 例外，关键槽 `O/T/D` 齐全且不歧义即放行）
2. 1 级库已完成**域审查**，确认命中本域

## 边界

- 覆盖：简历的岗位定向改写（概要 / 技能排序 / 经历侧重）、一岗一版本管理
- 不覆盖：求职路径规划 → `career-kit`；竞赛选择 → `competition-pick`；实习内推信息 → 就业信息网；个人陈述 / 文书 → `F7`（升学线）

## 执行步骤

1. **解析岗位**：从招聘描述（JD）提取 ① 必备技能关键词 ② 隐含优先级（排前面的要求权重高）③ 岗位核心产出物
2. **审计现有简历**：逐节问「这一条支持我投这个岗位吗？」——分三堆：强相关 / 弱相关 / 无关
3. **三处定制**（真实前提下）：
   - **概要**：镜像 JD 的核心要求重写（真实经历的换角度表述）
   - **技能栏**：强相关技能提到最前；JD 出现而你确实具备的关键词补进去
   - **经历**：条目顺序按相关度重排；每条 bullet 用「动作 + 对象 + 量化结果」改写（数字必须真实）
4. **一岗一版本**：`resume-<公司>-<岗位>.md` 命名管理多版本；母版只存事实，不存侧重点
5. **真实性自检**：任何一条 bullet 去掉所有修饰词后仍可被你本人用 30 秒讲出真实出处——讲不出的条目删除
6. 输出「定制版简历 + 改动清单（哪条重排 / 哪条补关键词 / 哪条删）」

## 方法库 · 判定细则

**侧重点版本**：同一真实经历，按岗位重排模块顺序与用词。

| 岗位 | 先放 |
|---|---|
| 研发 | 项目 / 技术栈 |
| 产品 | 需求 / 数据 |

**纪律**：只做选择与重排，不创造；写不出细节的经历宁删不编。

**DUT 特化**：岗位口径对齐 DUT 就业信息网的校招节奏（秋招 9–11 月、春招 3–5 月），简历版式按学校就业指导中心通行要求（一页、倒序、量化成果），校内竞赛与项目经历按 DUT 赛事名称规范书写。

**判定顺序**：先判是不是「编造 / 补充经历」请求，是则只做重排与措辞 → 再判目标岗位属哪一类 → 最后才按岗位重排模块顺序与用词。

**高频误判**

- ❌ 把「编得更丰富点」当优化 → ✅ 只做选择与重排，不创造
- ❌ 一份简历投所有岗位 → ✅ 按岗位重排模块顺序与用词，同一段经历可以有不同侧重点
- ❌ 写不出细节就编一段 → ✅ 写不出细节的经历宁删不编
- ❌ 版式随意排 → ✅ 版式按学校就业指导中心通行要求，页数与顺序都有约定
- ❌ 时间线随手改 → ✅ 经历时间线与成果量化都要与真实一致

## 可执行示例

**示例 1（正常命中）**

**输入**

> 投一个数据分析实习岗，我的简历是按学生工作写的，帮我改

**澄清判定**：对象（简历）、任务（面向数据分析岗定制）、产出（定制版 + 改动清单）齐全 → 不追问

**输出**

```
【结论】把「学生工作版」重排成「数据技能前置版」：课程项目上移、量化条目保留、无关条目砍掉。
【依据】JD 关键词：SQL / Python / 数据可视化 / 沟通；你的经历里前三项都有实证
【结果】① 概要改写：突出「Python 课程设计 + 调研数据处理」的真实组合
       ② 技能栏：SQL、Python、数据可视化提到最前（按 JD 顺序）
       ③ 经历重排：含数据处理的项目经历移到学生工作之前
       ④ 真实自检：每条 bullet 去修饰词后仍能 30 秒讲出真实出处
       → 产出：resume-XX公司-数据分析实习.md + 改动清单
【下一步】把 JD 原文和现简历发我，先做第①②步
【建议】只点亮真实经历（合规边界：不虚构任何条目）；成绩单/证书以原件为准
```

**示例 2（边界 / 失败例 —— 不该命中的情形）**

**输入**

> 帮我把这段实习经历编得更丰富点

**澄清判定**：命中红线（编造经历）→ 依 `clarity.md` §5 例外 2 放行域锁定后按红线拒绝并给替代

**为什么这样判**：编造经历属禁答范围，本 skill 一律只降级不代劳，只做真实经历的重排与措辞优化。

**输出**

```
【结论】不编造经历；只做真实经历的重排与措辞优化。
【依据】合规边界：不编造经历 / 时间线
【结果】只交付岗位定制的重排方案，经历内容保持真实不变 —— 编造类请求一律只降级不代劳。
【替代方案】岗位定制的重排方案
【下一步】提交真实经历原文，做侧重点版本
```

## ⚠️ 红线（不得绕过）

- **不编造经历、学历、获奖、实习、时间线** —— 只做「相关性重构」
- 面试不教「圆谎」；简历只保留可被追问到底的内容
- 商业计划书与作品集同样**只给结构，不代写**
