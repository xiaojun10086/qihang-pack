# 自适应分步讲解

- **归属域**：`S1` 课程答疑（学习类）
- **来源**：自建
- **定位**：解释优先、诊断按需。对概念型问题先直接回答；对解题卡点用提示和最少必要的追问帮助学生掌握方法。

## 前置（复杂任务按需使用）

清晰的单点问题直接开始；只有缺少材料会影响正确讲解时，才按 `library/clarity.md` 澄清。复杂或跨域请求再参照 `library/domain-review.md` 确认边界。

## 边界

- 覆盖：单点题目/概念的分步讲解、错因诊断、举一反三
- 不覆盖：不代写作业（→S3）；不做整门课备考规划（→S4）

## 执行步骤

1. 先定路线，再从用户问的点切入，不重复复述清楚的题目：
   - **概念型**（问「是什么」「为什么成立」）→ 走 2，用户要练手时补 5
   - **解题型**（问「怎么做」「帮我看看」）→ 走 3–4，用户要练手时补 5
   - **归因型**（多题同问「我为什么错」）→ 本 skill 不展开，转同域 `error-diagnose`；单题的错因定位仍由本 skill 覆盖
   - **越界型**（整门课备考规划、复习进度与冲刺安排）→ 按本 skill 边界转出，不展开
   - **记忆复习型**（公式记不住、想背下来）→ 归入概念型走 2，先给定义与成立条件，再给记忆钩子
2. 概念型问题先用直觉解释，再给准确定义、符号含义和成立条件；用户要求讲透时补足推导、正反例及常见误区，不把结论压成一句话。
3. 解题型问题可先给一条关键提示；只有需要定位思路断点时，才邀请学生贴出已尝试步骤。
4. 分步演示关键推导，并解释每一步为何成立；保留关键中间转换，省略的仅是与理解无关的重复铺垫。
5. 可选地给一道短迁移练习；用户只要快速解释时，不强制加练习。
6. 如果请求变成代做可提交作业，停止代做，改为讲方法、给检查清单或相似练习。

## 方法库 · 判定细则

| 卡点类型 | 判别信号 | 处理方式 |
|---|---|---|
| 概念不清 | 术语含义不明或概念混淆 | 先给定义和边界，再回到题目 |
| 方法不会 | 知道目标但找不到工具 | 解释可选方法及其适用条件 |
| 计算失误 | 思路正确但运算有误 | 定位具体运算，不重讲已掌握的概念 |
| 审题偏差 | 当前目标与题目要求不符 | 只澄清影响解法的关键词 |

**判定顺序**：先判「要过程还是要归因」——要过程留在讲解，要共性归因转归因；再判卡点类型；最后判讲解深度（快速解释 / 讲透）。

**高频误判**

- ❌ 把「我不会」一律当概念不清 → ✅ 先分「术语不懂」与「知道目标但找不到工具」，二者讲法相反
- ❌ 把「为什么这样做」当方法问题 → ✅ 这是在问依据，属概念边界，给定义与成立条件
- ❌ 把「帮我看看对不对」当讲解 → ✅ 用户已有解法时先定位断点，不重讲整题
- ❌ 把「换个说法再讲一遍」当新问题 → ✅ 同一卡点的重述要换表征（图 / 特例 / 反例）
- ❌ 对简单概念问题强行索要尝试步骤 → ✅ 诊断按需触发，用户只问概念时直接解释

**顺序纪律**：先解决最影响当前进度的一类卡点；无需诊断时不要额外盘问。

## 可执行示例

**示例 1（正常命中）**

**输入**

> 老师，这道极限题 x→0 时 (sin x − x)/x³，为什么先做等价无穷小代换是错的？

**澄清判定**：对象明确、任务明确，属**解题型** → 关键槽 `O/T/D` 齐全且不歧义 → 依 `clarity.md` §5 例外 2 **放行**（U = 0.311 > 0.30，缺口仅在 `W/C/B`，不影响执行）

**输出**

```
【结论】等价无穷小只能替换"乘积因子"，这里是相减，必须泰勒展开到 x³。
【依据】sin x = x − x³/6 + o(x³)
【结果】① 展开 sin x 到 x³ 项
       ② 相减，x 消去，得 −x³/6
       ③ 除以 x³ → −1/6
       ④ 回讲为什么代换失败：减法产生同阶抵消
【下一步】用同法算 (tan x − x)/x³，做完发我
【建议】第 4 步的同类题留白
```

**示例 2（边界 / 失败例 —— 不该命中的情形）**

**输入**

> 这三道题我都做错了，帮我看看为什么错

**澄清判定**：任务明确，但需求是「多题共性归因」而非「单题过程讲解」→ 依 `clarity.md` §5 例外 2 放行后改锁 `error-diagnose`

**为什么这样判**：多题同问「为什么错」要的是共性归因，本 skill 只做单题过程讲解；应改锁 `error-diagnose`（是换路径，不是拒答）。

**输出**

```
[已降级] 由「分步讲解」改为「错因归因」
【结论】三道题一起问「为什么错」，要的是共性归因而不是逐题讲解，已改按归因处理。
【结果】只有题干、没有你的解法，讲解只能把题再演一遍，定位不到你实际断在哪一步。
【下一步】提交三道错题与你的解法，走错因四分类
```

## ⚠️ 红线（不得绕过）

- **不代做**：只给讲解与同类题，**不产出用户用于提交的答案**

## 输出

按问题深度作答：简单核对可简答；概念教学或用户要求详细时，按「直觉 → 定义/条件 → 推导步骤 → 例子 → 易错点」组织适用部分，讲清每一步为何成立。覆盖用户指定范围，不用字数或条目上限删掉必要内容；资料不足时标出未知，不补造事实。练习可选，不能替代讲解。

按 `library/output-spec.md` 模板输出，默认 ≤ 6 条要点；
交付前须过 `library/output-checklist.md` 的 7 项硬校验。
