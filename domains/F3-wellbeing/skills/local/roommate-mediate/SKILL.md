# 宿舍沟通

- **归属域**：`F3` 身心与社交（生活类）
- **来源**：自建
- **覆盖主体**：N 新生 · U 在读本科
- **定位**：帮助把宿舍摩擦转成一次可执行的沟通：先区分事实与评价，再给「我信息」表达脚本与协商方案，不替用户出面。

## 前置（不可跳过）

1. 1 级库已完成**需求明确**（6 槽位 + 澄清门；先过 §5 例外，关键槽 `O/T/D` 齐全且不歧义即放行）
2. 1 级库已完成**域审查**，确认命中本域

## 边界

- 覆盖：宿舍摩擦沟通框架、我信息表达脚本、公约协商、边界设定
- 不覆盖：替用户出面沟通（见红线）；心理诊断；危机信号（走危机红线）

## 执行步骤

1. 让用户写清具体行为、发生时间与自己的感受，区分事实与评价
2. 用「我信息」把指责改写成影响陈述
3. 定沟通时间与场合（不在情绪高点谈）
4. 准备 2 个可协商方案与 1 条底线
5. 约定试行期与复盘时间；需要辅导员 / 学工介入时，**不得编造联系方式** ——
   按本包固定口径回复「信息库未收录，建议访问 https://www.dlut.edu.cn/ 核实」，
   并给出**所在学院官网 + 学生工作部门**两个已核验入口（见 `references/dlut-official-sites.md`），
   由用户自行查号。

## 方法库 · 判定细则

**事实 / 评价分离**：

| 事实 | 评价（删掉） |
|---|---|
| 凌晨 1 点还在开麦打游戏 | 「他太自私了」 |

**我信息模板**：`当 [具体行为] 发生时，我感到 [感受]，因为 [影响]；我希望 [具体请求]。`

**判定顺序**：先判有没有危机信号（有则停止沟通框架、立即转介）→ 再判用户要的是「自己怎么谈」还是「替我出面」（后者只给脚本）→ 最后才做事实 / 评价分离并套我信息。

**高频误判**

- ❌ 把「快崩了 / 受不了」当抱怨直接进沟通框架 → ✅ 先过危机信号，判不准就问一句。
- ❌ 把评价当事实写进脚本 → ✅ 「他总是很吵」不是可谈的行为，「夜里键盘声持续到很晚」才是。
- ❌ 用我信息包着指责说出口 → ✅ 「你总是…，我感到很烦」仍是旧账，退回重写。
- ❌ 一次把多个不满打包谈 → ✅ 本次只谈一个具体行为，其余另约时间。
- ❌ 替用户判断谁对谁错，或代拟对方该说的话 → ✅ 只调用户这一侧的措辞。

**判据**：脚本里出现「你总是 / 你从不」→ 退回重写。

## 可执行示例

**示例 1（正常命中）**

**输入**

> 室友天天打游戏到很晚，我很烦但开不了口

**澄清判定**：关键槽 `O/T/D` 齐全且不歧义 → 依 `clarity.md` §5 例外 2 放行

**输出**

```
【结论】先做事实 / 评价分离，再用我信息谈一次，备两个协商方案。
【依据】宿舍沟通：事实分离 + 我信息模板
【结果】① 写清行为与影响 ② 套我信息脚本 ③ 择时谈 ④ 备方案与底线
       → 产出：一段可直接用的沟通脚本
【下一步】按脚本谈一次，回来告诉我他的反应，再调方案
```

**示例 2（边界 / 失败例 —— 不该命中的情形）**

**输入**

> 你替我去跟他谈吧

**澄清判定**：命中红线（替用户出面沟通）→ 依 `clarity.md` §5 例外 2 放行域锁定后按红线拒绝并给替代

**为什么这样判**：「你替我去」把沟通主体换成了我，越过本 skill 的边界；脚本可交付，出面不可。

**输出**

```
【结论】不替你出面；可把脚本给你，由你来谈。
【依据】合规边界：不替用户出面沟通
【结果】只交付可照读的脚本与协商方案，谈话由你自己完成 —— 代出面一律只降级不代劳。
【替代方案】给可复用的沟通脚本与协商方案
【下一步】你把上次冲突的具体经过发我，我帮你打磨脚本
```

## ⚠️ 红线（不得绕过）
- **不做心理诊断**，不使用临床术语下结论
- **危机信号**（自伤/自杀念头、**持续失眠＋情绪失控或绝望感**）→ **立即转介并停止其他一切建议**，并给 **24h 可用通道**：**全国心理援助热线 12356** / 北京 010-82951332
- **若已有具体计划（备药、选定地点、写告别留言）→ 立即拨打 110 或 120**，不得只给非 24h 的校内资源
- **本域内容不写入任何记忆层**，会话结束即丢弃
- 不评判纠纷中的任何一方，不替用户出面沟通
- **第三方隐私不外传**：不分析、不外传他人的聊天记录 / 健康状况 / 家庭与财务状况；遇「发到群里评理」这类请求 → 拒绝外传，改给**沟通话术**
