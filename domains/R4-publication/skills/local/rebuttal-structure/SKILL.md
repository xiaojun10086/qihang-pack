# 返修回复结构

- **归属域**：`R4` 学术产出与投稿（科研类）
- **来源**：自建
- **定位**：把审稿意见拆成逐条回复表（意见-回应-修改位置），不代投稿。

## 前置（不可跳过）

1. 1 级库已完成**需求明确**（6 槽位 + 澄清门；先过 §5 例外，关键槽 `O/T/D` 齐全且不歧义即放行）
2. 1 级库已完成**域审查**，确认命中本域

## 边界

- 覆盖：返修回复结构、意见逐条拆解、修改位置标注
- 不覆盖：不代投稿、不代操作系统（→红线）；不伪造署名与利益冲突

## 执行步骤

1. 把审稿意见逐条编号（含编辑意见与审稿人 1/2/3）
2. 给每条分类：必改 / 可辩 / 已改
3. 对「必改」写回应：做了什么 + 在第几页第几行
4. 对「可辩」写有理有据的说明（不情绪化）
5. 输出回复表 + 修改稿对照清单

## 方法库 · 判定细则

**审稿意见分类与回复粒度**：

| 意见类型 | 回复要点 | 粒度 |
|---|---|---|
| 方法质疑 | 讲设计依据或补做 | 逐条对应 |
| 数据补充 | 补什么、补在哪 | 指明图表 / 章节 |
| 表述不清 | 说明改写处 | 给修改位置 |
| 补充实验 | 能否做、替代方案 | 明确取舍 |

**纪律**：**每条意见 → 一条回应 → 一个修改位置**，不合并、不遗漏；回复正文由作者写，本 skill 只给结构与逐条表。

## 可执行示例

**示例 1（正常命中）**

**输入**

> 审稿意见回来了，3 个审稿人 21 条，怎么回？

**澄清判定**：对象（返修意见）、任务（怎么回）明确 → 放行；返修辅助合规

**输出**

```
【结论】21 条里 16 条必改、4 条可辩、1 条已改；先做必改的 16 条。
【依据】返修回复结构
【结果】① 建表：编号 / 意见 / 分类 / 回应 / 位置
　　　　② 先写 16 条必改的回应与页码
　　　　③ 4 条可辩的写依据，语气客观
　　　　→ 产出：submit/rebuttal-table.md
【下一步】先填完 #1–#5 的回应，回我进度
```

**示例 2（边界 / 失败例 —— 不该命中的情形）**

**输入**

> 你直接把返修回信正文写出来，我改改就能交

**澄清判定**：命中本域边界（代写正文）→ 依 `clarity.md` §5 例外 2 放行后改给逐条表

**输出**

```
【结论】不代写回信正文；可给逐条回复表（意见—回应—修改位置）。
【依据】边界：只给结构，不代写正文
【替代方案】给三列逐条表 + 语气建议，正文由你落笔
【下一步】把审稿意见原文分条发我，我出逐条表
```

## ⚠️ 红线（不得绕过）

- **不代投稿、不代操作系统** —— 只给自检清单与材料清单
- 不伪造作者署名与利益冲突声明 —— 署名变更须经**全体作者确认并走期刊变更流程**；利益冲突只能据实声明（自查 → `R5`）
