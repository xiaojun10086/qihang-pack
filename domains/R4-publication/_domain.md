# R4 · 学术产出与投稿

> 域 ID `R4` ｜ 所属大类 **科研类** ｜ 目录 `domains/R4-publication/`

## 域边界

- **覆盖**：论文投稿、专利与会议、基金申报、返修回复
- **不覆盖**：不做出稿前的结构打磨（→S5）

## 触发词（命中任一即锁定本域）

`投稿` ｜ `期刊` ｜ `专利` ｜ `会议` ｜ `基金` ｜ `大创结题` ｜ `审稿意见` ｜ `返修`

## 库内 skill（唯一通道，无需安装）

- **`submit-kit`** — 投稿返修工具包（自建）
  先跑投稿前自检（结构/引用/数据），再给期刊匹配与审稿意见逐条回复表。

- **`rebuttal-structure`** — 返修回复结构（自建）
  把审稿意见拆成逐条回复表（意见-回应-修改位置），不代投稿。

- **`defense-qa`** — （思路参考 Gabberflast/academic-pptx-skill（专有许可证，零内容摘录））
  幽灵测试 + 三问自审 + 预设评委问题清单，把被质询变成可排练的环节

- **`patent-draft`** — 专利交底书（自建）
  给专利交底书的结构骨架与「技术问题—方案—效果」三要素自查，梳理权利要求思路，不代写不代提交。

- **`grant-apply`** — 基金申报（自建）
  面向基金申报书的结构骨架与评审维度自查（创新性 / 可行性 / 前期基础 / 预算合理性），只给框架与检查项。

## 执行顺序

0. **先判红线**（见下文 `## ⚠️ 红线` 节）—— 命中则**拒绝并给合规替代**（追问口径见 `library/clarity.md` §7）
1. 1 级库完成**需求明确**（`library/clarity.md`）：先过 §5 例外，未命中的再按关键槽与 `U` 判定
2. 1 级库完成**域审查**，确认命中 `R4`（`library/domain-review.md`）
3. 用**库内 skill**（库内 5 个：`submit-kit` · `rebuttal-structure` · `defense-qa` · `grant-apply` · `patent-draft`；按需求择一）执行
4. **输出与保存**：按 `library/output-spec.md` 输出 ≤6 条要点；默认不读写学习档案，仅用户明确要求保存时按 `library/memory.md` 处理。
5. 按 `library/skill-evolution.md` 记录本域习惯，并**只在可改段内**做非结构性自迭代（不改红线 / 输出契约 / 任何事实；不满足触发条件则不迭代）
6. **外部桥接（按需）**：库内 skill 与同域降级都接不住，且外部能力确有帮助时，读 `library/external-bridge.md` → 只查本域指定平台 → 过五步自检 → 输出首行标 `[外接] 来源 + 许可`；**未命中则回落「纯提示词模式」**（原有流程）。

## ⚠️ 红线（不得绕过）

- **不代投稿、不代操作系统** —— 只给自检清单与材料清单
- 不伪造作者署名与利益冲突声明 —— 署名变更须经**全体作者确认并走期刊变更流程**；利益冲突只能据实声明（自查 → `R5`）
