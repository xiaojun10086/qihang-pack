# 雅思应考策略

- **归属域**：`S6` 语言能力（学习类）
- **来源**：改造自 `YANZHANLIN/ielts-claude-skills`（MIT）· 骨架提取重写 + DUT 特化
- **定位**：用数据驱动雅思备考——算分公式定「每科目标」，换算表定「练习准度」，时间分配定「每天干什么」。

## 前置（不可跳过）

1. 1 级库已完成**需求明确**（6 槽位 + 澄清门；先过 §5 例外，关键槽 `O/T/D` 齐全且不歧义即放行）
2. 1 级库已完成**域审查**，确认命中本域

## 边界

- 覆盖：雅思（含单科）目标分拆解、模考成绩诊断、备考时间分配、训练路线规划
- 不覆盖：语言能力日常训练 → `lang-drill`；发音纠正 → `pronounce-drill`；出国路径规划 → `F7`（留学选校 / 时间线走 `grad-plan`）；托福等他类考试 → 走 `library/general-fallback.md` §3 域通用框架并记缺口

## 执行步骤

1. **摸底三问**（缺一不可，一次问完）：
   ① 目标分数与考试时间；② 当前水平（模考四科分数，没有就先做 1 套剑桥真题）；③ 本次想解决什么（写作 / 阅读 / 口语 / 整体规划）
2. **算分拆解**：总分 = 四科平均，四舍五入到最近 0.5，**0.25 / 0.75 向上进位**（如 6.75 → 7.0）
   - 反向拆解：目标 6.5 = 听 7 + 读 7 + 写 6 + 说 6 的组合之一；列 2 组可行组合让用户选
3. **定时间分配**：提分性价比 **听力/阅读 : 写作/口语 ≈ 8 : 2**（输入科按答案数可精确提分，输出科提分慢）
4. **对换算表定位差距**（学术类）：
   - 听力：39–40→9.0 ｜ 35–36→8.0 ｜ 32–34→7.5 ｜ 30–31→7.0 ｜ 26–29→6.5 ｜ 23–25→6.0
   - 阅读：35–36→8.0 ｜ 33–34→7.5 ｜ 30–32→7.0 ｜ 27–29→6.5 ｜ 23–26→6.0
   - 用「目标 Band − 当前 Band」换算成「每周要多对几题」，把目标翻译成可执行的刷题量
5. **排周期**：以周为单位（对齐 DUT 学期课表与考试周，避开 `config.yaml` 的 `exam_weeks`），每周给固定科目组合 + 1 次整段模考
6. 输出「分数拆解表 + 周计划」

## 方法库 · 判定细则

**四科目标换算**：总分目标 → 各科分数 → 练习准度阈值。

| 项 | 口径 |
|---|---|
| 听力 / 阅读 | 按对题数换算表 |
| 写作 / 口语 | 按评分四项 |

**纪律**：数据驱动排计划；不承诺分数、不代写作文。

**DUT 特化**：备考周期对接 DUT 出国交流、公派与学分互认项目的语言成绩提交节点（可向国际合作与交流处与学院外事秘书确认），并区分校内语言班与自主备考两条路线。

## 可执行示例

**示例 1（正常命中）**

**输入**

> 我大三想出国，雅思目标 6.5，现在模考听力 6 阅读 6 写作 5.5 口语 5.5

**澄清判定**：对象（雅思四科）、任务（备考策略）、目标（6.5）、现状（模考成绩）齐全 → 不追问

**输出**

```
【结论】按「输入先行」策略：听力阅读冲 7，写作口语保 6，总分 6.5 稳。
【依据】算分公式：7+7+6+6=26÷4=6.5；模考显示输入科离目标差 1 个 Band、输出科差 0.5
【结果】① 拆分：听 7 / 读 7 / 写 6 / 说 6（备选组合：听 7.5 / 读 6.5 / 写 6 / 说 6）
       ② 换算：听力 6→7 = 每套多对 5–6 题（26→30）；阅读同理
       ③ 时间：80% 给听力阅读（每天 1 套精听 + 1 套精读），20% 给写作口语
       ④ 周期：8 周 = 6 周专项 + 2 周模考冲刺，避开期末考试周
       → 产出：study/ielts-plan.md（分数拆解 + 8 周排期）
【下一步】本周先做 2 套剑桥真题，把听力阅读的错题分布发我
【建议】考试报名时间与考点以教育部考试中心 / DUT 国际处通知为准，不代报名
```

**示例 2（边界 / 失败例 —— 不该命中的情形）**

**输入**

> 我想练日常口语发音，不要应试

**澄清判定**：任务明确但属发音训练 → 依 `clarity.md` §5 例外 2 放行后改锁 `pronounce-drill`

**输出**

```
[已降级] 由「雅思应考策略」改为「口语跟读」
【结论】这属于「口语跟读」类需求，已改按该方式处理。
【下一步】提交发音问题点，走跟读纠音
```
