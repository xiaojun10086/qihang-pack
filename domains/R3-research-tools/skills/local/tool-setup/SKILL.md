# 科研环境搭建

- **归属域**：`R3` 科研工具与代码（科研类）
- **来源**：自建
- **定位**：先问清目标工具与系统，再给最小可用环境步骤；报错按「复现 → 最小化 → 假设 → 插桩验证 → 修复」处理。

## 前置（不可跳过）

1. 1 级库已完成**需求明确**（6 槽位 + 澄清门；先过 §5 例外，关键槽 `O/T/D` 齐全且不歧义即放行）
2. 1 级库已完成**域审查**，确认命中本域

## 边界

- 覆盖：科研编程环境、脚本编写、版本管理、仿真工具
- 不覆盖：不做算法题训练（→S1）

## 执行步骤

1. 明确目标工具与操作系统
2. 给最小可用环境步骤（虚拟环境 + 依赖）
3. 报错处理：复现 → 最小化 → 假设 → 插桩验证 → 修复
4. 版本管理：给 .gitignore 与提交规范
5. 给可复现的目录结构
6. 输出环境清单与 README

## 方法库 · 判定细则

**报错五步法**：

| 步 | 动作 | 产物 |
|---|---|---|
| 1 复现 | 记录最简触发路径 | 一段可复现命令 |
| 2 最小化 | 删到只留出错部分 | 最小样例 |
| 3 假设 | 列 1–3 个可能原因 | 可验证假设 |
| 4 插桩 | 打日志 / 打印中间量 | 定位到行 |
| 5 修复 | 只改必要处并回归 | 修复 + 回归结果 |

**纪律**：环境信息（系统 / 版本 / 安装方式）不清就**先追问**，不猜着给方案；逐层排除而非一次给十条命令。

## 可执行示例

**示例 1（正常命中）**

**输入**

> Python 跑机器学习，环境老装不好

**澄清判定**：缺「操作系统/具体报错」→ 追问 1 问

**输出**

```
【结论】用 conda 建独立环境，别在 base 里装。
【结果】① 建环境：conda create -n ml python=3.11
       ② 先装 torch 再装其余（顺序敏感）
       ③ 报错处理：复现 → 最小化 → 假设 → 插桩 → 修复
       ④ 固化：pip freeze > requirements.txt
       → 产出：env/requirements.txt + README
【下一步】把完整报错贴给我，我定位
【建议】网信中心有正版软件与超算资源 https://its.dlut.edu.cn/
```

**示例 2（边界 / 失败例 —— 不该命中的情形）**

**输入**

> 装不上，报错了

**澄清判定**：关键槽「环境 / 报错原文」缺失 → 依 `clarity.md` §5 例外 2 放行后**追问**

**输出**

```
【结论】信息不足，先补齐再给方案（盲猜易给错命令）。
【依据】报错五步法：先复现再诊断
【还需确认】① 什么系统与版本 ② 装什么工具 ③ 完整报错原文（三问即可定位）
【下一步】回我这三项，我按五步法带你排查
```
