# 可复现环境

- **归属域**：`R3` 科研工具与代码（科研类）
- **来源**：自建
- **定位**：固定依赖版本、随机种子与目录结构，产出可复现运行脚本，不代做课业代码。

## 前置（不可跳过）

1. 1 级库已完成**需求明确**（6 槽位 + 澄清门，U ≤ 0.30）
2. 1 级库已完成**域审查**，确认命中本域

## 边界

- 覆盖：环境锁定、随机种子、可复现运行
- 不覆盖：不代做课业代码（→S1/S3）；不代操作教务系统（→F1）

## 执行步骤

1. 记录解释器/依赖/系统三件套的版本
2. 写出依赖清单（requirements/environment）并锁定版本
3. 固定随机种子与数据划分方式
4. 整理目录结构（data / src / out / logs）
5. 给一条命令从零跑到出结果，并声明预期产物

## 可执行示例

**输入**

> 我上学期跑出来的结果，这学期重跑数字不一样了

**澄清判定**：对象（复现问题）、任务（让结果一致）明确 → 放行

**输出**

```
【结论】主因是没固定随机种子与依赖版本；三步就能锁死。
【依据】可复现三件套（库内 skill repro-env）
【步骤】① 记下 python/numpy 版本并写进 requirements.txt
　　　　② 脚本开头固定 seed（random/numpy/torch）
　　　　③ 数据划分改成固定索引而非随机打乱
【产物】env/requirements.txt · src/seed.py · 复现说明.md
【下一步】先把三处 seed 加上重跑一次，看数字是否稳定
```
