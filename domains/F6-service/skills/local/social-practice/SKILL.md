# 社会实践立项

- **归属域**：`F6` 军训与志愿（生活类）
- **来源**：自建
- **覆盖主体**：P 学生干部 / 社团负责人
- **定位**：面向社会实践（三下乡 / 调研）的立项：选题打磨、可行性与安全评估、报告结构，只给方法与模板不代写正文。

## 前置（不可跳过）

1. 1 级库已完成**需求明确**（6 槽位 + 澄清门；先过 §5 例外，关键槽 `O/T/D` 齐全且不歧义即放行）
2. 1 级库已完成**域审查**，确认命中本域

## 边界

- 覆盖：社会实践选题与立项书结构、可行性与安全评估、调研方法、结项报告结构
- 不覆盖：代写正文（→`S3` / `S5`，见红线）；活动执行与志愿时长认定（→`service-log`）；经费（→`F4`）

## 执行步骤

1. 打磨选题：把大主题收窄成可调查的具体问题
2. 给立项书结构（背景 / 目标 / 方法 / 分工 / 预期成果）
3. 做可行性评估（时间 / 经费 / 安全 / 对象可及性）
4. 给调研方法建议（问卷 / 访谈 / 样本量口径）
5. 给结项报告结构，正文由团队自写

## 方法库 · 判定细则

**立项可行性四问**：
1. 时间够不够在一个假期内完成？
2. 经费来源是否落实？
3. 实践地是否有安全预案？
4. 调研对象是否可接触？

**判定顺序**：先判请求是不是「代写正文 / 代填立项书」（命中即只给骨架，不进入后续判定）→ 再判选题是否已收窄成可调查的具体问题 → 最后才过可行性四问。

**高频误判**

- ❌ 大主题直接进可行性四问 → ✅ 未收窄的选题过不了关，先收窄再问。
- ❌ 把四问答「否」当成项目不可行 → ✅ 是「先补该问」，不是替用户否决项目。
- ❌ 把资源承诺当成可行性评估 → ✅ 经费与安全由实践队落实，本 skill 只出问题清单与结构。
- ❌ 给了结项报告骨架就顺手续写正文 → ✅ 结构到此为止，正文由团队自写。
- ❌ 把志愿时长认定、活动执行一并接走 → ✅ 属 `service-log` / `volunteer-hours` 的范围，不得顺手开记录。

**判据**：四问中任一答「否」→ 先解决该问，再写立项书。

## 可执行示例

**示例 1（正常命中）**

**输入**

> 我们想做一个乡村振兴主题的社会实践，怎么立项

**澄清判定**：关键槽 `O/T/D` 齐全且不歧义 → 依 `clarity.md` §5 例外 2 放行

**输出**

```
【结论】先把主题收窄成一个可调查的问题，再过可行性四问。
【依据】社会实践立项：立项结构 + 可行性四问
【结果】① 收窄选题 ② 过四问 ③ 搭立项书骨架 ④ 定调研方法
       → 产出：立项书结构骨架 + 可行性评估
【下一步】先回答可行性四问，把答案发我，再补立项书
```

**示例 2（边界 / 失败例 —— 不该命中的情形）**

**输入**

> 帮我把立项书写了吧

**澄清判定**：命中红线（代写正文）→ 依 `clarity.md` §5 例外 2 放行域锁定后按红线拒绝并给替代

**为什么这样判**：「帮我写」是代写请求，命中红线；给骨架不等于给正文，故只降级不代劳。

**输出**

```
【结论】不代写立项书正文；可给结构骨架与自查清单。
【依据】合规边界：不代写正文
【结果】交付物只有结构骨架与自查清单，正文仍由你写 —— 代写请求一律只降级不代劳。
【替代方案】立项书结构骨架 + 可行性四问
【下一步】你按骨架填，写完发我审结构
```
