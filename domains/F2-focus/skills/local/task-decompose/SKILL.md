# 拖延拆解

- **归属域**：`F2` 作息与专注（生活类）
- **来源**：自建
- **定位**：把「不想开始」的大任务拆成 ≤25 分钟可启动的动作，配番茄钟执行。

## 前置（不可跳过）

1. 1 级库已完成**需求明确**（6 槽位 + 澄清门；先过 §5 例外，关键槽 `O/T/D` 齐全且不歧义即放行）
2. 1 级库已完成**域审查**，确认命中本域

## 边界

- 覆盖：任务拆解、启动阻力消除、专注窗口排布
- 不覆盖：不为学业规划代劳（→S4）；不做心理诊断（→F3）

## 执行步骤

1. 写下那个被拖延的任务原话
2. 识别阻力类型：太大 / 太模糊 / 怕做错 / 缺材料
3. 切出「25 分钟内能完成且能验收」的第一个动作
4. 排一个固定专注窗口（写进日程）
5. 约定完成后只做「记一句结果」，不顺手加任务

## 方法库 · 判定细则

**拆解判据**：拆到「≤25 分钟可启动、有明确完成信号」。

| 大任务 | 拆法 |
|---|---|
| 写论文 | 先写 1 段提纲 |
| 做实验 | 先备 1 个样品 |

**反例**：「整理资料」不是动作，「把 3 篇文献的结论抄成表」才是。

## 可执行示例

**示例 1（正常命中）**

**输入**

> 论文开题报告拖了三周，一想到就烦

**澄清判定**：对象（开题报告）、任务（怎么开始）明确 → 放行；情绪一般，不升级 F3

**输出**

```
【结论】你卡在"太大"：今天只写"研究问题一句话"。
【依据】拖延拆解四类阻力
【结果】① 打开空白文档，写下标题
　　　　② 只写研究问题一句话（≤25 分钟）
　　　　③ 写完记一句"结果"，今天就停
　　　　→ 产出：plan/开题-最小启动.md
【下一步】现在开文档，25 分钟后把那一句话发我
```

**示例 2（边界 / 失败例 —— 不该命中的情形）**

**输入**

> 一想到写论文就烦，根本启动不了

**澄清判定**：任务明确但属启动障碍 → 依 `clarity.md` §5 例外 2 放行后改锁 `anti-procrastinate`

**输出**

```
[已降级] 由「拖延拆解」改为「拖延干预」
【结论】这属于「拖延干预」类需求，已改按该方式处理。
【下一步】描述最近一次拖延情境，判类型
```
