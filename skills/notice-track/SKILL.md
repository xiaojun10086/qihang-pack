# 通知与截止节点

## 执行前置

- 本文所有包内相对路径均以本 `SKILL.md` 所在目录为基准，不以用户当前工作目录（cwd）为基准。
- 执行任何业务步骤前，先完整读取并遵守 `../using-qihang/SKILL.md` 中的共享行为准则及安全兜底，再完整读取 `../../config.yaml`。这里只加载共享规则和配置，不重复总入口路由。
- 本会话已完整加载上述文件时可复用；必需文件不可读时，停止本包执行并说明缺失或不可读的文件，不猜测规则。

## Overview

每条节点必须带来源与截止时间；来源不可核验时标注状态，不猜时间。

## When to Use

追踪通知公告、报名与考试节点、评奖时间线。**不适用**：一般校园信息检索 → `campus-search`。

## 执行流程

1. 明确要追踪的事项（考试报名 / 评奖 / 夏令营 / 缴费）
2. 定位权威来源（教务处 / 研究生院 / 学院 / 新闻网等公开站）
3. 摘录关键节点与截止时间，标注来源与核验状态
4. 生成追踪清单与提醒建议
5. 未收录的固定回复「信息库未收录」，给核实入口

**来源分级**：

| 级别 | 来源 | 可信度 |
|---|---|---|
| A | 职能部门官网通知 | 高 |
| B | 学院 / 辅导员通知 | 高 |
| C | 二手转述 / 群消息 | 需回源核实 |

**判定顺序**：先判是不是「要非公开个人信息」请求，是则只给公开联系方式 → 再判来源属哪一级（A / B / C）→ 最后才按级别给核实入口。

## 常见误判

- ❌ 把「查私人电话」当信息跟踪 → ✅ 不获取非公开个人信息，只查公开联系方式
- ❌ 群消息直接当通知节点 → ✅ 二手转述要回源核实，只凭 C 级要标待核实
- ❌ 只给 C 级不给核实入口 → ✅ 标 ⚠️ 待核实的同时要给 A 级核实入口
- ❌ 时间节点不标来源级别 → ✅ 每个节点都要能追到来源级别
- ❌ 编造通知链接 → ✅ 不编造链接与电话，只给可访问到的来源

**判据**：只有 C 级来源的节点 → 标 ⚠️ 待核实，并给 A 级核实入口。
