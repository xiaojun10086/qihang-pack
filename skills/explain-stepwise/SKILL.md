# 分步讲解

## 执行前置

- 本文所有包内相对路径均以本 `SKILL.md` 所在目录为基准，不以用户当前工作目录（cwd）为基准。
- 执行任何业务步骤前，先完整读取并遵守 `../using-qihang/SKILL.md` 中的共享行为准则及安全兜底，再完整读取 `../../config.yaml`。这里只加载共享规则和配置，不重复总入口路由。
- 本会话已完整加载上述文件时可复用；必需文件不可读时，停止本包执行并说明缺失或不可读的文件，不猜测规则。

## Overview

解释优先、诊断按需。概念型问题直接讲清定义与成立条件；解题型问题先给一条关键提示，只在需要定位思路断点时才请学生贴出已尝试的步骤。

## When to Use

单点题目或概念的分步讲解、易混概念辨析、前置知识补缺、举一反三练习。**不适用**：多道错题的共性归因 → `error-diagnose`；整门课或整本书系统学习 → `faster-cycle`；要求代做可提交的作业 → 明确拒绝并改给同类练习。

## 执行流程

### 分步讲解

1. 先定路线，再从用户问的点切入，不重复复述清楚的题目：
   - **概念型**（问「是什么」「为什么成立」）→ 走 2，用户要练手时补 5
   - **解题型**（问「怎么做」「帮我看看」）→ 走 3–4，用户要练手时补 5
   - **归因型**（多题同问「我为什么错」）→ 本 skill 不展开，转 `error-diagnose`；单题的错因定位仍由本 skill 覆盖
   - **超出范围型**（整门课备考规划、复习进度与冲刺安排）→ 按本 skill 边界转出，不展开
   - **记忆复习型**（公式记不住、想背下来）→ 归入概念型走 2，先给定义与成立条件，再给记忆钩子
2. 概念型问题先用直觉解释，再给准确定义、符号含义和成立条件；用户要求讲透时补足推导、正反例及常见误区，不把结论压成一句话。
3. 解题型问题可先给一条关键提示；只有需要定位思路断点时，才邀请学生贴出已尝试步骤。
4. 分步演示关键推导，并解释每一步为何成立；保留关键中间转换，省略的仅是与理解无关的重复铺垫。
5. 可选地给一道短迁移练习；用户只要快速解释时，不强制加练习。
6. 如果请求变成代做可提交作业，停止代做，改为讲方法、给检查清单或相似练习。

| 卡点类型 | 判别信号 | 处理方式 |
|---|---|---|
| 概念不清 | 术语含义不明或概念混淆 | 先给定义和边界，再回到题目 |
| 方法不会 | 知道目标但找不到工具 | 解释可选方法及其适用条件 |
| 计算失误 | 思路正确但运算有误 | 定位具体运算，不重讲已掌握的概念 |
| 审题偏差 | 当前目标与题目要求不符 | 只澄清影响解法的关键词 |

**判定顺序**：先判「要过程还是要归因」——要过程留在讲解，要共性归因转归因；再判卡点类型；最后判讲解深度（快速解释 / 讲透）。

### 追问导学（不直接给答案）

1. **理解题目**：读题干，内部完成解题，但**不输出**任何答案或关键结论
2. **摸底提问**：先问 1 个开放式问题评估用户当前水平（如「你觉得这道题在考哪个定理？」）
3. **渐进追问**（由浅入深，每轮 1 问；最多 3 轮无进展的引导，达到阈值后不再额外追问）：
   - 澄清类：暴露隐含假设 ——「你说要用洛必达，依据是什么？」
   - 深挖类：逼出下一步 ——「如果这个极限不存在，后面的推导还成立吗？」
   - 连接类：串联知识点 ——「这和上周讲的连续性有什么关系？」
   - 反例类：挑战错误思路 ——「如果换成 x→∞，你的结论还对吗？」
   - 假设类：推演后果 ——「把这个结论用到期末那道真题上会怎样？」
4. **回应策略**：
   - 方向对 → 简短确认后加深一层（「对，再往前走一步——」）
   - 方向错 → **不直接纠正**，问一个能暴露矛盾的问题（「那你怎么解释这个反例？」）
   - 说「不知道」→ 拆成更小的子问题
   - 直接索要答案 → 重申规则并给一个更小的切入点
5. **收口确认**：用户到达结论后，请他用自己的话复述一遍，并指出 1 个可以延伸的自查问题

**五类渐进提问**：澄清 → 深挖 → 连接 → 反例 → 假设。

| 轮次 | 若用户 | 动作 |
|---|---|---|
| 1–2 | 有进展或能回应 | 针对暴露的缺口继续提问；不机械换类别 |
| 1–3 | 卡壳或无实质进展 | 先把问题拆小；累计连续 3 轮无进展即停止并降级，不开启第 4 轮 |
| 任一轮 | 到达结论 | 请用户复述并收口，不为凑轮数继续追问 |

**判定顺序**：先判用户是否**明确选了「引导我自己想」**——未明确或要直接答案即留在本 skill 直接讲解；再判本轮该用哪一类提问（依用户上一轮暴露的缺口选，不按类别机械推进）；最后判是否已到降级阈值。

### 易混概念对照

1. 列出被混淆的 2–4 个对象，确认同属一个上位概念
2. 选 3–4 个辨析维度（定义域 / 条件 / 结论 / 反例）
3. 逐维度填对照表，标出「唯一差异点」
4. 对每个关键差异给出能说明边界的例子或反例；若用户要求完整辨析，不能只给口诀或只列结论
5. 总结判别方法，并说明它适用的条件与容易误用之处

**维度选择四问**（每次都从这四问里挑，避免维度漂移）：
1. 适用范围一样吗？→ 定义域 / 前提条件维度
2. 结论强弱一样吗？→ 充分必要维度
3. 反过来成立吗？→ 逆命题维度
4. 有没有只属于一个的反例？→ 反例维度

**判据**：若四个维度下表完全一致 → 这两个对象其实是同一个，停止辨析并告知用户。

**判定顺序**：先判对象是否**同属一个上位概念且真会被混**——若只是「想了解某个概念」，留在本 skill 直接讲解；再选辨析维度；最后找唯一差异点。

### 前置知识补缺

1. 让学习者写出当前卡在哪一步
2. 沿该步回溯 2–3 层找最早讲不清的概念
3. 判定断点类型（定义 / 定理条件 / 运算规则）
4. 只补解决当前卡点所需的最小前置单元，但须把该单元讲到可理解、可应用；不以「最小」为由只抛公式或结论
5. 用原题的下一步验证补齐是否生效
6. 给出断点清单与建议复习章节

| 断点类型 | 特征 | 处理方式 |
|---|---|---|
| 定义没记牢 | 说不出符号含义 | 补定义 + 1 个最小例子 |
| 定理条件不清 | 忽略前提直接用 | 补条件对照表 + 反例 |
| 运算规则用错 | 步骤对、结果错 | 补规则 + 易错反例 |

**判定顺序**：先判卡点**是不是前置断层**——若当前步骤所需概念用户讲得清，说明是单题问题，留在本 skill 直接讲解；再沿步骤回溯定位最早讲不清的一层；最后判断点类型（定义 / 定理条件 / 运算规则）。

## 常见误判

### 分步讲解

- ❌ 把「我不会」一律当概念不清 → ✅ 先分「术语不懂」与「知道目标但找不到工具」，二者讲法相反
- ❌ 把「为什么这样做」当方法问题 → ✅ 这是在问依据，属概念边界，给定义与成立条件
- ❌ 把「帮我看看对不对」当讲解 → ✅ 用户已有解法时先定位断点，不重讲整题
- ❌ 把「换个说法再讲一遍」当新问题 → ✅ 同一卡点的重述要换表征（图 / 特例 / 反例）
- ❌ 对简单概念问题强行索要尝试步骤 → ✅ 诊断按需触发，用户只问概念时直接解释

**顺序纪律**：先解决最影响当前进度的一类卡点；无需诊断时不要额外盘问。

### 追问导学（不直接给答案）

- ❌ 用户答错就直接纠正 → ✅ 那等于给了答案，应改问一个能暴露矛盾的反例
- ❌ 用户答对仍继续追问 → ✅ 方向对时只确认并加深一层，不重复同一类提问
- ❌ 按固定类别顺序机械推进 → ✅ 类别依用户暴露的缺口选，缺哪补哪
- ❌ 把「不知道」直接计入卡壳 → ✅ 应先拆成更小的子问题再问，仍无进展才算卡壳
- ❌ 提问里夹带答案关键词 → ✅ 题干本身不能泄露结论或关键中间量

**纪律**：提问是为了引导自悟，不是为了考倒用户；不因用户答错而否定。

**DUT 特化**：追问语料取材于 DUT 课程常见卡点（数学分析、大学物理、专业基础课），每次追问回扣培养方案对应能力点，使「自己发现答案」的过程同时对齐课程考核要求。

### 易混概念对照

- ❌ 把「讲一下 X」当辨析 → ✅ 只有一个对象时无从对照，属讲解
- ❌ 维度漂移 → ✅ 每次都从既定维度里挑，不临时另起，否则各列不可比
- ❌ 对照表填成定义复述 → ✅ 每格须落在**差异**上，相同项不必逐格重复
- ❌ 只给口诀不给反例 → ✅ 边界靠反例确立，口诀不能替代适用条件
- ❌ 对象其实等价却硬找差异 → ✅ 各维度全一致即说明同源，停止辨析

### 前置知识补缺

- ❌ 把「这题太难」当断层 → ✅ 须让学习者写出卡在哪一步，凭回溯定位，不凭难度感觉
- ❌ 一路追到中学内容 → ✅ 相邻层级讲得清即停，过度回溯会脱离原题
- ❌ 只抛公式或结论当补齐 → ✅ 最小补齐指**范围**最小，不是**深度**最小，须讲到可理解、可应用
- ❌ 断点判成「不会算」就只练运算 → ✅ 运算对而概念错时，真断点在定义或定理条件
- ❌ 补完不回原题验证 → ✅ 补齐是否生效，要用原题的下一步检验

回溯停止条件：连续两层都能讲清楚，即停 —— 不要一路追到高中内容。
