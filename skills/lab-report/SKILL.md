# 实验报告骨架

## 执行前置

- 本文所有包内相对路径均以本 `SKILL.md` 所在目录为基准，不以用户当前工作目录（cwd）为基准。
- 执行任何业务步骤前，先完整读取并遵守 `../using-qihang/SKILL.md` 中的共享行为准则及安全兜底，再完整读取 `../../config.yaml`。这里只加载共享规则和配置，不重复总入口路由。
- 本会话已完整加载上述文件时可复用；必需文件不可读时，停止本包执行并说明缺失或不可读的文件，不猜测规则。

## Overview

AI 只做结构与自查，想法与数据必须由用户提供。给完骨架后学生自己写正文。

## When to Use

实验报告、实验类课程报告的结构设计与提交前自查。**不适用**：课程论文与学位论文的论证打磨、摘要与答辩准备 → `paper-outline`；数据处理 → `data-lab`。

## 执行流程

### 实验报告骨架

1. 确认实验名称、目的、数据是否齐备
2. 按 IMRAD 出骨架：引言 / 方法 / 结果 / 讨论 / 结论
3. 分配各节字数（如 300/400/500/500/200）
4. 标记必须由本人完成的部分（数据处理、结论）
5. 给出格式自查清单（单位、有效数字、图表编号、引用）
6. 输出 Markdown / docx 落点

**IMRAD 字数分配**：引言 15% · 方法 25% · 结果 35% · **讨论与结论 25%**（结论节含在此份额内，合计 100%）。

| 节 | 只写什么 |
|---|---|
| 结果 | 数据与图表，不解释 |
| 讨论 | 与文献比对、局限 |

**判定顺序**：先判有没有「代写正文 / 编造数据」请求（有则只给骨架与自查）→ 再判数据是否齐备（缺则标待补，不给结论）→ 最后才排 IMRAD 骨架与字数。

### IMRAD 论文骨架

1. **人类主权双闸（先于一切）**：
   - 💡 **想法闸**：研究问题 / 论点必须由用户提出或从其草稿中提取——AI 可以帮打磨措辞、指出模糊，但**永不替用户发明论点**
   - 📊 **数据闸**：所有数据必须来自用户的实验 / 调研 / 计算——AI 永不生成任何数据点、被试或结果
2. **建项目目录**（骨架的物理形态）：
   ```
   paper-<课程或题目slug>/
   ├── 00-任务书.md      # 要求、截止日期、评分口径（抄任课教师原文）
   ├── 10-引言.md  20-方法.md  30-结果.md  40-讨论.md   # 四节骨架
   ├── refs.md           # 参考文献（每条必须有可回源锚点）
   └── checklist.md      # 写作前 / 提交前两套自查
   ```
3. **四节各给「填空式骨架」**（每节 3–5 个小节标题 + 每个小节的引导问题，不给正文）：
   - 引言：研究背景 → 已有工作 → 缺口 → 本文贡献（一句话）
   - 方法：设计 → 变量与测量 → 流程 → 分析方法（写作时最 solid 的一节，先写它）
   - 结果：图表先行 → 描述性统计 → 推断结果（只陈述，不解释）
   - 讨论：主要发现 → 与已有工作对照 → 局限 → 结论
4. **顺序建议**：方法 → 结果 → 引言 → 讨论（先写最确定的，最后写最需要全局观的）
5. **对抗性自审**（提交前红队）：站在「最挑剔的评阅人」角度对核心论点提 3 个问题写进 checklist，让用户逐一防守
6. 输出「项目目录 + 四节骨架 + 自查表」

**四节骨架文件**：每节给「要回答的问题 + 建议字数 + 自查项」。

| 节 | 要回答 |
|---|---|
| Intro | 为什么做 |
| Methods | 怎么做 |
| Results | 得到什么 |
| Discussion | 意味着什么 |

**纪律**：正文一个字不代写；骨架交付后由本人填充。

**DUT 特化**：骨架对接 DUT 学位论文与课程设计格式要求（章节编号、图表题注、公式编号、参考文献 GB/T 7714），并提供 DUT 毕业设计系统提交前的自查项。

**判定顺序**：先判请求是不是「骨架之外的正文代写」，是则一律只给骨架与自查 → 再判研究类型是否明确（不明先问）→ 最后才逐节给「要回答的问题 + 建议字数 + 自查项」。

## 常见误判

### 实验报告骨架

- ❌ 数据未齐就把结论节写实 → ✅ 结论只能由本人据数据得出，缺数据一律标「待补数据」
- ❌ 在「结果」节写解释 → ✅ 结果只放数据与图表，解释归讨论节
- ❌ 字数按节平均分 → ✅ 结果与讨论占大头，按份额分才能压住引言膨胀
- ❌ 拒绝代写只回一句 → ✅ 拒绝的同时要给骨架、字数与自查清单，才算可交付的替代
- ❌ 把格式自查当可选 → ✅ 单位、有效数字、图表编号、引用四类须逐项过一遍

**纪律**：只给骨架与自查；数据缺失时标「待补数据」，绝不编造。

### IMRAD 论文骨架

- ❌ 把「骨架我有了，正文你补上」当续写 → ✅ 正文一个字不代写，只给逐节自查清单
- ❌ 骨架只列节名 → ✅ 每节要给出「要回答的问题」，否则填的时候还是不知道写什么
- ❌ 结果与讨论混写 → ✅ 结果只答「得到什么」，讨论只答「意味着什么」
- ❌ 引用体例等到终稿再管 → ✅ 骨架阶段就对齐体例，否则回改成本极高
- ❌ 骨架交付即结束 → ✅ 交付后按节核回，写完一节核一节
