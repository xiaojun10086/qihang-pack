# 宿舍与离校

## 执行前置

- 本文所有包内相对路径均以本 `SKILL.md` 所在目录为基准，不以用户当前工作目录（cwd）为基准。
- 执行任何业务步骤前，先完整读取并遵守 `../using-qihang/SKILL.md` 中的共享行为准则及安全兜底，再完整读取 `../../config.yaml`。这里只加载共享规则和配置，不重复总入口路由。
- 本会话已完整加载上述文件时可复用；必需文件不可读时，停止本包执行并说明缺失或不可读的文件，不猜测规则。

## Overview

按「材料 → 入口 → 周期」给路径并逐项标来源；需要实际提交或缴费时转 `portal-operator` 代操作，涉及金额先复述再确认。

## When to Use

宿舍入住与调整、报修、离校手续。**不适用**：其他校园事务 → `campus-desk`。

## 执行流程

1. 判定场景：入住 / 报修 / 调宿 / 退宿 / 离校
2. 列出该场景所需材料与办理地点
3. 给对应系统或窗口入口
4. 提示关键时间节点（退宿截止、离校清单）
5. 输出材料清单与办理顺序，入口与截止节点逐项标来源与核验状态

| 场景 | 典型材料 | 入口 |
|---|---|---|
| 入住 | 录取 / 住宿凭证 | 公寓服务中心 |
| 报修 | 房号 + 设施描述 | 后勤报修入口 |
| 调宿 | 申请表 + 理由 | 学生工作处 |
| 退宿 / 离校 | 离校清单 + 钥匙 | 离校系统 |

**判据**：用户说「帮我提交 / 帮我退」时，需要实际提交则转 `portal-operator` 代操作，提交前复述操作内容与后果。

**登录判断**：先判事项在哪办——公寓服务中心与后勤的公开通知 公开可查，直接给；离校系统、调宿申请与缴费入口 需登录，转 `portal-operator`。需登录时按 `../using-qihang/SKILL.md` 共享行为准则第四条给出登录要求（**先给最快捷做法**：让用户用专用配置目录加 `--remote-debugging-port=0` 启动一次，登录一次即长期免登录，端口写入该目录的 `DevToolsActivePort`；用户本人用**自己的浏览器**登录，本包不代开浏览器、不代填凭证；要本包直接操作页面需带调试端口启动，用户确认已登录后本包才接入）；完整流程见 `../portal-operator/SKILL.md`。

**判定顺序**：先判是不是「代提交 / 代退办」请求（是则转 `portal-operator`，退宿等不可撤销操作先复述后果并确认）→ 再判场景（入住 / 报修 / 调宿 / 退宿离校）→ 最后才给材料与入口。

## 常见误判

- ❌ 把「帮我提交退宿」当咨询 → ✅ 转 `portal-operator` 代提交，提交前复述后果并确认
- ❌ 四类场景用同一套材料 → ✅ 入住、报修、调宿、退宿各自材料不同，先定场景
- ❌ 报修只报房号 → ✅ 房号之外要给设施描述，否则维修上门还得再跑一趟
- ❌ 调宿只交申请不写理由 → ✅ 调宿需申请表与理由，理由不写会被退回补
- ❌ 退宿忘带钥匙与离校清单 → ✅ 退宿按离校清单逐项核，钥匙要在最后一步交
- ❌ 入口与截止节点不标来源 → ✅ 入口、材料与时间节点逐项标来源，以官方通知为准
- ❌ 离校系统与调宿申请当公开入口给 → ✅ 需登录，先给出登录要求再转 `portal-operator`
