# 宿舍与离校

## Overview

按「材料 → 入口 → 周期」给路径；需要实际提交或缴费时转 `portal-operator` 代操作，涉及金额先复述再确认。

## When to Use

宿舍入住与调整、报修、一卡通、离校手续。**不适用**：其他校园事务 → `campus-desk`。

## 执行流程

1. 判定场景：入住 / 报修 / 调宿 / 退宿 / 离校
2. 列出该场景所需材料与办理地点
3. 给对应系统或窗口入口
4. 提示关键时间节点（退宿截止、离校清单）
5. 输出材料清单与办理顺序

| 场景 | 典型材料 | 入口 |
|---|---|---|
| 入住 | 录取 / 住宿凭证 | 公寓服务中心 |
| 报修 | 房号 + 设施描述 | 后勤报修入口 |
| 调宿 | 申请表 + 理由 | 学生工作处 |
| 退宿 / 离校 | 离校清单 + 钥匙 | 离校系统 |

**判据**：用户说「帮我提交 / 帮我退」时，需要实际提交则转 `portal-operator` 代操作，提交前复述操作内容与后果。

**判定顺序**：先判是不是「代提交 / 代退办」请求（是则转 `portal-operator`，退宿等不可撤销操作先复述后果并确认）→ 再判场景（入住 / 报修 / 调宿 / 退宿离校）→ 最后才给材料与入口。

## 常见误判

- ❌ 把「帮我提交退宿」当咨询 → ✅ 转 `portal-operator` 代提交，提交前复述后果并确认
- ❌ 四类场景用同一套材料 → ✅ 入住、报修、调宿、退宿各自材料不同，先定场景
- ❌ 报修只报房号 → ✅ 房号之外要给设施描述，否则维修上门还得再跑一趟
- ❌ 调宿只交申请不写理由 → ✅ 调宿需申请表与理由，理由不写会被退回补
- ❌ 退宿忘带钥匙与离校清单 → ✅ 退宿按离校清单逐项核，钥匙要在最后一步交
