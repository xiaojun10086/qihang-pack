# 文献精读笔记

## 执行前置

- 本文所有包内相对路径均以本 `SKILL.md` 所在目录为基准，不以用户当前工作目录（cwd）为基准。
- 执行任何业务步骤前，先完整读取并遵守 `../using-qihang/SKILL.md` 中的共享行为准则及安全兜底，再完整读取 `../../config.yaml`。这里只加载共享规则和配置，不重复总入口路由。
- 本会话已完整加载上述文件时可复用；必需文件不可读时，停止本包执行并说明缺失或不可读的文件，不猜测规则。

## Overview

精读的产出是可核验的笔记，不是摘要。每条引文都要给出可回溯的锚点。

## When to Use

精读单篇论文或专著、做文献矩阵、积累综述素材。**不适用**：检索与获取全文、综述方法框架 → `lit-fetch`；核验引文是否真实 → `citation-verify`；翻译或整段改写论文 → 只给改写方向与方法，不代写；笔记用于提交的作业 → 拒绝代写，只给骨架与自查清单（见 `assignment-plan` / `paper-outline`）。

## 执行流程

### 段落级精读

1. 先读摘要与结论，写下这篇文献的主张
2. 逐段三色标记：主张（蓝）/ 证据（绿）/ 疑点（红）
3. 抽出论证链：主张 ← 证据 ← 方法
4. 记下 2–3 个可追问的疑点和要查的引文
5. 用自己的话写 3 句摘要

**三色标记细则**：

| 颜色 | 标记对象 | 判定信号 |
|---|---|---|
| 蓝（主张） | 作者要你相信的结论 | 「we argue / 本文认为」 |
| 绿（证据） | 支撑主张的数据 / 实验 / 引用 | 出现图表、数字、引文编号 |
| 红（疑点） | 你不同意 / 没看懂 / 想查证处 | 样本小、缺对照、结论外推 |

**判定顺序**：先判对象是不是文献正文（论文、专著）——课堂录音、讲义一类材料改走 `lecture-to-notes` → 再判是整篇精读还是只拆某一节的论证 → 最后才逐段做三色标记并抽出论证链。

### 主题—方法—结论矩阵

1. 把研究问题拆成 2–4 个检索概念
2. 为每个概念出同义词与检索式（中英各一版）
3. 定纳入/排除标准
4. 建矩阵：主题 | 方法 | 样本 | 结论 | 局限
5. 每条引文标注来源与可核验锚点（DOI/页码）
6. 输出文献矩阵表

**纳排标准与整理矩阵**：

| 维度 | 必填 | 常见坑 |
|---|---|---|
| 检索式 | 库名 + 检索式 + 日期 | 只给关键词、不可复现 |
| 纳排 | 纳入 / 排除各列判据 | 只写「相关」无判据 |
| 主题—方法—结论 | 每条一行 | 结论抄摘要而非读全文 |

**判定顺序**：先判用户要的是「检索与获取全文」（→ `lit-fetch`）还是「已拿到全文的精读」→ 再定整理范围与纳排标准（检索式归 `lit-fetch`）→ 最后才逐条读并填整理矩阵。

## 常见误判

### 段落级精读

- ❌ 把「这节课讲了什么」当精读 → ✅ 课堂材料属讲义转笔记，精读只面向文献正文
- ❌ 只摘抄结论句 → ✅ 主张要配证据与出处，缺证据的主张归入疑点
- ❌ 三色标记做成全文高亮 → ✅ 只标主张、支撑证据与自己存疑处，其余留白
- ❌ 把「没看懂」直接写成质疑 → ✅ 先分「没看懂」与「不同意」，两者追问方向不同
- ❌ 用作者的话写摘要 → ✅ 摘要须用自己的话重述，抄原文等于没读

**用途边界**：本 skill 支持自用精读笔记与可核验的综述素材整理；若用于提交作业或论文，不代写提交成品。作业任务拆解与排期引导至 `assignment-plan`，论文结构与论证自查引导至 `paper-outline`；仅提供方法、结构与自查建议。

### 主题—方法—结论矩阵

- ❌ 把「直接打包全文」当综述整理 → ✅ 全文获取改走合法获取路径，地图不代替下载
- ❌ 先读再补检索式 → ✅ 检索式与纳排要先定，否则读的东西无法复现
- ❌ 纳排只写「相关」→ ✅ 纳入与排除各要列判据，只写相关等于没标准
- ❌ 结论抄摘要 → ✅ 结论要读全文得出，抄摘要会在综合时出错
- ❌ 引文不给锚点 → ✅ 每条给可核验锚点，无锚点的行标「待核验」

**纪律**：先定检索式与纳排，**再开始读**；每条引文给可核验锚点（DOI / 页码），无锚点的行标「待核验」。
