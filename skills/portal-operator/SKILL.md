# 校内平台代操作

## Overview

用户明确授权后，直接打开目标平台并执行操作，然后回报结果。本 skill 的默认动作是**做完**，不是「给用户一个链接让他自己去」。

只保留两条操作常识：涉及支付金额的操作先复述金额再确认；不把密码或凭证写入任何文件。

**纪律**：先判用户要的是路径还是结果——要路径转 `campus-desk`，要结果就在这里做完；再判操作可否撤销——可撤销的连做，不可撤销或涉及金额的先复述再确认；最后才判是否需要用户本人到场（验证码、人脸识别、线下签字）。

## When to Use

用户要求代为查询或代办校内平台上的事项，平台范围包括：

| 平台 | 入口 | 常见事项 |
|---|---|---|
| 统一身份认证 | https://sso.dlut.edu.cn/ | 登录各系统 |
| 综合信息门户 | https://portal.dlut.edu.cn/ | 通知、日程、一站式办事 |
| 综合教务系统 | http://jxgl.dlut.edu.cn/student/home | 课表、成绩、考试安排、培养方案、选课 |
| WebVPN | https://webvpn.dlut.edu.cn/ | 校外访问校内资源 |
| 图书馆 | 见 `references/dlut-official-sites.md` | 借阅、续借、文献 |
| 一卡通 | 见 `references/dlut-official-sites.md` | 余额、消费记录 |

**不适用**：用户只是问办理路径 → `campus-desk`；只是问培养方案怎么对照 → `course-select`；只是查公开信息 → `campus-search`。

## 执行流程

1. **确认授权范围**：用户要办的是哪件事、在哪个平台。用户已说清楚就直接开始，不再复述确认。
2. **打开平台**：用用户可见的本机浏览器打开目标入口，让用户能看到每一步在做什么。
3. **登录**：需要登录时，由用户本人完成身份认证，或使用用户已授权的会话。凭证只存在于浏览器会话中。
4. **执行操作**：按用户的要求查询或办理。可以连续完成多步，不必每步都停下来问。
5. **回报结果**：给出用户要的结论（课表、成绩、通知要点、办理结果），必要时附原文摘要。用户要截图就给截图。
6. **收尾**：告诉用户做了哪些操作、当前状态、还需要用户本人完成的部分（如线下签字、缴费）。

### 平台打不开或需要验证时

- 页面需要短信验证码、人脸识别等用户本人环节 → 停下来请用户完成，然后继续。
- 平台无法访问（校外网络、系统维护）→ 说明原因，给出替代路径（WebVPN、线下窗口、公开来源）。
- 用户要办的事超出授权范围 → 停下来说明，不擅自扩大。

### 操作前复述（仅以下两类需要）

| 类别 | 处理 |
|---|---|
| 涉及支付金额 | 复述金额与用途，用户确认后再继续 |
| 不可撤销操作（提交报名、退课、退宿申请等） | 复述操作内容与后果，用户确认后再提交 |

其余查询类操作直接执行。

## 常见误判

- ❌ 用户说「帮我查一下」却只回一个链接 → ✅ 用户的意图是让我去做，直接打开并执行
- ❌ 每做一步都停下来问一次 → ✅ 授权范围内连续做完，只在金额与不可撤销操作前确认
- ❌ 把用户名密码或验证码写进文件、日志或回复正文 → ✅ 凭证只留在浏览器会话里
- ❌ 登录不上就编一个成绩或课表 → ✅ 拿不到数据就明说拿不到，给替代路径
- ❌ 顺手把页面上的身份证号、银行卡、家庭信息读出来 → ✅ 只回用户问的那部分，其余不主动读取也不转述
- ❌ 用户只是问「在哪办」也去登录系统 → ✅ 问路径的走 `campus-desk`，不要多此一举
