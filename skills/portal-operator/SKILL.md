# 校内平台代操作

## 执行前置

- 本文所有包内相对路径均以本 `SKILL.md` 所在目录为基准，不以用户当前工作目录（cwd）为基准。
- 执行任何业务步骤前，先完整读取并遵守 `../using-qihang/SKILL.md` 中的共享行为准则及安全兜底，再完整读取 `../../config.yaml`。这里只加载共享规则和配置，不重复总入口路由。
- 本会话已完整加载上述文件时可复用；必需文件不可读时，停止本包执行并说明缺失或不可读的文件，不猜测规则。

## Overview

确需登录查询或实际代办、用户明确授权且站点限制允许后，接入用户**已登录的浏览器**，在目标平台上执行操作并回报结果。本 skill 的默认动作是**在许可范围内做完**；站点级隐私限制优先于「默认做完」，不能因用户授权而跳过限制。例如心理服务只给入口，既不登录读取预约内容，也不代替用户提交预约，其他系统中的心理记录同样不读取。

操作边界：执行前加载站点限制和字段表，只读取授权且允许的字段；涉及支付金额的操作先复述金额与用途再确认；不把密码或凭证写入任何文件，也不接收用户主动发来的密码 / 验证码 / Cookie（收到即提示撤回，改用用户本人在可见窗口登录）。

**流程只做一次提醒、一次确认**：① 提醒用户自己打开浏览器并登录（本 skill 不代开浏览器）；② 用户确认已登录后，直接接入并操作。

**纪律**：先判是否需要登录及用户是否明确授权——公开查询转 `campus-search`，办理材料或路径咨询转 `campus-desk`，都不登录；确需登录查询或实际代办且授权范围明确，才在站点限制允许范围内执行，权限未知时先问必要问题。再判操作可否撤销——可撤销的连做，不可撤销或涉及金额的先复述再确认；需要用户本人完成的环节（验证码、人脸识别、线下签字）停下来请用户处理。

## When to Use

用户要求代为查询或代办校内平台上的事项，平台范围包括：

入口配置读取 `../../config.yaml`，服务详情及限制读取 `../../references/dlut-login-sites.md` 与 `../../references/dlut-official-sites.md`；不得用硬编码地址覆盖配置，也不得自行拼接未登记入口。

| 平台 | 入口来源 | 常见事项 |
|---|---|---|
| 统一身份认证 | `../../config.yaml` 的 `school.entry_sso` | 登录各系统 |
| 综合信息门户 | `../../config.yaml` 的 `school.entry_portal` | 通知、日程、一站式办事 |
| 综合教务系统 | `../../config.yaml` 的 `school.entry_jwgl` | 课表、成绩、考试安排、培养方案完成情况、全校开课查询、选课 |
| WebVPN | `../../config.yaml` 的 `school.webvpn` | 用户明确要求的校外访问 |
| 图书馆 | `../../references/dlut-login-sites.md` 与 `../../references/dlut-official-sites.md` | 借阅、续借、文献，按具体服务区分 |
| 一卡通 | `../../references/dlut-login-sites.md` 与 `../../references/dlut-official-sites.md` | 余额、消费记录、卡内充值，按具体系统区分 |

**不适用**：用户只是问办理路径 → `campus-desk`；只是问培养方案怎么对照、或转专业所需的培养方案与学分要求 → `course-select`；只是查公开信息、电话或平台入口（不必登录）→ `campus-search`。

## 执行流程

1. **核对需求与授权**：先判断是否需要登录、是否属于实际代办，再核对用户明确授权的事项、平台和范围；不把「帮我查一下」「帮我办一下」等礼貌措辞单独当作授权。已有明确授权不反复确认，权限或范围未知时先问必要问题。公开查询或办理材料、路径咨询不登录，按前述边界转出。
2. **加载站点限制与字段表**：打开平台前，完整读取 `../../references/dlut-login-sites.md`、`../../references/dlut-official-sites.md` 与 `../../references/dlut-field-map.md`，核对目标登记、服务详情、可读字段及隐私限制；本会话已完整加载时可复用。目标为综合教务系统且涉及开课清单、培养方案完成情况或课表时，按 `../../references/dlut-field-map.md` 第四～七节的入口、取数流程与字段口径执行。任一必需文件不可读时停止本包执行并说明缺失或不可读的文件；目标未收录、所需入口配置缺失或限制无法确认时，不启动登录查询或代办，不猜测地址、权限或可读字段。给出校验路径：从配置中的 `school.official` 进入对口部门官网或办事指南核验，或请用户本人从门户内核验服务入口，再由维护者补齐登记与限制；无法读取配置时请用户恢复配置或提供官方材料。
3. **提醒用户打开浏览器并登录**（提醒①，只做一次）：仅在授权、登记与限制核对通过后，**提醒用户自己打开浏览器并登录**；本 skill 不代开浏览器。

   **为什么不代开**：由本 skill 启动的浏览器会被它拥有，命令中断或会话结束时会被一并终止，已登录的页面随之关闭、登录态丢失。登录必须发生在**用户自己的浏览器**里——那是外部进程，本 skill 接上去也不取得所有权，因此不会被连带关闭。

   提醒话术要点（把目标入口一并给用户）：

   - 请打开你自己的浏览器，进入目标入口，本人完成登录。入口读 `../../config.yaml`：教务 `school.entry_jwgl`、门户 `school.entry_portal`；需要认证时即 `school.entry_sso` 统一认证入口。
   - **最快捷方式**（要本 skill 直接操作页面时先给这一条，登录一次即可长期免登录）：让浏览器用**专用配置目录 + 自动端口**启动，复制即用，把 `<目标入口>` 换成实际入口：
     `msedge.exe --remote-debugging-port=0 --user-data-dir="%USERPROFILE%\.qihang\browser\edge" <目标入口>`
     Chrome 同形命令（`chrome.exe --remote-debugging-port=0 --user-data-dir="%USERPROFILE%\.qihang\browser\chrome" <目标入口>`）；macOS / Linux 用 `~/.qihang/browser/edge` 或 `~/.qihang/browser/chrome`。
   - `--remote-debugging-port=0` 让浏览器**自选空闲端口**，不会撞已占用端口；实际端口写在该配置目录下的 `DevToolsActivePort` 第一行，本 skill 据此接入。该文件缺失、或修改时间早于本次启动时刻，即视为无效，请用户重新启动。
   - **必须指定独立配置目录**：Chrome / Edge 136 起出于安全会**忽略默认用户配置目录上的调试端口**，直接对默认配置加 `--remote-debugging-port` 不会生效；独立目录也避开用户日常浏览器的单实例锁。登录态存在该目录，之后免登录，但须**正常关窗**（或由本 skill 优雅关闭）才会落盘 cookie，强制结束进程会丢登录态。
   - 用户**已有**带调试端口且已登录的实例时，按其端口直接接入（`--port <端口>`），不必重开。
   - 登录窗口必须**可见**，由用户本人在窗口内完成认证；不代填用户名、密码、验证码。
   - WebVPN 仅在用户明确要求校外访问时使用，从 WebVPN 门户资源卡进入，不手拼代理 URL；仅 APP 可办的环节由用户本人操作。

   提醒后**等用户回话**：不自行启动浏览器、不预先探测登录态、不重复追问。
4. **用户确认后接入并直接操作**：

   a. **接入**：得到用户「已打开并登录」的确认后，接入该浏览器——优先按专用配置目录下的 `DevToolsActivePort` 自动取端口，或用用户给出的端口接入（`--port <端口>`）。接入的浏览器保持**外部所有**，不会被本 skill 结束，用户的登录窗口不会被关掉。
   b. **直接操作**：接入成功后直接执行授权操作，不重开浏览器、不重新登录、不反复查询登录状态、不为了「确认」而重复导航；只读取授权且允许的字段。
   c. **接入失败时**：说明失败原因（通常是端口未开、端口被占用或浏览器未启动），给出具体的开启方式，请用户重开后确认；**不改为由本 skill 代开浏览器**，也不反复重试同一命令的不同变体。
   d. **页面需要短信验证码、人脸识别等本人环节** → 停下请用户在该窗口完成，不重复提交；平台要求重新认证时同理，等用户完成后继续。

   **登录态与凭证纪律**：是否已登录以用户确认为准，或仅以当次页面实际内容为准；同一任务只保留一个页面，不为测试连通性连续打开多个地址——重复导航会离开已登录页面并导致登录态失效。不主动保存或输出用户名、密码、验证码、Cookie、令牌等凭证，也**不接收用户主动发来的凭证**：收到即不复述、不写入、不转发，提示用户撤回，并请其在本 skill 打开的可见登录窗口内自行输入。先核对浏览器及工具的缓存、日志和 trace 设置，不宣称凭证或 trace 一定不会留存，无法满足所需隐私边界时不启动接入操作。
5. **执行操作**：只查询或办理授权且站点限制允许的事项，只读取必要字段；站点级隐私限制优先于「默认做完」。心理服务只给入口，既不读取预约内容也不代提交预约；成绩明细仅在用户明确要求时读取，校园邮箱默认不读正文。范围内可以连续完成多步，涉及金额或不可撤销操作仍须按下表先复述再确认。**改写禁令**：无论用户是否授权，都不修改、删除或伪造校内系统记录（成绩、学籍、缴费、考勤、评奖等），一律拒绝并只给正规申诉或更正渠道——用户授权不构成改写依据。
6. **回报结果**：给出用户要的结论（课表、成绩、通知要点、办理结果），必要时附原文摘要。用户要截图时，仅提供授权且站点限制允许的内容，不截取凭证或无关隐私。
7. **收尾**：告诉用户实际做了哪些操作、当前状态、未执行及还需要用户本人完成的部分（如线下签字、缴费），不得把提供入口说成已经代办完成。

### 平台打不开或需要验证时

- 页面需要短信验证码、人脸识别等用户本人环节 → 停下来请用户完成，然后继续。
- 平台无法访问（校外网络、系统维护）→ 说明原因，给出替代路径（WebVPN、线下窗口、公开来源）。
- 用户要办的事超出授权范围 → 停下来说明，不擅自扩大。
- 浏览器命令报错 → 先读取真实报错再定位原因，不连续重试同一条命令的不同变体；重试前先确认上一次操作是否已改变页面或登录状态。
- 用户把浏览器关了，或接入后页面消失 → 说明当前状态，请用户重新打开并登录后确认；不自行代开浏览器。
- 端口未监听、接入被拒 → 给出开启调试端口的命令示例（专用配置目录 + `--remote-debugging-port=0`），请用户重开后确认；不擅自改由本 skill 启动浏览器。

### 操作前复述（仅以下两类需要）

| 类别 | 处理 |
|---|---|
| 涉及支付金额 | 复述金额与用途，用户确认后再继续 |
| 不可撤销操作（提交报名、退课、退宿申请等） | 复述操作内容与后果，用户确认后再提交 |

其余查询类操作仅在授权明确、必需文件已加载且站点限制允许时直接执行；权限或范围未知时先问必要问题，受限内容不因确认而放行。

## 常见误判

- ❌ 仅凭「帮我查一下」就登录操作 → ✅ 先判断是否需要登录及是否有明确用户授权；公开查询或办理材料、路径咨询不登录，礼貌措辞不等于授权
- ❌ 每做一步都停下来问一次 → ✅ 已有明确授权且站点限制允许时连续做完；权限未知先问必要问题，金额与不可撤销操作仍须复述确认
- ❌ 把用户名密码或验证码写进文件、日志或回复正文 → ✅ 不主动保存或输出凭证，并核对浏览器及工具记录设置，不保证缓存、日志或 trace 绝不留存
- ❌ 用户把密码 / 验证码 / Cookie 贴进对话就照着用 → ✅ 不接收用户主动发来的凭证：不复述、不写入、不转发，提示撤回并请其本人在可见登录窗口输入
- ❌ 登录不上就编一个成绩或课表 → ✅ 拿不到数据就明说拿不到，给替代路径
- ❌ 顺手把页面上的身份证号、银行卡、家庭信息读出来 → ✅ 只回用户问的那部分，其余不主动读取也不转述
- ❌ 用户只是问「在哪办」也去登录系统 → ✅ 问路径的走 `campus-desk`，不要多此一举
- ❌ 为「验证连通性」连续打开多个地址，或反复轮询登录状态 → ✅ 同一任务只开一个页面；重复导航会离开已登录页并让登录态失效，是否已登录以用户确认为准
- ❌ 由本 skill 启动浏览器、再让用户在里面登录 → ✅ 登录必须用**用户自己的浏览器**；skill 启动的浏览器归 skill 所有，命令中断或会话结束会被一并终止，窗口一关登录就丢
- ❌ 用户已确认登录后还去探测、轮询登录状态 → ✅ 确认即视为已登录，直接接入并操作，不再查询
- ❌ 接入失败就改为由 skill 代开一个浏览器 → ✅ 说明端口开启方式，等用户重开后确认，不擅自代开
- ❌ 用户还没回话就自行打开浏览器 → ✅ 提醒后等用户确认，不抢跑、不预先探测登录态
- ❌ 认证成功后仍在中间页来回跳 → ✅ 认证完成直接进入目标页执行授权操作
- ❌ 命令失败就连续重试变体 → ✅ 先看真实报错再定位，未确认上一次操作结果前不重试
- ❌ 靠页面下拉筛选或自己拼 URL 参数取开课数据 → ✅ 下拉是历史分类、`selectize` 的值不进请求，一律在已登录页面内按接口分页取数，以返回字段为准
- ❌ 按标签页序号取目标页 → ✅ 标签页顺序会变动，按 URL 片段匹配；新开的 SPA 页初始 `title` / `url` 可能为空，不要判定为失败
- ❌ 取完数顺手结束浏览器进程 → ✅ 接入的浏览器归用户所有，只断开连接，不结束进程，否则登录态丢失
