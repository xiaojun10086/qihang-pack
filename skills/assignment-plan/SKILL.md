# 作业与小组任务拆解

## 执行前置

- 本文所有包内相对路径均以本 `SKILL.md` 所在目录为基准，不以用户当前工作目录（cwd）为基准。
- 执行任何业务步骤前，先完整读取并遵守 `../using-qihang/SKILL.md` 中的共享行为准则及安全兜底，再完整读取 `../../config.yaml`。这里只加载共享规则和配置，不重复总入口路由。
- 本会话已完整加载上述文件时可复用；必需文件不可读时，停止本包执行并说明缺失或不可读的文件，不猜测规则。

## Overview

先看交付要求与截止时间，再切成可启动的动作块；小组作业额外产出分工表与进度看板。

## When to Use

大作业、课程设计、小组作业的任务拆解与排期。**不适用**：代写代码或正文 → 拒绝并给自查清单（见 `code-mentor` / `lab-report`）。

## 执行流程

### 里程碑与排期

1. 读清评分标准与截止日，抽出交付物清单
2. 把交付物拆成 ≤8 个里程碑，每个标预计工时
3. 倒排到日，留出 20% 缓冲
4. 标出 3 类风险：依赖外部（他人/设备/数据）、易返工、易低估
5. 给出「今天能启动的最小一步」

**里程碑拆分**：需求确认 → 初稿 → 合稿 → 自查 → 提交，五点必排。

| 风险信号 | 应对 |
|---|---|
| 数据未采 | 前移采集里程碑 |
| 依赖他人 | 标外部依赖块 |

**判定顺序**：先判有没有「代写正文 / 代提交 / 数据未采却要先写」的请求（有则只给骨架与清单）→ 再判交付物与截止日是否明确（不明确先问）→ 最后才拆里程碑与排期。

### 小组分工与看板

1. 复述作业目标、交付物与截止时间
2. 拆成 4–8 个可独立认领的任务块
3. 给每块标工作量、前置依赖与负责人（留空待认领）
4. 排出里程碑（初稿 / 合稿 / 提交）与检查点
5. 生成周会纪要模板与进度看板列

**任务块拆分口径**：每块满足「一个人一周内可独立完成 + 有明确交付物」。

| 看板列 | 含义 |
|---|---|
| 待认领 | 拆好但无人负责 |
| 进行中 | 已认领 |
| 待合稿 | 单块完成，等并稿 |
| 已交付 | 通过检查点 |

**判据**：任一任务块的前置依赖为空且无负责人 → 标记为风险项，先解决。

**判定顺序**：先判是「多人协作」还是「一个人写」，后者改走个人拆解 → 再判交付物与截止日是否明确 → 最后才拆任务块并落看板列。

## 常见误判

### 里程碑与排期

- ❌ 数据还没采就排写作里程碑 → ✅ 采集必须前移到最早，否则后面全被它卡住
- ❌ 把「代写正文」当加急需求 → ✅ 只给骨架、自查清单与排期，正文不代劳
- ❌ 里程碑按周粗排 → ✅ 每个里程碑要能勾选完成，粗排到周等于没拆
- ❌ 不标外部依赖 → ✅ 依赖他人 / 设备 / 数据的里程碑必须单列并前置
- ❌ 缓冲堆在最后一周 → ✅ 缓冲要摊进每个里程碑，集中堆放等于没有

**纪律**：只拆解与排期；不代写正文、不编造数据。

### 小组分工与看板

- ❌ 把「我一个人写」当小组协作 → ✅ 单人作业改走个人拆解，看板列用不上
- ❌ 任务块拆到半天粒度 → ✅ 拆到「一人可独立完成且可勾选」即可，过细反而难维护
- ❌ 拆完不标负责人 → ✅ 无负责人的任务块要单列风险项，先解决再往下走
- ❌ 把「谁有空谁做」当分配 → ✅ 按交付物归属分配，否则合稿时无人认账
- ❌ 合稿阶段才发现接口对不上 → ✅ 前置依赖要在拆分时就单列并前置
