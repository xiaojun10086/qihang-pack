# 证明开具

## 执行前置

- 本文所有包内相对路径均以本 `SKILL.md` 所在目录为基准，不以用户当前工作目录（cwd）为基准。
- 执行任何业务步骤前，先完整读取并遵守 `../using-qihang/SKILL.md` 中的共享行为准则及安全兜底，再完整读取 `../../config.yaml`。这里只加载共享规则和配置，不重复总入口路由。
- 本会话已完整加载上述文件时可复用；必需文件不可读时，停止本包执行并说明缺失或不可读的文件，不猜测规则。

## Overview

给路径与材料清单，逐项标来源；线上可办的转 `portal-operator` 代提交，线下盖章必须本人到场。

## When to Use

在读证明、成绩单、学籍证明等各类证明的开具路径。**不适用**：其他校园事务 → `campus-desk`；宿舍、报修与离校 → `dorm-life`。

## 执行流程

1. 先判定证明类型（在学 / 成绩 / 学籍 / 党团 / 户籍 / 出国）与用途国别
2. 查 DUT 信息库锁定对口部门与办公地点
3. 列出材料清单（学生证 / 一寸照 / 申请表 / 用途说明）
4. 给出办理周期与是否可线上办
5. 逐项标来源与核验状态；信息库未收录时固定回复「未收录，建议访问 www.dlut.edu.cn 核实」

**证明 → 部门映射**：

| 证明 | 对口 | 入口（以 `../../references/dlut-official-sites.md` 登记为准） |
|---|---|---|
| 在学证明 | 学院 / 教务处（本科） | `https://teach.dlut.edu.cn/` |
| 成绩单 | 教务处（本科）/ 研究生院 | `https://teach.dlut.edu.cn/`、`https://gs.dlut.edu.cn/` |
| 学籍证明 | 教务处（本科）/ 研究生院 | `https://teach.dlut.edu.cn/`、`https://gs.dlut.edu.cn/` |
| 党团证明 | 学院党委 / 团委 | 学部学院导航 → 学院官网 |
| 户籍证明 | 保卫处 / 属地派出所 | `https://gach.dlut.edu.cn/` |
| 出国材料 | 教务处 / 研究生院 / 国际合作与交流处 | `https://teach.dlut.edu.cn/`、`https://gs.dlut.edu.cn/`、`https://dutdice.dlut.edu.cn/` |

> 科室电话见 `https://teach.dlut.edu.cn/bmjs/jgsz.htm`；上表入口未登记或已失效时，按「信息库未收录」回复并给官网核实入口。

**周期**：多数 1–3 个工作日，以部门答复为准。

**登录判断**：先判要查的字段在哪——部门办事指南与公开材料清单 公开可查，直接给；线上申请入口与成绩明细查询 需登录，转 `portal-operator`。需登录时按 `../using-qihang/SKILL.md` 共享行为准则第四条给出登录要求（**先给最快捷做法**：让用户用**独立配置目录**加 `--remote-debugging-port=0` 启动一次，登录一次即长期免登录，端口写入该目录的 `DevToolsActivePort`（**Chrome / Edge 136 起会忽略默认配置目录上的调试端口，必须用独立目录**，理由见共享行为准则第四条）；用户本人用**自己的浏览器**登录，本包不代开浏览器、不代填凭证；要本包直接操作页面需带调试端口启动，用户确认已登录后本包才接入）；完整流程见 `../portal-operator/SKILL.md`。

**判定顺序**：先判是不是「代办理 / 代提交」请求（线上可办的转 `portal-operator`；线下盖章必须本人到场）→ 再判证明类型与用途国别（决定要中文版还是英文版）→ 最后才给材料清单与周期。

## 常见误判

- ❌ 把「帮我去盖个章交过来」当加急代办 → ✅ 线下盖章必须本人到场；线上可办的转 `portal-operator` 代提交
- ❌ 不问用途国别就报份数 → ✅ 出国用途常需英文版，份数与语种由用途决定
- ❌ 把成绩证明当成绩查询 → ✅ 要成绩明细本身转 `portal-operator` 代查询，本 skill 只给证明办理路径
- ❌ 周期给一个确定天数 → ✅ 周期以部门答复为准，只给大致区间
- ❌ 信息库没收录就编一个部门 → ✅ 未收录时按固定口径引导去官网核实
- ❌ 对口部门与周期不标来源 → ✅ 部门、材料与周期逐项标来源与核验状态，便于用户复核
- ❌ 线上申请入口与成绩明细当公开信息给 → ✅ 需登录，先给出登录要求再转 `portal-operator` 代提交或代查询
