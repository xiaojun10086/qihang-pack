# 登录选择原则（Level 1 · login-policy）

> 1 级 skill 库的第 5 份规则文件。
> 适用的核心场景：**回答需要站内数据时，是否请用户登录 —— 由用户决定，不由包决定。工具不会读取登录后的页面内容。**

---

## 1. 一句话原则

> **能不打扰就不打扰；确有必要才请求登录；请求时把选择权与风险一并交给用户。**

---

## 2. 三档判定（回答前先自查）

对每个请求，先判定属于哪一档：

| 档 | 判定条件 | 动作 |
|---|---|---|
| **A · 不登录即可答** | 答案来自**公开站**（学校/学院官网、新闻、信息公开、招生章程、图书馆首页、教务处通知） | **直接回答**，不提示登录 |
| **B · 登录后更完整** | 公开站能答**一部分**，个人页面可供用户自行核实更具体的信息 | **先给不登录版本**，再告知可在本机浏览器自行查看；工具不读取页面，是否分享由用户决定 |
| **C · 必须登录才能答** | 答案**只**存在于登录后（个人课表、成绩、借阅、余额、办事进度） | **说明限制**：工具不能代读登录页面；可打开本机浏览器供用户查看，也可只给通用流程 |

**红线**：**不得**为了「输出更全面」而在 A/B 档强行索要登录。

---

## 3. 请求登录时的标准话术

**必须包含 4 个要素**（缺一不可）：

```
① 为什么需要  —— 「你要的是**你自己的**课表，这个只有登录后才能看到」
② 我怎么做    —— 「我可以打开一个**独立本机浏览器窗口**，由你自行登录和查看」
③ 安全保障    —— 「工具不读取或输出网页内容、不代操作；本次 Profile 用后删除」
④ 选择权      —— 「你可以不登录，只看通用流程；是否在聊天中分享必要信息由你决定」
```

**替代表达**（用户不想登录时）：
> 「那我只给**通用流程**（去哪办、带什么、找谁）；个人信息请你在对应系统自行查看，是否分享必要字段由你决定。」
> —— **绝不因为用户拒绝登录就摆烂**，仍给完整可用的一般性答案。

---

## 4. 登录态接入（方案 A）的操作规范

```
0) 为本次请求创建随机会话与一次性 Profile；绝不复用用户真实浏览器或其他 agent-browser 会话
1) 有头模式打开目标站（--headed），让用户看得见
2) 提示用户「请在这个窗口里自行登录」—— 编排器不接触、不代填任何凭证
3) 用户在浏览器中自行查看请求所需信息；工具不读取、复制或输出网页内容
4) 用户可选择只向助手提供回答所需的最少信息；不得要求密码、验证码或无关敏感数据
5) 只关闭本次随机会话，并删除一次性 Profile；失败须明确报错，不得静默继续
```

### 安全保障（对用户承诺）

| 保证 | 落实方式 |
|---|---|
| **只读** | 不点提交、不选课、不缴费、不改密码、不改个人信息 |
| **不外传** | 工具不采集网页内容、不打印页面快照、不发第三方；用户自行决定是否在聊天中提供必要字段 |
| **不落盘** | 浏览器使用一次性 Profile；正常退出时清理该目录，不保存页面原文或 Cookie |
| **可中止** | 用户说「停止」→ 立即关闭本次随机命名的会话 |
| **隔离** | 随机命名的独立会话 + 一次性 Profile；不会关闭其他浏览器会话 |
| **可清理** | 每次使用后自动删除临时 Profile；异常退出后若仍有残留，用户可删除 `~/.qihang/browser-profile.*` 中对应目录 |

### L3 禁读（无论用户是否登录，一律不读）

缴费金额 / 银行卡 / 身份证 / 家庭信息 / 邮件正文 / 心理记录 / 成绩明细

### 裸词澄清

以下词**单独出现**时，**不得直接判 L1 或 L3**，必须**先让用户区分**：

| 裸词 | 可能的 L1 | 可能的 L3 | 处理 |
|---|---|---|---|
| **成绩** | 成绩等级 / 是否通过 | 成绩明细（单科分数、绩点计算） | **先问一句**：「你要的是等级 / 是否通过，还是单科分数明细？」 |
| **消费 / 花费** | 一卡通余额 | 消费金额与流水明细 | 同上 |

> **依据**：`config.yaml` 的 `L1_auto` 含「成绩等级」、`L3_forbidden` 含「成绩明细」——
> **裸「成绩」两者都不是**，必须先澄清才可打开对应页面供用户查看。
> `scripts/dlut-read.sh` 对裸「成绩」返回 `rc=1`（要求区分），与本节点一致。
> **红线优先不适用**：这里不是拦，是**要求区分**；区分后才能判级。
> **与「C 档登录告知」的先后**：**同一条回复里先区分等级/明细，再给 C 档登录四要素说明**；
> 不要先抛登录流程（用户还没说清要哪种，登录也可能白做）。

---

## 5. 「尽可能全面输出」的正确做法

**不是**「尽可能多登录、多抓数据」，而是：

| 做法 | 说明 |
|---|---|
| **公开优先** | 先用公开站把能给的说满（信息库 142 条条目覆盖大量问题） |
| **一次说清** | 需要用户登录时说明站点、查看目的和限制，避免反复打扰 |
| **分步自查** | 需要访问多个站时列出入口与路径供用户核对；脚本不自动遍历或读取多个站点 |
| **元信息沉淀** | 只把经公开来源核实的栏目结构/入口位置写进包，**不写用户个人数据** |
| **边界清晰** | 提供交易类栏目入口 = 告诉你入口在哪；**≠ 可以代你操作或读取交易数据** |

---

## 6. 与其他规则的关系

```
先判红线（redline） → 再判登录档位（本文件 A/B/C） → 再判澄清门（clarity） → 锁域
```

- 红线优先：命中红线时**不追问、也不请求登录**，直接拒绝并给合规替代（追问口径见 `library/clarity.md` §7）
- 登录档位优先于澄清门：C 档时先说清「要登录」，避免用户白答一堆问题
- **两套坐标不是一回事**：
  - **方案 A/B/C** = **动作方式**（是否登录、怎么读）—— 本文件；
  - **L1/L2/L3** = **数据级别**（读到什么程度）—— `config.yaml` 的 `level_rules`。
  - 二者**并行、不换算**，输出时应**同时给出**。例：「帮我交网费」→ 动作档 **C**（只给入口、不代操作）
    ＋ 数据级别 **L3**（涉金额，禁读）。
  - **L3 命中按红线处理**（不再走澄清门），与本节第一条一致。
