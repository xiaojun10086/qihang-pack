# 登录选择原则（Level 1 · login-policy）

> 1 级 skill 库的第 5 份规则文件。
> 适用的核心场景：**回答需要站内数据时，是否请用户登录 —— 由用户决定，不由包决定。**

---

## 1. 一句话原则

> **能不打扰就不打扰；确有必要才请求登录；请求时把选择权与风险一并交给用户。**

---

## 2. 三档判定（回答前先自查）

对每个请求，先判定属于哪一档：

| 档 | 判定条件 | 动作 |
|---|---|---|
| **A · 不登录即可答** | 答案来自**公开站**（学校/学院官网、新闻、信息公开、招生章程、图书馆首页、教务处通知） | **直接回答**，不提示登录 |
| **B · 登录后更完整** | 公开站能答**一部分**，站内数据能让答案**更准**（如：公告能答大概时间，站内能答你的具体课表） | **先给不登录版本的答案**，再**一句话**告知「想更准的话可以登录 X 查」，**不强制** |
| **C · 必须登录才能答** | 答案**只**存在于登录后（个人课表、成绩、借阅、余额、办事进度） | **明确请求登录**，并说明「不登录我只能给通用流程，无法给到你的具体情况」 |

**红线**：**不得**为了「输出更全面」而在 A/B 档强行索要登录。

---

## 3. 请求登录时的标准话术

**必须包含 4 个要素**（缺一不可）：

```
① 为什么需要  —— 「你要的是**你自己的**课表，这个只有登录后才能看到」
② 我怎么做    —— 「我会用一个**独立浏览器窗口**打开，你在里面登录」
③ 安全保障    —— 「我只读、不落盘、不代操作、用完立刻关闭；你的登录态不会进我的任何文件」
④ 选择权      —— 「你也可以选择不登录，我就只给通用流程 —— 由你决定」
```

**替代表达**（用户不想登录时）：
> 「那我只给**通用流程**（去哪办、带什么、找谁），具体到你个人的信息需要你自己在 `XXX` 查看。」
> —— **绝不因为用户拒绝登录就摆烂**，仍给完整可用的一般性答案。

---

## 4. 登录态接入（方案 A）的操作规范

```
0) ★ 独立 Profile：--profile "$HOME/.qihang/browser-profile"
      （绝不复用用户真实浏览器 profile —— 否则会连带继承其他所有站点登录态）
1) 有头模式打开目标站（--headed），让用户看得见
2) 提示用户「请在这个窗口里自行登录」—— 编排器不接触、不代填任何凭证
3) 用户确认后，只读读取当前页面
4) 只抽所需字段用于当次回答
5) close --all 关闭会话；不保存页面、不导出 Cookie
```

### 安全保障（对用户承诺）

| 保证 | 落实方式 |
|---|---|
| **只读** | 不点提交、不选课、不缴费、不改密码、不改个人信息 |
| **不外传** | 读取内容只服务当次回答，不写文件、不发第三方 |
| **不落盘** | 不保存页面原文；只沉淀「栏目结构」这类元信息 |
| **可中止** | 用户说「停止」→ 立即 `close --all` |
| **隔离** | 独立 Profile；可核验「真实浏览器未被触碰」（比对 Cookies 时间戳） |
| **可清理** | 用户可随时删除 `~/.qihang/browser-profile` |

### L3 禁读（无论用户是否登录，一律不读）

缴费金额 / 银行卡 / 身份证 / 家庭信息 / 邮件正文 / 心理记录 / 成绩明细

---

## 5. 「尽可能全面输出」的正确做法

**不是**「尽可能多登录、多抓数据」，而是：

| 做法 | 说明 |
|---|---|
| **公开优先** | 先用公开站把能给的说满（信息库 160 条覆盖大量问题） |
| **一次问清** | 需要登录时**一次说明白**要查哪些，避免反复弹窗 |
| **批量读取** | 用户同意后，同一会话**依次**读取多个站（复用 SSO），而不是反复请求 |
| **元信息沉淀** | 只把「栏目结构/入口位置」写进包，**不写用户个人数据** |
| **边界清晰** | 记录交易类栏目 = 告诉你入口在哪；**≠ 可以代你操作** |

---

## 6. 与其他规则的关系

```
先判红线（redline） → 再判登录档位（本文件 A/B/C） → 再判澄清门（clarity） → 锁域
```

- 红线优先：命中红线时**不追问、也不请求登录**，直接拒绝并给合规替代
- 登录档位优先于澄清门：C 档时先说清「要登录」，避免用户白答一堆问题
