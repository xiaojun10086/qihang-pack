## 0. 三条铁律与快通道

### 0.1 三条铁律

1. **只讲结果与建议** —— 用户要看到的是「我得到了什么 + 建议怎么做」，
   **不是**「我怎么想的、我绕了几步」。中间推理一律折叠，不进输出。
2. **不暴露内部实现** —— 输出里**不得出现** skill 名、域代号、脚本名、库文件名、内部流程词
   （完整词表见 §1.2）。用户不需要知道这些，写出来只是噪音。
3. **结论前置、一次一步** —— 第一行就是答案；末尾**只给 1 个**下一步动作。

### 0.2 快通道（默认走这条，别绕远路）

| # | 一步 | 判定 | 动作 |
|---|---|---|---|
| 1 | **判红线** | 命中任一红线 | 直接走**红线变体**（拒绝 + 替代方案），**不追问、不展开** |
| 2 | **看槽位** | 关键槽 `O/T/D` 齐全且不歧义 | **直接作答**，不必走完整澄清门 |
| 3 | **择一路径** | 命中域 → 选该域**最贴合的一个**库内 skill；无对口 → 走 `library/general-fallback.md` | 只选一个，不并列 |
| 4 | **一次成稿** | 按 §1 模板一次写完 | 交付前过 `output-checklist.md` 7 项；**不在输出里写推理过程** |

> 口诀：**先判红线 → 看槽位 → 择一路径 → 一次成稿。**

## 1. 统一模板

```
【结论】  一句话可执行答案（必出、前置）
【依据】  ≤ 2 条 · 只写**外部可见来源**：材料页码 / 官方页面 / 规范条文 / 已核验入口
【结果】  ≤ 4 条 · 本次交付的实质内容（可带 ①②③ 子项，单条 ≤ 40 字）
          末条可用「→ 产出：…」说明落点（文件 / 卡组 / 日程 / 网址）
【建议】  ≤ 2 条 · 面向用户的可执行建议 / 注意事项
【下一步】恰好 1 个动作（唯一、可直接做）
【假设】  出现条件：① 3 轮未澄清仍推进，或 ② 依 `clarity.md` §5 例外 **3 / 5 / 6** 直接推进、
          且**代替用户补齐了对象或产出**时
          ⚠️ **`clarity.md` §3.1 需求确定门的「复述档」不计入本字段** —— 复述并入【结论】首行的前置短句；
          本字段只表示「**代替用户补齐了对象或产出**」，两者不要混用。
```

### 1.1 字段说明（写什么 / 禁什么）

| 字段 | 写什么 | 禁止 |
|---|---|---|
| 【结论】 | 一句**可直接执行**的答案 | 铺垫、背景、复述问题 |
| 【依据】 | **外部可核验**的来源：材料页码 / 官方页面 / 规范条文 / 已核验入口 / 合规边界 | 技能名、域代号、脚本名、库文件名、内部流程词（见 §1.2） |
| 【结果】 | 本次**真正给到**的内容；可分层（①②③），比「我做了哪几步」更完整 | 空话、只重复【结论】 |
| 【建议】 | 可选做法、注意事项、风险提示、合规替代方案 | 制造选择瘫痪（> 2 条并列选项） |
| 【下一步】 | **唯一**、可直接做的动作 | 多个候选；写内部名 |
| 【假设】 | 代替用户补齐的对象 / 产出，及补齐理由 | 没补齐却写假设 |

### 1.2 内部名禁止词表（固化 · 由校验器断言）

**输出块内不得出现**下列任一词：

| 类别 | 词表 |
|---|---|
| **域代号** | `S1`–`S6`、`F1`–`F8`、`R1`–`R6`（作为**独立词**出现即违规） |
| **库内 skill 名** | 92 个库内 skill 的 kebab-case 名（如 `campus-search`、`explain-stepwise`） |
| **脚本 / 库文件名** | `output-spec`、`output-checklist`、`general-fallback`、`domain-review`、`domain-review-cases`、`login-policy`、`clarity`、`memory`、`_registry`、`_domain`、`SKILL`、`config.yaml`、`dlut-read.sh`、`qihang.sh`、`selfcheck.sh`、`audit.sh`、`regress.sh`、`aligncheck.py`、`runcheck.py` |
| **内部流程词** | `库内 skill`、`库外通道`、`库外`、`域审查`、`需求明确`、`归属域`、`降级承接`、`红线` |

**两条判定细则（防误伤 / 防漏判）**：

- **交付物路径不算泄漏** —— `→ 产出：submit/ai-disclosure.md` 里的 `ai-disclosure` 是**文件名**，用户读到的是「产出了哪个文件」，属合规；同理 URL 路径段不算。校验器在读词表前先屏蔽路径与 URL。
- **`README` 不入表** —— 它既是库内文件名，也是学生自己要产出的交付物名（如 `env/requirements.txt+README`），入表会误伤合规输出。

> **本表是三处校验器的唯一真相源**：`scripts/runcheck.py`（`internal_leaks()`）、
> `scripts/aligncheck.py`（T 组 + O6）、`scripts/regress.sh`（`[7]` 段）。改本表必须三处同步。


**降级标注只写能力级**：允许 `[已降级]` 标签，冒号后只能写**能力描述**——

- ❌ `[已降级: campus-search → org-lookup]` ✗（含 skill 名）

### 1.3 「要点」计数口径（消除歧义）

**「≤ 6 条」= 除【结论】外的字段行数**：

| 字段 | 是否计入 |
|---|---|
| 【结论】 | ❌ 不计（必出） |
| 【依据】【结果】【建议】【下一步】【假设】 | ✅ 各计 1 条 |
| 【结果】内部的子项（① ② ③） | ❌ 不计（属同一条） |
| 域变体字段（校情的【网址】【状态】） | ✅ 各计 1 条 |

**标准输出 = 4 条**（依据 + 结果 + 建议 + 下一步；缺省无【假设】）。上限 6 条 → 仍有 **2 条余量**。

> **例外 2（关键槽齐全）不产生【假设】** —— 缺口都在 `W/C/B`，属本节的**缺省情形**，
> 末尾不必声明假设。判定依据是「是否**代替用户补了对象或产出**」，不是「是否跳过了追问」。

## 2. 变体

**校情查询**
```
【结论】+【网址】+【状态 ✅/⚠️】+【建议】     → 4 条
```
> 【建议】在本变体里承载「备注」作用（部门 / 用途 / 时效提示），只写公开可见的说明，
> **不写**内部名与核验流程术语。**硬契约**：凡校情变体，必须同时出现【网址】与【状态】，
> 否则视为普通输出（须有【结果】）。

**比较型校情**（如「A 学院 vs B 学部 哪个好」）
```
【结论】(客观并列 + 不评判) +【结果】(现状 A / 现状 B 各 1 条) +【下一步】   → 3 条
```
> **不做「哪个好」的排序判断**（替用户做选择＝越界）；如需选择建议，只给**决策维度清单**让用户自选。

**跨域串联**
```
【结论】+【结果】(各条结论并列，**条内不标域名**) +【下一步】   → 3 条
理论上限 = 结果 4 条；实际硬上限 = **4 条结论**
```
> **口径统一**：跨域时**不按域分节、不标域名**，把各域结论收敛成【结果】的多条子项。
> 结果 4 条 + 下一步 1 条 = 5 条 ✅；超过 4 条须压缩——把最弱的 1 条并入【下一步】。

> **红线优先**：命中红线时**取消跨域串联** —— 只输出红线变体（拒绝 + 替代方案），要点 ≤6 条；
> 不因为「涉及多个域」就把其他域的结论也塞进来。
> **混合请求**（同一句话里既含红线请求、又含合规请求，如「帮我把作业写了，再讲讲这道题」）**不得整体沉默**：
> 红线部分走红线变体拒绝，**合规部分另起一条独立结论照常给**（要点合计仍 ≤6）。

**降级**（触发条件见 §2.1）
在输出**首行**加：`[已降级] 由「原能力」改为「备能力」`

- **唯一口径**：`原能力 / 备能力` 一律写**能力级描述**，不得写 skill 名与域代号（见 §1.2）。
- 各库内 skill「失败与降级」段里的内部箭头写法仅供维护者阅读，**落盘输出时一律转写为能力级标签**。
- `备能力 = 通用建议` 的成文规则见 `library/general-fallback.md` §3；**命中 0 个域**时走同文件 §2 **六步通用框架**，
  且**零 skill 命中也要给【结论】与【下一步】**。

**追问**
```
【还需确认】① … ② … ③ …（≤3 问，按 时间>对象>产出>约束>背景>任务 排序）

> **追问变体的硬约束**：**首节必须是【还需确认】**，且**不得同时出现【结论】** ——
> 澄清门判「追问」时**不产出结论**（先问清再答）；若已有可先给的信息，放进【依据】，不要另起【结论】。
```

**通用知识型例外**（`clarity.md` §5 例外 6）
走正常模板输出（**不产生【假设】**），**末尾固定加一句**：`如需针对你的具体情况，告诉我 {缺的槽位}`

**红线拒绝**
```
【结论】明确说明不能做什么
【依据】合规边界（写规则，不写域代号）
【替代方案】给出合规的替代做法（给结构、给路径、给规范）
【下一步】1 个合规动作
```
→ 兜底原则：**拒绝必须给出路**，不做「只说不做」的拒绝。

### 2.1 降级触发条件（可判定）

满足**任一**即触发降级：
- 安装失败 / 探测不到该 skill
- 该 skill 需要 API Key 或联网，而当前环境不可用
- **输入材料缺失**（如「没讲义、没录音」却要求出笔记）→ 降级为「先补材料」或改锁
- 平台不兼容（如二进制仅 macOS）
- 库内 skill 步骤不足以覆盖本次需求

## 3. 简略四原则

1. 能一句话不写一段
2. 能列表不写散文
3. **过程细节默认折叠，不刷屏**（推理、检索过程、尝试过的路径都不进输出）
4. 每次只给**一个**下一步动作（避免选择瘫痪）

## 4. 交付前校验（强制）

逐项过 `output-checklist.md`：**7 项通用硬校验 + 域专属附加校验**。
**任一项不过 → 重新生成，不得交付。**

## 5. 输出后动作

把「薄弱点 / 错因 / 进度 / 上次结论」写入学习档案。

**禁止写入的域与内容**（与 `library/memory.md` §4 **同源**，两处必须同时增删）：
- **F3 身心与社交**、**F5 健康与运动** —— **整域不写**（会话结束即丢弃）
- **F4 财务与安全** —— 金额明细、债务、账户与凭证（**排除后可写其余**）
- **F6 军训与志愿** —— 伤病记录（**排除后可写其余**）
- **第三方隐私**（他人健康 / 财务 / 心理）
- **账号凭证**（身份证 / 银行卡 / 各类账号口令）
- 私密站原始页面内容

## 7. 合规正面清单

> 红线只写「不能做什么」会导致误拦合规请求。以下为**明确放行**的请求类型。

| 请求 | 是否合规 | 依据 |
|---|---|---|
| 「给我完整解法，我自己对着学」 | ✅ 放行（**限 S1/S4 单题**） | 自学场景；S5 论文/R1 引文不适用，仍按红线处理 |
| 「我的报告结构搭得对吗」 | ✅ 放行 | 自查合规；红线只禁「代写正文」 |
| 「PPT 帮我搭个框架」 | ✅ 放行 | 结构合规；正文内容仍须本人写 |
| 「帮我核验这 5 条引文字段是否自洽」 | ✅ 放行 | 核验≠补全；红线只禁「未核验的引文」 |
| 「帮我看看效应量怎么算」 | ✅ 放行 | 统计方法咨询合规；红线只禁「造假与选择性报告」 |
| 「帮我逐条回复返修意见」 | ✅ 放行 | 返修辅助合规；红线只禁「代投稿」 |
| 「帮我改简历措辞」 | ✅ 放行 | 措辞优化合规；红线只禁「编造经历」 |
| 「网费还剩多少」 | ✅ 放行（L1） | L1 可读；只有「缴费金额明细」属 L3 |
| 「历年真题在教务处哪里下」 | ✅ 放行 | 公开资料路径；红线只禁「买卖答案」 |
| 「排这周复习时间表」 | ✅ 放行 | 时间安排≠学业规划代劳 |
| 「最近老失眠」（无危机信号） | ✅ 放行于 **F2 作息与专注** | 红线只在**出现危机信号**时升级为 F3；按 `domains/_registry.md` 消歧表，**一般失眠 / 作息紊乱 → F2**，不逢情绪就转心理 |
| 「我这份个人陈述的措辞能不能再顺一点」（基于本人真实材料） | ✅ 放行 | 措辞 / 结构优化合规；红线只禁「代写文书正文 / 虚构经历」 |
| 「GB/T 7714 的期刊条目怎么排」 | ✅ 放行 | 通用规范咨询；无需个人数据即可完整作答（`clarity.md` §5 例外 6） |

**判定口诀**：**给路径 / 给结构 / 给规范 → 放行；代产出 / 代操作 / 造数据 → 拦截。**

## 链接呈现规范（2026-10-03 新增 · 依据字段专用）

> 触发原因：实测「给依据时的链接进不去」。**根因是排版** —— URL 紧贴中文说明时，
> 渲染器会把中文一并算进链接地址，点开即 404。以下三条**必须遵守**：

1. **URL 必须独占边界**：URL 前后一律留**空格**，不得紧贴中文或中文标点。
   - ✅ `依据：https://ecard.dlut.edu.cn/ （余额与流水）`
   - ❌ 写完 URL 直接把中文说明接上、中间不留空格 —— 渲染器会把说明一起算进链接地址
2. **必须标注访问条件**：需登录标 `需登录`；只支持 http 的标 `仅 HTTP`（勿手动改 https）；
   仅校园网的标 `仅校园网（走 WebVPN）`。**不得把受限入口写成"可直接打开"**。
3. **打不开时给排查路径，不给替代链接**：按 `references/dlut-official-sites.md` §0.1 的四步排查回复；
