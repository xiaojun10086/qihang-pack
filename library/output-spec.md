# 输出规范（Level 1 · output-spec）

> 所有 3 级 skill 的输出都必须走本模板，并过 `output-checklist.md` 校验。

## 1. 统一模板

```
【结论】  一句话可执行答案
【依据】  ≤ 2 条（来自哪个 skill / 哪份材料 / 信息库哪一节）
【步骤】  ≤ 5 条编号动作，每条 ≤ 15 字
【产物】  文件 / 卡组 / 日程 / 网址的落点
【下一步】只给 1 个动作
【假设】  出现条件：① 3 轮未澄清仍推进，或 ② 依 `clarity.md` §5 例外 **3 / 5 / 6** 直接推进、
          且**代替用户补齐了对象或产出**时
```

### 1.1 「要点」计数口径（消除歧义）

**「≤ 6 条」= 除【结论】外的字段行数**：

| 字段 | 是否计入 |
|---|---|
| 【结论】 | ❌ 不计（必出） |
| 【依据】【步骤】【产物】【下一步】【假设】 | ✅ 各计 1 条 |
| 【步骤】内部的子项（① ② ③） | ❌ 不计（属同一条） |
| 域变体字段（校情的【网址】【状态】） | ✅ 各计 1 条 |

**标准输出 = 4 条**（依据 + 步骤 + 产物 + 下一步；缺省无【假设】）。上限 6 条 → 仍有 **2 条余量**。

> **例外 2（关键槽齐全）不产生【假设】** —— 缺口都在 `W/C/B`，属本节的**缺省情形**，
> 末尾不必声明假设。判定依据是「是否**代替用户补了对象或产出**」，不是「是否跳过了追问」。

## 2. 变体

**校情查询**
```
【结论】+【网址】+【状态 ✅/⚠️】+【备注】     → 4 条
```

**比较型校情**（如「A 学院 vs B 学部 哪个好」）
```
【结论】(客观并列 + 不评判) +【现状 A】+【现状 B】+【网址】   → 4 条
```
> **不做「哪个好」的排序判断**（替用户做选择＝越界）；如需选择建议，只给**决策维度清单**让用户自选。

**跨域串联**
```
每个域给 1 条结论（计入要点数）→ 末尾 1 张行动清单
理论天花板 = 域数 + 1 ≤ 6（数学上等于 5 域）；但**实际硬上限 = 4 域**（理由见下）
```
> **口径统一**：跨域时**各域结论计入要点数**（每个域 1 条），行动清单另计 1 条。
> 于是 **域数 + 1 ≤ 5**（把 1 条余量留给【假设】或【红线】）→ **域数上限 = 4**。
> 4 域 + 清单 = 5 条 ✅；**5 域须压缩**：把最弱的 1 条结论并入行动清单。

> **红线优先**：命中红线时**取消跨域串联** —— 只输出红线变体（拒绝 + 合规替代），要点 ≤6 条；不因为「涉及多个域」就把其他域的结论也塞进来。
> **混合请求**（同一句话里既含红线请求、又含合规请求，如「帮我把作业写了，再讲讲这道题」）**不得整体沉默**：
> 红线部分走红线变体拒绝，**合规部分另起一条独立结论照常给**（要点合计仍 ≤6）。

**降级**（触发条件见 §2.1）
在输出**首行**加：`[已降级: 原 → 备]`

- **唯一口径**：`原` = 原需求或原 skill，`备` = 实际执行方式（备用 skill / 域通用框架）。
  20 个域的库内 skill 与 `output-checklist.md` §一第 6 项（降级标注）均用此写法，不再出现别名。
- 各库内 skill「失败与降级」段的 `[已降级]` 是**简写**，落盘输出时一律展开为上述完整形式。
- `备 = 域通用框架` 的成文规则见 `library/general-fallback.md` §3；**命中 0 个域**时走同文件 §2 **六步通用框架**，且**零 skill 命中也要给【结论】与【下一步】**。

**追问**
```
【还需确认】① … ② … ③ …（≤3 问，按 时间>对象>产出>约束>背景>任务 排序）
```

**通用知识型例外**（`clarity.md` §5 例外 6）
走正常模板输出（**不产生【假设】**），**末尾固定加一句**：`如需针对你的具体情况，告诉我 {缺的槽位}`

**红线拒绝**
```
【结论】明确说明不能做什么
【依据】域边界 / 红线条款
【可替代】给出合规的替代做法（给结构、给路径、给规范）
【下一步】1 个合规动作
【红线】复述红线条款
```
→ 兜底原则：**拒绝必须给出路**，不做「只说不做」的拒绝。

### 2.1 降级触发条件（新增，可判定）

满足**任一**即触发降级：
- 安装失败 / 探测不到该 skill
- 该 skill 需要 API Key 或联网，而当前环境不可用
- **输入材料缺失**（如「没讲义、没录音」却要求出笔记）→ 降级为「先补材料」或改锁
- 平台不兼容（如二进制仅 macOS）
- 库内 skill 步骤不足以覆盖本次需求

## 3. 简略四原则

1. 能一句话不写一段
2. 能列表不写散文
3. 过程细节默认折叠，不刷屏
4. 每次只给**一个**下一步动作（避免选择瘫痪）

## 4. 交付前校验（强制）

逐项过 `output-checklist.md`：**7 项通用硬校验 + 域专属附加校验**。
**任一项不过 → 重新生成，不得交付。**

## 5. 输出后动作

把「薄弱点 / 错因 / 进度 / 上次结论」写入学习档案。

**禁止写入的域与内容**（与 `library/memory.md` §4 **同源**，两处必须同时增删）：
- **F3 身心与社交**、**F5 健康与运动** —— **整域不写**（会话结束即丢弃）
- **F4 财务与安全** —— 金额明细、债务、账户与凭证（**排除后可写其余**）
- **F6 军训与志愿** —— 伤病记录（**排除后可写其余**）
- **第三方隐私**（他人健康 / 财务 / 心理）
- **账号凭证**（身份证 / 银行卡 / 各类账号口令）
- 私密站原始页面内容

## 6. 反例（不合格输出）

| 不合格输出 | 违反项 |
|---|---|
| 列了 12 条要点 | 校验 1 |
| 先铺垫三段才给结论 | 校验 2 |
| 「先做 A，也可以做 B，或者 C」 | 校验 3 |
| 给出信息库没有的 dlut.edu.cn 网址 | 校验 5 |
| 对 F3 用户说「你这是典型焦虑症」 | 校验 7 |
| 【依据】写了 3 条，且未写明来自哪个 skill / 材料 / 信息库哪节 | 校验 4 |
| 已发生降级，但首行没有 `[已降级: 原 → 备]` | 校验 6 |
| 拒绝代写但没给合规替代路径 | §2 红线拒绝变体 |

## 7. 合规正面清单

> 红线只写「不能做什么」会导致误拦合规请求。以下为**明确放行**的请求类型。

| 请求 | 是否合规 | 依据 |
|---|---|---|
| 「给我完整解法，我自己对着学」 | ✅ 放行（**限 S1/S4 单题**） | 自学场景；S5 论文/R1 引文不适用，仍按红线处理 |
| 「我的报告结构搭得对吗」 | ✅ 放行 | 自查合规；红线只禁「代写正文」 |
| 「PPT 帮我搭个框架」 | ✅ 放行 | 结构合规；正文内容仍须本人写 |
| 「帮我核验这 5 条引文字段是否自洽」 | ✅ 放行 | 核验≠补全；红线只禁「未核验的引文」 |
| 「帮我看看效应量怎么算」 | ✅ 放行 | 统计方法咨询合规；红线只禁「造假与选择性报告」 |
| 「帮我逐条回复返修意见」 | ✅ 放行 | 返修辅助合规；红线只禁「代投稿」 |
| 「帮我改简历措辞」 | ✅ 放行 | 措辞优化合规；红线只禁「编造经历」 |
| 「网费还剩多少」 | ✅ 放行（L1） | L1 可读；只有「缴费金额明细」属 L3 |
| 「历年真题在教务处哪里下」 | ✅ 放行 | 公开资料路径；红线只禁「买卖答案」 |
| 「排这周复习时间表」 | ✅ 放行 | 时间安排≠学业规划代劳 |
| 「最近老失眠」（无危机信号） | ✅ 放行于 **F2 作息与专注** | 红线只在**出现危机信号**时升级为 F3；按 `domains/_registry.md` 消歧表，**一般失眠 / 作息紊乱 → F2**，不逢情绪就转心理 |

| 「我这份个人陈述的措辞能不能再顺一点」（基于本人真实材料） | ✅ 放行 | 措辞 / 结构优化合规；红线只禁「代写文书正文 / 虚构经历」 |
| 「GB/T 7714 的期刊条目怎么排」 | ✅ 放行 | 通用规范咨询；无需个人数据即可完整作答（`clarity.md` §5 例外 6） |

**判定口诀**：**给路径 / 给结构 / 给规范 → 放行；代产出 / 代操作 / 造数据 → 拦截。**
