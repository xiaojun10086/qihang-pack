# 通用兜底框架（Level 1 · general-fallback）

> 1 级 skill 库的职责之四。**当需求没有指向任何库内 skill 时，保证仍然得出有效、可执行的结果** ——
> 本框架是**三档降级链**的收尾：档 1「同域库内 skill」→ 档 2「外部桥接」（`library/external-bridge.md`）→ **档 3「本框架」（= 自生成）**。
>
> ⚠️ **档序强制**：本框架是**最后一档**。**未穷尽档 1、未尝试档 2，不得直接跳到本框架自行生成**。
> 例外只有两种，且**必须在输出里说明原因**：① 红线域（`F3`/`F5`）禁外接；② 环境离线 / 用户禁止联网。
> 也就是说：**外部桥接也没命中时，必须回到这里出结果** —— 不允许「只回一句拒绝」。

## 1. 何时进入本框架

| 情形 | 上游来源 | 本文件作用 |
|---|---|---|
| **命中 0 个域** | `domain-review.md` §3 无域兜底 | 走 §2 **六步通用框架** |
| 命中域，但**无对口 skill**，且同域另一 skill 也承接不了 | `domain-review.md` §1③ b | 走 §3 **域通用框架** |
| **极模糊输入**（身心两可等） | `domain-review.md` §3.6 | **先反问 1 问**，再回到本文件 |

> 兜底**不代表降质**：无论走哪条分支，输出的结构与可执行性要求与正常路径**完全一致**。

## 2. 六步通用框架（任何输入都能跑出结果）

| # | 步骤 | 产出 | 禁止 |
|---|---|---|---|
| 1 | **复述需求** | 用自己的话复述一遍，标出**理解偏差风险点** | 直接跳到给建议 |
| 2 | **拆解子问题** | 拆成 **2–4 个**可独立回应的子问题 | 拆得比需求还抽象 |
| 3 | **逐一回应** | 每个子问题给「**能做**→怎么做」或「**不能做**→替代路径 / 找谁」 | 只说「做不了」 |
| 4 | **标注不确定** | 未核验信息标 ⚠️；**不臆造 URL / 电话 / 人名 / 数字**（硬规则 2） | 编一个看起来像真的入口 |
| 5 | **给下一步** | **恰好 1 个**可执行动作（去哪个站 / 问谁 / 做什么） | 给一堆并列选项 |
| 6 | **记缺口** | 写入学习档案（`library/memory.md`），作为后续扩库依据 | 悄悄丢掉这次未覆盖需求 |

## 3. 域通用框架（有域锁定、但无对口 skill）

**不放弃域锁定**（`domain-review.md` §1③ 明令禁止）——以该域 `_domain.md` 的 **`## 域边界` + `## DUT 绑定点`** 为骨架：

1. **域能覆盖的部分**：照常给【结果】
2. **域不能覆盖的部分**：明确标注「超出本域边界」并指向正确方向（按该域 `_domain.md` 的「不覆盖 → X」）
3. **输出首行**标 `[已降级] 由「原能力」改为「通用建议」`（口径见 `output-spec.md` §2 降级；**只写能力级，不写 skill 名与域代号**）
4. **仍不满足**时叠加 `[已降级]` 并记缺口

## 4. 输出要求（不得降级质量）

- 必须过 `output-checklist.md` 的 7 项硬校验（含**零内部名**）
- **即使零 skill 命中**，输出也必须有【结论】与【下一步】，且只讲结果与建议、不写推理过程
- 跨域串联仍按 `output-spec.md` 的变体规范（结果并列、**条内不标域名**，≤6 条要点）

## 5. 反例（出现即违规）

| 反例 | 为什么违规 |
|---|---|
| 只回「本包暂无这个方向」就结束 | **零可执行产出**，等于把用户晾在原地 |
| 输出里写「我先查了信息库、再按域路由」 | 违反 `output-spec.md` 铁律 1（只讲结果与建议） |
| 输出里出现 skill 名 / 域代号 / 脚本名 | 违反 `output-spec.md` 铁律 2（零内部名） |
| 把需求硬塞进不相干的域 | 违反 `domain-review.md` §3.4「绝不硬塞」 |
| 臆造一个官网 / 电话以显得「有用」 | 违反硬规则 2（未收录固定回复「信息库未收录」） |
| 跳过不确定性标注，把猜测当事实 | 违反 `output-checklist.md` 核验状态项 |
| 极模糊输入直接判域作答 | 漏判 `F3` 会绕过危机转介红线 |
