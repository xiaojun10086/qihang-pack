# 通用兜底框架（Level 1 · general-fallback）

> 仅当请求没有匹配的库内能力且仍需要帮助时使用。核心快路径不会为了满足降级顺序而先搜索外部 skill；外部工具仅在确有帮助时按需使用。

> 当需求没有指向任何库内 skill 时，提供简洁、诚实且可执行的一般帮助。此框架不要求先穷尽全部 skill 或检索外部平台。

## 1. 何时进入本框架

| 情形 | 上游来源 | 本文件作用 |
|---|---|---|
| **命中 0 个域** | 默认路由无直接匹配 | 按需使用 §2 简洁框架 |
| 命中域，但**无对口 skill** | 任务超出 skill 范围 | 说明边界，按需使用 §3 域通用框架 |
| **极模糊输入**（身心两可等） | `domain-review.md` §3 第 6 条 | **先反问 1 问**，再回到本文件 |

> 兜底不代表凭空编造：优先回答当前能可靠回答的部分，并标明未知信息。

## 2. 六步通用框架（任何输入都能跑出结果）

| # | 步骤 | 产出 | 禁止 |
|---|---|---|---|
| 1 | **确认目标** | 需要时用一句话说明理解；无歧义则直接回答 | 为简单问题重复复述 |
| 2 | **拆分复杂项** | 仅对多部分请求拆成可独立回应的小项 | 把简单请求复杂化 |
| 3 | **直接回应** | 给能可靠回答的内容；不能完成时给替代路径 | 只说「做不了」 |
| 4 | **标注不确定** | 未核验信息明确说明；不臆造 URL / 电话 / 人名 / 数字 | 编造看起来像真的入口 |
| 5 | **给下一步** | 复杂任务给一个最有价值的可执行动作 | 罗列无关选项 |
| 6 | **保存缺口（可选）** | 仅在用户明确要求记录时写入 `library/memory.md` | 未经请求持久化会话内容 |

## 3. 域通用框架（有域锁定、但无对口 skill）

**不放弃域锁定**（`domain-review.md` §1③ 明令禁止）——以该域 `_domain.md` 的 **`## 域边界` + `## DUT 绑定点`** 为骨架：

1. **域能覆盖的部分**：照常给【结果】
2. **域不能覆盖的部分**：明确标注「超出本域边界」并指向正确方向（按该域 `_domain.md` 的「不覆盖 → X」）
3. 直接给与任务匹配的结构或方法；不强制使用降级标签。
4. 只有用户要求长期记录时才保存未覆盖缺口。

## 4. 输出要求（不得降级质量）

- 保持直接、可执行，并如实区分已知与未知。
- 用户需要结构化交付时，参照 `output-spec.md`；简短问题不强制套模板。
- 只有用户明确提出多项目标时，才按 `output-spec.md` 的跨域规范并列结果。

## 5. 反例（出现即违规）

| 反例 | 为什么违规 |
|---|---|
| 只回「本包暂无这个方向」就结束 | **零可执行产出**，等于把用户晾在原地 |
| 输出里写「我先查了信息库、再按域路由」 | 违反 `output-spec.md` 铁律 1（只讲结果与建议） |
| 输出里出现 skill 名 / 域代号 / 脚本名 | 违反 `output-spec.md` 铁律 2（零内部名） |
| 把需求硬塞进不相干的域 | 违反 `domain-review.md` §3 第 4 条「绝不硬塞」 |
| 臆造一个官网 / 电话以显得「有用」 | 违反硬规则 2（未收录固定回复「信息库未收录」） |
| 跳过不确定性标注，把猜测当事实 | 违反 `output-checklist.md` 核验状态项 |
| 极模糊输入直接判域作答 | 漏判 `F3` 会绕过危机转介红线 |
