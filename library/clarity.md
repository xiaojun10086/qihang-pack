# 需求明确（Level 1 · clarity）

> 本文件是 1 级 skill 库的职责之一。**未通过本步，不得进入域锁定。**
> v2.5.0 修订：修复了旧版 `U = 1 − ∏cᵢ` **必然追问**的缺陷（旧版下任何真实输入 U ≈ 0.9+）。

## 1. 提示词拆解（6 槽位）

| 槽位 | 含义 | 「已填」判定标准 |
|---|---|---|
| `O` 对象 | 课程 / 科目 / 章节 / 学院 / 校区 / 事件 | 原话出现具体名词 |
| `T` 任务 | 答疑 / 备考 / 笔记 / 事务 / 规划 / 查校情 / **投稿 / 返修 / 查重 / 排错** | 能从动词唯一推断 |
| `W` 时间 | 截止日 / 可投入时长 / 周期 | 出现日期、天数或周期词 |
| `C` 约束 | 形式 / 字数 / 工具 / 禁忌 | 出现格式或工具要求 |
| `D` 产出 | 提纲 / 卡组 / 计划 / 文档 / 网址 | 明确说了要什么 |
| `B` 背景 | 年级 / 专业 / 薄弱点 / 情绪 | 出现身份或状态描述 |

空槽**显式留空，不臆测**。

## 2. 槽位分级与置信度

**只有「关键槽位」参与判定**，避免边缘槽位拖垮结果。

| 级别 | 槽位 | 说明 |
|---|---|---|
| **关键** | `O` `T` `D` | 缺任一 → 必须追问 |
| **次要** | `W` `C` | 缺失时不单独追问，但若影响执行（如「明天就考」）则追问 |
| **可选** | `B` | 缺失**永不**作为追问理由 |

置信度取值（**离散、可复现**，不用主观 0–1）：

| 情况 | `cᵢ` |
|---|---|
| 原话显式出现 | `1.0` |
| 可从上下文唯一推断 | `0.8` |
| 有多个合理可能（歧义） | `0.5` |
| **完全缺失** | `0.0` |

## 3. 判定公式（已修正）

```
对 6 个槽位分别取 cᵢ（见 §2 表），按权重加权求均值：

              Σ (wᵢ · cᵢ)
    U = 1 −  ───────────────
                 Σ wᵢ

权重：O=1.5  T=1.5  D=1.5   W=0.8  C=0.6   B=0.2
（与 config.yaml 的 `library.clarity.weights` 一致；关键槽位权重更高）

阈值（单一真相源＝`config.yaml` 的 `library.clarity.threshold`）：U ≤ 0.30 → 放行
      U >  0.30 → 追问，最多 3 轮、每轮 ≤3 问
```

### 例 A 的口径说明（v2.6.0）

`U = 0.311` 略高于阈值 0.30，但**最终判「放行」** —— 这不是矛盾，而是**两层判定**：

1. **第一层（必要性）**：`O` `T` `D` 三关键槽位**齐全** → 具备放行条件
2. **第二层（补充性）**：算得的 `U` 用于**判断次要槽位缺失是否影响执行**
   —— `U` 略高但缺口都在 `W/C/B`，不影响本次答疑 → 仍放行

**简记：关键槽齐 = 放行；关键槽缺 = 追问，`U` 只用于缺哪个槽时的取舍。**

> **为什么不是 ∏cᵢ**：旧版要求 6 槽全部接近 1 才放行，等于「永远追问」。
> 改用**加权均值**后，`O/T/D` 齐全即可放行，与「避免打扰」目标一致。

## 4. 追问优先级（高杠杆优先）

`时间 W(3.0) > 对象 O(2.5) > 产出 D(2.0) > 约束 C(1.5) > 背景 B(1.0) > 任务 T(0.5)`

> ⚠️ 上表是**追问优先级分**（决定「先问哪个」），**不是** §3 的公式权重，两者不要混用。
> 优先级分来自 `config.yaml` 的 `library.clarity.ask_priority`。

**只问关键槽位里缺失的**；次要/可选槽位缺失不主动问。

## 5. 不追问的例外（必须遵守）

1. **命中「校情横切」且对象明确** —— 如「图书馆几点开门」「机械学院官网」
2. **`O` `T` `D` 三关键槽位齐全** —— 缺 `W/C/B` 一律不追问
3. **用户显式要求「直接给结果」** —— 跳过澄清，但输出首行须标注假设
4. **触发红线时优先拦红线** —— 先拒绝/改锁，**再**视情况澄清（见 §7）
5. **紧急场景豁免** —— 出现「明天/今晚就截止」等时限，**最多追问 1 个问题**，其余按最大后验假设执行

## 6. 可复现算例

**例 A**「x→0 时 (sin x − x)/x³ 为什么不能等价无穷小？」

| 槽位 | 判定 | cᵢ | wᵢ |
|---|---|---|---|
| O 对象 | 显式（该极限题） | 1.0 | 1.5 |
| T 任务 | 显式（为什么=答疑） | 1.0 | 1.5 |
| D 产出 | 唯一推断（讲解） | 0.8 | 1.5 |
| W 时间 | 缺失 | 0.0 | 0.8 |
| C 约束 | 缺失 | 0.0 | 0.6 |
| B 背景 | 缺失 | 0.0 | 0.2 |

`Σ wᵢcᵢ = 1.5×1.0 + 1.5×1.0 + 1.5×0.8 = 4.2`
`Σ wᵢ = 1.5+1.5+1.5+0.8+0.6+0.2 = 6.1`
`U = 1 − 4.2/6.1 = 0.311`

→ **`U = 0.311 > 0.30`，按阈值应追问……但 `O/T/D` 齐全，按 §5 例外 2 放行。**
（此例说明：**关键槽位齐全是「放行」的充分条件**，阈值只在其上做补充判断。）

**例 B**「高数快挂了」

| 槽位 | 判定 | cᵢ |
|---|---|---|
| O | 显式（高数），但**未指定章节** → 歧义 | 0.5 |
| T | 唯一推断（备考） | 0.8 |
| D | 完全缺失 | 0.0 |
| W | 完全缺失 | 0.0 |
| C | 完全缺失 | 0.0 |
| B | 唯一推断（新生） | 0.8 |

关键槽位 `D` 缺失 → **必须追问**（不再依赖算数值）。
追问 3 项：① 距考试几天？② 卡在哪几章？③ 要计划还是卡组？

## 7. 红线优先级（新增）

**红线 > 澄清门**。顺序固定：

```
1) 先判红线 → 命中 → 输出拒绝/改锁话术（不追问，或最多追问 1 个用于改锁的问题）
2) 再判澄清门 → U > 0.30 且关键槽位缺失 → 追问
3) 通过 → 进入域锁定
```

**理由**：对「帮我把作业做了」这类请求，追问细节等于变相承诺代做。
