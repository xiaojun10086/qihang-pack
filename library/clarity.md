# 需求明确（Level 1 · clarity）

> 本文件是 1 级 skill 库的职责之一。**未通过本步，不得进入域锁定。**
> v2.5.0 修订：修复了旧版 `U = 1 − ∏cᵢ` **必然追问**的缺陷（旧版下任何真实输入 U ≈ 0.9+）。

## 1. 提示词拆解（6 槽位）

| 槽位 | 含义 | 「已填」判定标准 |
|---|---|---|
| `O` 对象 | 课程 / 科目 / 章节 / 学院 / 校区 / 事件 | 原话出现具体名词 |
| `T` 任务 | 答疑 / 备考 / 笔记 / 事务 / 规划 / 查校情 / **投稿 / 返修 / 查重 / 排错** | 能从动词唯一推断 |
| `W` 时间 | 截止日 / 可投入时长 / 周期 | 出现日期、天数或周期词 |
| `C` 约束 | 形式 / 字数 / 工具 / 禁忌 | 出现格式或工具要求 |
| `D` 产出 | 提纲 / 卡组 / 计划 / 文档 / 网址 | 明确说了要什么 |
| `B` 背景 | 年级 / 专业 / 薄弱点 / 情绪 | 出现身份或状态描述 |

空槽**显式留空，不臆测**。

## 2. 槽位分级与置信度

**只有「关键槽位」参与判定**，避免边缘槽位拖垮结果。

| 级别 | 槽位 | 说明 |
|---|---|---|
| **关键** | `O` `T` `D` | 缺任一 → 必须追问 |
| **次要** | `W` `C` | 缺失时不单独追问，但若影响执行（如「明天就考」）则追问 |
| **可选** | `B` | 缺失**永不**作为追问理由 |

置信度取值（**离散、可复现**，不用主观 0–1）：

| 情况 | `cᵢ` |
|---|---|
| 原话显式出现 | `1.0` |
| 可从上下文唯一推断 | `0.8` |
| 有多个合理可能（歧义） | `0.5` |
| **完全缺失** | `0.0` |

### 2.1 关键槽「已填」的判定细则（v2.9 新增 · 消除「指代型对象」导致的漂移）

§2 的四档只说了「显式 / 唯一推断 / 歧义 / 缺失」，**没说指代型与泛指型算哪一档** ——
实测中同一句话不同执行者会打出 `1.0` 或 `0.5`，`U` 值在 **0.13–0.48** 之间漂移、结论直接翻转
（同一输入换执行者，「放行↔追问」翻转率 20%）。下表为**强制口径**，`O` 与 `D` 均适用。

**`O` 对象**

| 形态 | `c_O` | 例 |
|---|---|---|
| 含**可定位的具体内容**（题面/公式/文件名/课程名+章节/院系名/日期事件） | `1.0` | 「x→0 时 (sin x − x)/x³」「高等数学第三章」「机械学院」 |
| 名词类别明确、范围可唯一收窄 | `0.8` | 「高数期中」（科目有、章节无） |
| **指代型**：有指称词但无内容（「这个 X」「刚才那道题」「它」） | `0.5` | 「这个极限」「这个实验」「这份报告」 |
| **泛指型**：只有类目（「文献」「作业」「资料」「材料」） | `0.5` | 「帮我找文献」「帮我弄一下作业」 |
| 无任何对象词 | `0.0` | 「帮我整理一下」 |

**`D` 产出**

| 形态 | `c_D` | 例 |
|---|---|---|
| 明确说了产出物（提纲/卡组/计划/清单/网址/表） | `1.0` | 「排个背诵计划」「给个提纲」 |
| **单一动词只能推出一种产出** | `0.8` | 「推导一下」→ 分步讲解；「排一下」→ 计划 |
| **泛化动词**（弄一下 / 梳理一下 / 安排好 / 提升一下 / 搞一下 / **查一下 / 看一下 / 要个**）→ 多种可能产出 | `0.5` | 「帮我梳理一下」「帮我查一下我的成绩」 |
| 无产出线索 | `0.0` | 「帮我复习」 |

> **一句话记忆**：**「有指称、无内容」= `0.5`（歧义）；「有内容、可定位」= `1.0`。**
> 关键槽取 `0.5` 时按 §3 的硬条件**视同「缺」→ 必须追问**。
>
> **F3 情绪类特例**：F3 的普通情绪请求**仍需追问**（不豁免澄清门），但**先共情再问、≤2 问**，
> 且**不得**做「你是不是想自杀」这类诱导性筛查 —— 具体口径见 `domains/F3-wellbeing/_domain.md`「澄清与追问口径」。
>
> **为什么要写死这一条**：`explain-stepwise` 需要题面、`stats-guard` 需要数据、`data-lab` 需要实验对象 ——
> 指代型对象在**执行期无法落地**，此时放行等于「先答应再要材料」，违反「不打扰」与「不答错」双目标。

## 3. 判定公式（已修正）

```
对 6 个槽位分别取 cᵢ（见 §2 表），按权重加权求均值：

              Σ (wᵢ · cᵢ)
    U = 1 −  ───────────────
                 Σ wᵢ

权重：O=1.5  T=1.5  D=1.5   W=0.8  C=0.6   B=0.2
（与 config.yaml 的 `library.clarity.weights` 一致；关键槽位权重更高）

阈值（单一真相源＝`config.yaml` 的 `library.clarity.threshold`）：U ≤ 0.30 → 放行
      U >  0.30 → 追问，最多 3 轮、每轮 ≤3 问

> **主从关系（v2.9 明确）：§5 例外优先于本阈值。**
> 真实输入几乎都缺 `W/C/B`（三者权重合计仅 `1.6/6.1`），因此 `U` **天然落在 0.31–0.41** ——
> **这不等于「超过阈值」**。判定顺序是：
> ① **关键槽硬条件**（`O/T/D` 三者均 `cᵢ ≥ 0.8`）→ 具备放行条件；
> ② **阈值只用于判断「次要槽缺失是否影响执行」**。
> 故「`U > 0.30` 且关键槽齐全且不歧义」= **放行**（见 §6 例 A）。
>
> **与 §5 例外 6 的关系（v2.9 明确）**：**「通用知识型」例外可以跨越「关键槽取 `0.5`」这条硬条件** ——
> 因为通用问题的答案**不依赖**个人情况，关键槽的「指代不明」并不影响作答。
> 判定顺序：**先判 §5 例外（按优先级）→ 再用 §3 硬条件与阈值**。
```

### 例 A 的口径说明（v2.6.0）

`U = 0.311` 略高于阈值 0.30，但**最终判「放行」** —— 这不是矛盾，而是**两层判定**：

1. **第一层（必要性）**：`O` `T` `D` 三关键槽位**齐全** → 具备放行条件
2. **第二层（补充性）**：算得的 `U` 用于**判断次要槽位缺失是否影响执行**
   —— `U` 略高但缺口都在 `W/C/B`，不影响本次答疑 → 仍放行

**简记（v2.7 加固）：关键槽「齐全且不歧义」= 放行；关键槽缺**或**出现歧义（`cᵢ = 0.5`）= 追问。**

> **v2.7 修复的逻辑漏洞**：旧版「关键槽齐全即放行」只判「有没有」，不判「清不清楚」。
> 反例：`O/T/D` 都填了但都是歧义（各 `cᵢ=0.5`）→ `U = 1 − (1.5×0.5×3)/6.1 = 0.63`，
> 按旧版仍会**放行**，与「避免答错」目标相反。故补一条硬条件：
> **关键槽判「已填」时必须 `cᵢ ≥ 0.8`（显式或唯一推断）；出现 `0.5` 视同「缺」，必须追问。**

> **为什么不是 ∏cᵢ**：旧版要求 6 槽全部接近 1 才放行，等于「永远追问」。
> 改用**加权均值**后，`O/T/D` 齐全即可放行，与「避免打扰」目标一致。

## 4. 追问优先级（高杠杆优先）

`时间 W(3.0) > 对象 O(2.5) > 产出 D(2.0) > 约束 C(1.5) > 背景 B(1.0) > 任务 T(0.5)`

> ⚠️ 上表是**追问优先级分**（决定「先问哪个」），**不是** §3 的公式权重，两者不要混用。
> 优先级分来自 `config.yaml` 的 `library.clarity.ask_priority`。

**只问关键槽位里缺失的**；次要/可选槽位缺失不主动问。

## 5. 不追问的例外（必须遵守）

> **例外优先级（v2.9 明确，命中高优先级即按该条处理、不再往下判）**：
> **4 红线 > 6 通用知识型 > 1 校情横切 > 2 关键槽齐全 > 5 紧急豁免 > 3 显式要求**

1. **命中「校情横切」且对象明确** —— 如「图书馆几点开门」「机械学院官网」
2. **`O` `T` `D` 三关键槽位齐全且均 `cᵢ ≥ 0.8`** —— 缺 `W/C/B` 一律不追问；若某关键槽只有 `0.5`（歧义），**不适用本例外**，按 §3 追问
3. **用户显式要求「直接给结果」** —— 跳过澄清，但输出首行须标注假设
4. **触发红线时优先拦红线** —— 先拒绝/改锁，**再**视情况澄清（见 §7）
5. **紧急场景豁免** —— 出现「明天/今晚就截止」等时限，**最多追问 1 个问题**，其余按最大后验假设执行
6. **通用知识型**（v2.9 新增）—— 答案与**用户个人情况、DUT 校内资源均无关**的通用问题，**直接放行**，
   给通用清单 / 规范即可：如「投稿前要准备哪些材料」「学术诚信该注意什么」「GB/T 7714 怎么排」。
   判据：**不需要任何个人数据或校情数据就能给出完整答案**。
   输出末尾加一句：「如需针对你的具体情况，告诉我 {缺的槽位}」。
   > 为什么需要这条：这类问题按 `O` 判会得 `0.5` 而被迫追问，属**假追问** —— 用户问的是公共知识，不是自己的情况。

## 6. 可复现算例

**例 A**「x→0 时 (sin x − x)/x³ 为什么不能等价无穷小？」

| 槽位 | 判定 | cᵢ | wᵢ |
|---|---|---|---|
| O 对象 | 显式（该极限题） | 1.0 | 1.5 |
| T 任务 | 显式（为什么=答疑） | 1.0 | 1.5 |
| D 产出 | 唯一推断（讲解） | 0.8 | 1.5 |
| W 时间 | 缺失 | 0.0 | 0.8 |
| C 约束 | 缺失 | 0.0 | 0.6 |
| B 背景 | 缺失 | 0.0 | 0.2 |

`Σ wᵢcᵢ = 1.5×1.0 + 1.5×1.0 + 1.5×0.8 = 4.2`
`Σ wᵢ = 1.5+1.5+1.5+0.8+0.6+0.2 = 6.1`
`U = 1 − 4.2/6.1 = 0.311`

→ **`U = 0.311 > 0.30`，按阈值应追问……但 `O/T/D` 齐全，按 §5 例外 2 放行。**
（此例说明：**关键槽位齐全是「放行」的充分条件**，阈值只在其上做补充判断。）

**例 C（v2.7 新增 · 漏洞反例）**「帮我写点东西」

| 槽位 | 判定 | cᵢ |
|---|---|---|
| O | 「东西」= 无具体对象 → 歧义 | 0.5 |
| T | 「写」→ 可推断为写作，但导向 S3/S5 两域 | 0.5 |
| D | 完全缺失 | 0.0 |

`U = 1 − (0.75+0.75+0)/6.1 = 0.75 > 0.30`，且关键槽含歧义 → **必须追问**。
若按旧版「三关键槽都非空」判，会误放行 —— 这正是 v2.7 要修掉的洞。

**例 B**「高数快挂了」

| 槽位 | 判定 | cᵢ |
|---|---|---|
| O | 显式（高数），但**未指定章节** → 歧义 | 0.5 |
| T | 唯一推断（备考） | 0.8 |
| D | 完全缺失 | 0.0 |
| W | 完全缺失 | 0.0 |
| C | 完全缺失 | 0.0 |
| B | 唯一推断（新生） | 0.8 |

关键槽位 `D` 缺失 → **必须追问**（不再依赖算数值）。
追问 3 项：① 距考试几天？② 卡在哪几章？③ 要计划还是卡组？

## 7. 红线优先级（新增）

**红线 > 澄清门**。顺序固定：

```
1) 先判红线 → 命中 → 输出拒绝/改锁话术（不追问，或最多追问 1 个用于改锁的问题）
2) 再判澄清门 → U > 0.30 且关键槽位缺失 → 追问
3) 通过 → 进入域锁定
```

**理由**：对「帮我把作业做了」这类请求，追问细节等于变相承诺代做。
