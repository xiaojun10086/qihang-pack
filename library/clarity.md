# 需求明确（Level 1 · clarity）

> 本文件是复杂、多约束或存在实质歧义请求的澄清参考。普通清晰请求直接作答，不要求每轮拆槽位、计算分数或复述。

## 1. 提示词拆解（6 槽位）

| 槽位 | 含义 | 「已填」判定标准 |
|---|---|---|
| `O` 对象 | 课程 / 科目 / 章节 / 学院 / 校区 / 事件 | 原话出现具体名词 |
| `T` 任务 | 答疑 / 备考 / 笔记 / 事务 / 规划 / 查校情 / **投稿 / 返修 / 查重 / 排错** | 能从动词唯一推断 |
| `W` 时间 | 截止日 / 可投入时长 / 周期 | 出现日期、天数或周期词 |
| `C` 约束 | 形式 / 字数 / 工具 / 禁忌 | 出现格式或工具要求 |
| `D` 产出 | 提纲 / 卡组 / 计划 / 文档 / 网址 | 明确说了要什么 |
| `B` 背景 | 年级 / 专业 / 当前基础 / 薄弱点 | 出现身份或状态描述 |

空槽**显式留空，不臆测**。

## 2. 槽位分级与置信度

**只有「关键槽位」参与判定**，避免边缘槽位拖垮结果。

| 级别 | 槽位 | 说明 |
|---|---|---|
| **关键** | `O` `T` `D` | 缺任一 → 必须追问 |
| **次要** | `W` `C` | 缺失时不单独追问，但若影响执行（如「明天就考」）则追问 |
| **条件可问** | `B` | 一般不问；仅当当前基础等信息会实质改变讲解路径、难度或安全边界时才问 |

置信度取值（**离散、可复现**，不用主观 0–1）：

| 情况 | `cᵢ` |
|---|---|
| 原话显式出现 | `1.0` |
| 可从上下文唯一推断 | `0.8` |
| 有多个合理可能（歧义） | `0.5` |
| **完全缺失** | `0.0` |

### 2.1 关键槽「已填」的判定细则

§2 的四档只说了「显式 / 唯一推断 / 歧义 / 缺失」，**没说指代型与泛指型算哪一档** ——
实测中同一句话不同执行者会打出 `1.0` 或 `0.5`，`U` 值在 **0.13–0.48** 之间漂移、结论直接翻转
（同一输入换执行者，「放行↔追问」翻转率 20%）。下表为**强制口径**，`O` 与 `D` 均适用。

**`O` 对象**

| 形态 | `c_O` | 例 |
|---|---|---|
| 含**可定位的具体内容**（题面/公式/文件名/课程名+章节/院系名/日期事件） | `1.0` | 「x→0 时 (sin x − x)/x³」「高等数学第三章」「机械学院」 |
| 名词类别明确、范围可唯一收窄 | `0.8` | 「高数期中」（科目有、章节无） |
| **指代型**：有指称词但无内容（「这个 X」「刚才那道题」「它」） | `0.5` | 「这个极限」「这个实验」「这份报告」 |
| **泛指型**：只有类目（「文献」「作业」「资料」「材料」） | `0.5` | 「帮我找文献」「帮我弄一下作业」 |
| 无任何对象词 | `0.0` | 「帮我整理一下」 |

**`D` 产出**

| 形态 | `c_D` | 例 |
|---|---|---|
| 明确说了产出物（提纲/卡组/计划/清单/网址/表） | `1.0` | 「排个背诵计划」「给个提纲」 |
| **单一动词只能推出一种产出** | `0.8` | 「推导一下」→ 分步讲解；「排一下」→ 计划 |
| **泛化动词**（弄一下 / 梳理一下 / 安排好 / 提升一下 / 搞一下 / **查一下 / 看一下 / 要个**）→ 多种可能产出 | `0.5` | 「帮我梳理一下」「帮我查一下我的成绩」 |
| 无产出线索 | `0.0` | 「帮我复习」 |

> **一句话记忆**：**「有指称、无内容」= `0.5`（歧义）；「有内容、可定位」= `1.0`。**
> 关键槽取 `0.5` 时按 §3 的硬条件**视同「缺」→ 必须追问**。
>
> **F3 情绪类特例**：F3 的普通情绪请求**仍需追问**（不豁免澄清门），但**先共情再问、≤2 问**，
> 且**不得**做「你是不是想自杀」这类诱导性筛查 —— 具体口径见 `domains/F3-wellbeing/_domain.md`「澄清与追问口径」。
>
> **为什么要写死这一条**：`explain-stepwise` 需要题面、`stats-guard` 需要数据、`data-lab` 需要实验对象 ——
> 指代型对象在**执行期无法落地**，此时放行等于「先答应再要材料」，违反「不打扰」与「不答错」双目标。

## 3. 判定公式（已修正）

> **按需使用**：以下公式用于需要稳定澄清口径的复杂请求，不是日常对话的必经计算。若缺失信息不会改变回答、安全边界或下一步行动，直接继续处理。

```
对 6 个槽位分别取 cᵢ（见 §2 表），按权重加权求均值：

              Σ (wᵢ · cᵢ)
    U = 1 −  ───────────────
                 Σ wᵢ

权重：O=1.5  T=1.5  D=1.5   W=0.8  C=0.6   B=0.2
（与 config.yaml 的 `library.clarity.weights` 一致；关键槽位权重更高）

阈值（单一真相源＝`config.yaml` 的 `library.clarity.threshold`）：U ≤ 0.30 → 放行
      U >  0.30 → **先过 §5 的 6 条「不追问例外」**；仍未命中例外才追问（轮次与问数上限见 §4）

> **主从关系：§5 例外优先于本阈值。**
> 真实输入几乎都缺 `W/C/B`（三者权重合计仅 `1.6/6.1`），因此 `U` **天然落在 0.31–0.41** ——
> **这不等于「超过阈值」**。判定顺序是：
> ① **关键槽硬条件**（`O/T/D` 三者均 `cᵢ ≥ 0.8`）→ 具备放行条件；
> ② **阈值只用于判断「次要槽缺失是否影响执行」**。
> 故「`U > 0.30` 且关键槽齐全且不歧义」= **放行**（见 §6 例 A）。
>
> **与 §5 例外 6 的关系**：**「通用知识型」例外可以跨越「关键槽取 `0.5`」这条硬条件** ——
> 因为通用问题的答案**不依赖**个人情况，关键槽的「指代不明」并不影响作答。
> 判定顺序：**先判 §5 例外（按优先级）→ 再用 §3 硬条件与阈值**。
```

### 例 A 的口径说明

`U = 0.311` 略高于阈值 0.30，但**最终判「放行」** —— 这不是矛盾，而是**两层判定**：

1. **第一层（必要性）**：`O` `T` `D` 三关键槽位**齐全** → 具备放行条件
2. **第二层（补充性）**：算得的 `U` 用于**判断次要槽位缺失是否影响执行**
   —— `U` 略高但缺口都在 `W/C/B`，不影响本次答疑 → 仍放行

**简记：关键槽「齐全且不歧义」= 放行；关键槽缺**或**出现歧义（`cᵢ = 0.5`）= 追问。**

> **为什么不是 ∏cᵢ**：旧版要求 6 槽全部接近 1 才放行，等于「永远追问」。
> 改用**加权均值**后，`O/T/D` 齐全即可放行，与「避免打扰」目标一致。

### 3.1 需求确定门（理解准确率 **≥ 95%** 才直接执行 · **实质歧义驱动**）

§3 的 `U` 解决「**能不能问**」，本门解决「**我理解得对不对**」。二者是同一算式的两面：

```
理解准确率  C = 1 − U = Σ(wᵢ · cᵢ) / Σwᵢ
```

| 档 | `C` | 动作 |
|---|---|---|
| **确定档** | `C ≥ 0.95` | **直接执行**，不复述（保住「快速输出」） |
| **复述档** | `0.70 ≤ C < 0.95` **且存在实质歧义** | **先用一句话复述**「你要的是 ⟨对象 + 任务⟩，产出 ⟨产出物⟩，约束 ⟨若有且影响执行⟩」；用户不纠正即执行，纠正则按 §4 就缺口追问 |
| **确定档**（降级） | `0.70 ≤ C < 0.95` **但无实质歧义** | **直接执行，不复述** —— 关键槽齐全、产物形态唯一时，复述只是空转（见下方硬规格 1） |
| **追问档** | `C < 0.70` | **仅当澄清门本就要追问时才追问**（判定不变）；若澄清门已放行（如例 A：关键槽齐全、仅次要槽缺、**无实质歧义**）→ **直接执行**，**不得新增追问、不得复述** |

**三条前置约定（判定顺序在本门之前，实测易错，故写明）**：

1. **红线优先 → 本门短路**：命中红线时**不计算 `C`、不标注档位**（记「**不适用**」），仍按 §7 直接拒绝 + 给合规替代。
2. **先问后述**：澄清门判「**追问**」时，本门**不再复述** —— 追问已要求用户补充；复述档**只在澄清门已放行时**生效。
3. **例外 6 视为达标**：通用知识型免复述（不因 `C` 未达 0.95 而要求确认）。

**复述档的四条硬规格**（**实质歧义驱动** —— 判据一句话：**能直接做就不复述；可能做偏才复述**）：

1. **有实质歧义**（决定性条件）：`T`(任务) / `O`(对象) / 产出物形态三者中，**至少一个有两种以上合理读法**，且不同读法会产出**不同的产物**。
   - **不构成实质歧义**（→ **直接执行，免复述**）：关键槽齐全；只是表述口语化；只是没说要什么格式（默认按 `library/output-spec.md` 交付）；只是信息不全但**不改变产物形态**。
2. **一句话**，且**必须引用用户原话里的词**（≥1 个对象词 + ≥1 个产出词）—— 引用不出即视为「尚未确定」，退回追问档；
3. **不得新增**用户没说过的内容（新增即视为理解错误），只允许删与并；
4. 复述**并入【结论】首行的前置短句**（形如「按你给的 ⟨引用原话里的词⟩ —— ⟨结论⟩」）：**不新增输出字段、不改输出硬契约**，也不出现内部名或过程叙述。
   > ⚠️ **不要用【假设】承载复述** —— 该字段的触发条件另有规定（见 `library/output-spec.md` §1.3），两者口径已对齐：复述是「先说清我理解的是什么」，【假设】是「代替用户补了对象或产出」。

**与既有规则的关系（优先级不变）**：

| 规则 | 关系 |
|---|---|
| **红线**（§5 例外 4 / §7） | **红线优先于本门** —— 命中红线仍**不追问、不复述**，直接拒绝 + 合规替代（**唯一例外**：需判定改锁目标时最多追问 1 问，见 §7） |
| **例外 6 通用知识型** | 答案不依赖个人与校情数据 → **视为 `C` 达标**，直接执行（否则会退化成假复述） |
| **例外 3 显式「直接给结果」** | 跳过复述，但**必须输出【假设】字段**逐条列出**所补的对象 / 产出**（与 §8 一致；不另起裸首行） |
| **例外 5 紧急豁免** | 复述**并入**那 1 个追问，不额外增加打扰 |
| **§8 三轮未达标** | 仍按最大后验执行 + **输出【假设】字段**逐条列出所补的对象 / 产出（与复述档**合并**，不重复两次） |

**两个可复现自检问**（任一为「否」→ 不得进入执行）：

1. 我能否用「**做什么 + 给什么**」一句话说清用户要的东西？
2. 用户看到我的产出，会不会说「**我指的不是这个**」？

> **为什么要有这道门**：澄清门允许 `C ≈ 0.70` 就放行（例 A 即 `C = 0.689`）—— 那是「可以问、但不必问」的口径；
> 而「动手前确认理解」是另一件事：**错理解的代价 = 白做一轮**。本门只加「一句话复述」的成本，
> 且**只在 0.70–0.95 这一档、并且确实存在实质歧义时**才触发，`C ≥ 0.95`、关键槽齐全与「通用知识型」都**免复述**。

**算例（与 §6 同源，`C` 由同一算式算出；`C` 只影响「是否复述」，不影响「是否追问」）**

| 算例 | 输入 | `C = 1 − U` | 澄清门 | **需求确定门** |
|---|---|---|---|---|
| 例 A | 「x→0 时 (sin x − x)/x³ 为什么不能等价无穷小？」 | `0.689`（数值 <0.70，**但澄清门已放行**，见下方前置约定 ②） | 放行（例外 2） | **确定档（降级为执行）** —— 对象 / 任务 / 产出唯一，**无实质歧义** → 直接执行 |
| 例 C | 「帮我写点东西」 | `0.25` | 追问 | 追问档 |
| 例 D | 「明天下午考高数第三章，帮我排 3 天背诵计划，要卡组，我是大一新生」 | `1.00` | 放行 | **确定档**（直接执行） |
| 例 E | 「把机械学院官网的招生简章整理成一页要点清单」 | `0.816` | 放行 | **复述档** |

> 例 D 六槽齐全（O 高数第三章 / T 备考 / D 卡组 / W 3 天 / C 卡组形式 / B 大一新生）→ `Σwᵢcᵢ = 6.1` → `C = 1.00`；
> 例 E 缺 `W`、`B`（`O/T/D` 各 `1.0`、`C = 0.8`）→ `Σwᵢcᵢ = 1.5+1.5+1.5+0.48 = 4.98` → `C = 4.98/6.1 = 0.816`。
> **注意例 A**：澄清门判「放行」（关键槽齐全），而 `C = 0.689 < 0.70` —— 此时**直接执行，既不复述也不追问**
> （关键槽齐全 = **无实质歧义**），这正是「本门不改变追问判定」的含义，也避免了与例外 2「缺 `W/C/B` 一律不追问」冲突。
>
> **例 F（实质歧义 → 复述档）**：「帮我整理一下这学期的重点」—— 澄清门放行（对象「这学期」明确），
> 但「这学期」可指 3 门课或全部课程，**读法不同 → 产物不同** → **有实质歧义** → **复述档**
> （一句话复述并入【结论】首行）。这才是复述档唯一该被触发的情形。

## 4. 追问优先级（高杠杆优先）

`时间 W(3.0) > 对象 O(2.5) > 产出 D(2.0) > 约束 C(1.5) > 背景 B(1.0) > 任务 T(0.5)`

> ⚠️ 上表是**追问优先级分**（决定「先问哪个」），**不是** §3 的公式权重，两者不要混用。
> 优先级分来自 `config.yaml` 的 `library.clarity.ask_priority`。

**先定「能不能问」，再按上表排序** —— 上表只在**可问集合内**生效：

| 槽位 | 可问性 | 条件 |
|---|---|---|
| `O` `T` `D` | ✅ 必问 | 缺失或歧义（`cᵢ = 0.5`）时必须追问 |
| `W` `C` | ⚠️ 条件可问 | 仅当**影响执行**时（如「明天就考」） |
| `B` | ⚠️ 条件可问 | 仅当当前基础等信息会实质改变讲解路径、难度或安全边界时；否则缺失不单独触发追问 |

> ⚠️ **不得因为 `W` 分值最高就去问 `W`** —— 表中 `W(3.0)`/`B(1.0)` 仅在
> 「W/C 已因影响执行而进入追问、需与其他槽位排序」时才有意义；`B` 不参与排序。
> **轮次与问数上限（唯一真相源）**：追问最多 **3 轮**，每轮最多 **3 问**；全部落在可问集合内。

## 5. 不追问的例外（必须遵守）

> **例外优先级（命中高优先级即按该条处理、不再往下判）**：
> **4 红线 > 6 通用知识型 > 1 校情横切 > 2 关键槽齐全 > 5 紧急豁免 > 3 显式要求**

1. **命中「校情横切」且对象明确** —— 如「图书馆几点开门」「机械学院官网」
2. **`O` `T` `D` 三关键槽位齐全且均 `cᵢ ≥ 0.8`** —— 缺 `W/C/B` 一律不追问；若某关键槽只有 `0.5`（歧义），**不适用本例外**，按 §3 追问
3. **用户显式要求「直接给结果」** —— 跳过澄清，但**必须输出【假设】字段**列出所补的对象 / 产出（口径见 `library/output-spec.md` §1）
4. **触发红线时优先拦红线** —— 先拒绝/改锁，**再**视情况澄清（见 §7）
5. **紧急场景豁免** —— 出现「明天/今晚就截止」等时限，**最多追问 1 个问题**，其余按最大后验假设执行
6. **通用知识型**—— 答案与**用户个人情况、DUT 校内资源均无关**的通用问题，**直接放行**，
   给通用清单 / 规范即可：如「投稿前要准备哪些材料」「学术诚信该注意什么」「GB/T 7714 怎么排」。
   判据：**不需要任何个人数据或校情数据就能给出完整答案**。
   **本例外只豁免追问，不豁免域路由与库内 skill 选择**；仍须按 `SKILL.md` 快通道第 3 步「择一路径」执行。
   把「如需针对你的具体情况，告诉我 {缺的槽位}」作为【下一步】的**唯一动作**写入（不新增字段、不在末尾另起裸行；见 `library/output-spec.md` §2 通用知识型例外）。
   > 为什么需要这条：这类问题按 `O` 判会得 `0.5` 而被迫追问，属**假追问** —— 用户问的是公共知识，不是自己的情况。

## 6. 可复现算例

**例 A**「x→0 时 (sin x − x)/x³ 为什么不能等价无穷小？」

| 槽位 | 判定 | cᵢ | wᵢ |
|---|---|---|---|
| O 对象 | 显式（该极限题） | 1.0 | 1.5 |
| T 任务 | 显式（为什么=答疑） | 1.0 | 1.5 |
| D 产出 | 唯一推断（讲解） | 0.8 | 1.5 |
| W 时间 | 缺失 | 0.0 | 0.8 |
| C 约束 | 缺失 | 0.0 | 0.6 |
| B 背景 | 缺失 | 0.0 | 0.2 |

`Σ wᵢcᵢ = 1.5×1.0 + 1.5×1.0 + 1.5×0.8 = 4.2`
`Σ wᵢ = 1.5+1.5+1.5+0.8+0.6+0.2 = 6.1`
`U = 1 − 4.2/6.1 = 0.311`

→ **`U = 0.311 > 0.30`，按阈值应追问……但 `O/T/D` 齐全，按 §5 例外 2 放行。**
（此例说明：**关键槽位齐全是「放行」的充分条件**，阈值只在其上做补充判断。）

**例 C（漏洞反例）**「帮我写点东西」

| 槽位 | 判定 | cᵢ |
|---|---|---|
| O | 「东西」= 无具体对象 → 歧义 | 0.5 |
| T | 「写」→ 可推断为写作，但导向 S3/S5 两域 | 0.5 |
| D | 完全缺失 | 0.0 |

`U = 1 − (0.75+0.75+0)/6.1 = 0.75 > 0.30`，且关键槽含歧义 → **必须追问**。
若按「三关键槽都非空」判，会误放行 —— 这正是本包要堵住的洞。

**例 B**「高数快挂了」

| 槽位 | 判定 | cᵢ |
|---|---|---|
| O | 显式（高数），但**未指定章节** → 歧义 | 0.5 |
| T | 唯一推断（备考） | 0.8 |

| W | 完全缺失 | 0.0 |

## 7. 红线优先级

**红线 > 澄清门**。顺序固定：

```
1) 先判红线 → 命中 → 输出拒绝/改锁话术（**默认不追问**；**唯一例外**：需判定改锁目标时最多追问 1 问）
2) 再判登录档位（`library/login-policy.md` 的 A/B/C）→ 决定是否请求登录
3) 再判澄清门 → 先过 §5 例外；未命中例外且关键槽位缺失/歧义（`cᵢ = 0.5`）→ 追问
4) 通过 → 进入域锁定
```

**理由**：对「帮我把作业做了」这类请求，追问细节等于变相承诺代做。
